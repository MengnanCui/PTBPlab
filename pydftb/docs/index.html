关键信息

pydftb 是从零写成的 Python SCC-DFTB 程序，每一项功能都与 DFTB+ 逐项对照，参考结果冻结在仓库里，测试不需要 DFTB+。它已接入 PTBP，可以替代 DFTB+ 做参数优化。

  • 已完成：原型、M0 底座、M1 接入 PTBP，M2 的全部七项（应力、DFTB3、共线自旋、色散、能带与 DOS/PDOS、结构优化与 MD 的验证、f 轨道），以及 M3a、M3b：PTBP 的 BO 步默认用满可用核心，Cu 数据集 4 核上一个 BO 步从 147 s 降到 27 s，运行目录与原来逐字节相同。
  • 下一步：M3c 计算策略推荐器、M3d DFTB+ 配置顾问。
  • 验收标准：与 DFTB+ 的能量差 < 1e-6 Ha、力差 < 1e-5 Ha/Bohr、应力差 < 1e-7 Ha/Bohr³。实际差异通常小 3–5 个数量级，剩下的差异都已归因。
  • 对照中发现并记录了 DFTB+ 自身的几处问题：U 接近时 γ 公式数值崩溃（M2b）、原生 D4 的三处错误（M2d），以及 k 点权重有舍入时绝缘体的费米能级被放到导带底（M2e）。
  • 74 + 11DFTB+ 参考算例（单点 + 优化/MD），全部通过
  • 223 + 150离线测试：pydftb + PTBP（conda 环境）
  • < 1e-7PTBP 损失函数与 DFTB+ 的相对差
  • 5.4×PTBP 的一个 BO 步，4 核（pydftb，对 M3 之前）

如何接手

环境

  • 最小环境：numpy、scipy、ase（与 CI 相同）。全部离线测试都能跑；需要 D3/D4 库或 DFTB+ 的用例会跳过并写明原因。
  • 完整环境：再从 conda-forge 装 dftbplus=25.1（nompi）、dftd3-python=1.0.0、dftd4-python=3.6.0、hotcent。这两个库的版本与 DFTB+ 链接的库相同，参考结果才能逐位复现。开发机上它们在 /opt/mm/dftb，DFTB+ 路径可用环境变量 DFTBPLUS 指定。重新生成 M2e 中冻结的 DOS 曲线还需要 DFTB+ 仓库里的 dptools 源码（tools/dptools/src，环境变量 DPTOOLS）。

常用命令（在仓库根目录）

PYTHONPATH=. pytest -q pydftb/tests -o addopts=""         # 离线测试，用冻结的 DFTB+ 参考
python -m pydftb.validation.refgen --check                 # 与冻结参考逐项对照的表格
python -m pydftb.validation.dynamics --check               # 结构优化与 MD，对照 DFTB+ 的驱动
python -m pydftb.validation.refgen --regenerate <算例名>    # 需要 dftb+，重写参考 JSON
python -m pydftb.validation.refgen --live <算例名>          # 与新跑的 dftb+ 直接比较
python -m pydftb.validation.make_f_set                     # 重新生成 f 轨道测试参数（需要 hotcent）

代码与数据在哪里

  • 引擎：pydftb/calculator.py（四段式：_setup、_scc、_energies、_gradient）；ASE 接口 pydftb/ase_calc.py；PySCF 风格接口 pydftb/api.py。
  • 对照工具：算例登记 pydftb/validation/cases.py，DFTB+ 输入与输出解析 validation/dftbplus.py，参考生成与比较 validation/refgen.py；参考 JSON 在 pydftb/tests/data/ref/。结构优化与 MD 的对照在 validation/dynamics.py，参考在 tests/data/ref_dynamics/。
  • 测试参数在 pydftb/tests/data/skf/，来源和校验和见其中的 PROVENANCE.md；hotcent_gdo 是带 f 轨道的 Gd/O 参数（扩展 SKF 格式，无排斥势）。
  • PTBP 的引擎分发：utils/engines.py。

已知问题

  • PTBP 的 --optimization_option bandstructure 模式有多处错误，目前跑不通（与 pydftb 无关，另有任务）。
  • 已修正（M3 之前）：PTBP 损失函数的惩罚项过去总用 0.5 Bohr 的共价半径（cli/run.py 算出了元素的半径，但没有传给 Loss(...)），Cu 的惩罚因子因此是 1.2e4 而不是 6.0。现在用被参数化元素的半径；参数表中已发表的 75 个元素的损失值都能用这个公式复现（相对差 ≤ 5e-5）。已发表的 Cu 参数下，dataset 模式的损失从 901629.83 变为 446.20，energygeometry 模式从 3837.92 变为 1.8993，两个引擎的相对差仍在 1e-8 以内。旧运行的损失值是另一个尺度：旧的 skopt 检查点在恢复时会被拒绝，可用 tools/rescale_checkpoint.py 精确换算。
  • energygeometry 模式在已发表的 Cu 参数下的损失为 1.90，论文中为 0.288：μE、μV 本身大约大 6.6 倍（0.510、0.120 对 0.0775、0.0182），与惩罚项无关，待查（可能与数据集、hotcent 版本或 E0 的设置有关）。
  • 多元素模式（--multi_element）跑不通：命令行给的是元素符号，而 data.get_elements_from_dataset、Loss.set_parameters 要原子序数；参数表里也没有 set_parameters 要读的 r_wave 键。cli/run.py 只优化 sigma_rep 的分支调用 Loss_EnergyGeometry 的参数也不对。
  • k 点密度较低（--kpts 2.0）、T = 0 时，Cu 数据集的第 44 个结构（6×6×6 网格）在两个引擎中都 1000 轮 SCC 不收敛（各约 40 s），结果照常返回：pydftb 给出警告，DFTB+ 只在输出文件里注明。默认的 5.0 和 3.0 下都收敛（见 M3a 报告）。
  • σ_rep 搜索每个 BO 步评估 74 次，其中 L-BFGS-B 的 41 次回到网格搜索已经找到的 σ（损失在 1e-8 量级上有噪声，差分梯度没有意义）；部分 σ 上状态方程拟合失败，损失出现尖峰（例如 σ = 0.38 时 101.8）。改搜索方法会改变结果，见 M3b 报告。
  • physrep.evaluate_pbc 的超胞层数由最短的晶格矢量长度决定，晶胞很斜时会漏掉近邻（γ = 13° 的测试晶胞：22 对中只算 20 对）；Cu 数据集没有遗漏。为了结果不变，没有修。
  • tools/physrep.py 可能改编自 J. Margraf 的 physrep，上游许可未知；仓库整体为 MIT，需确认这个文件可以按 MIT 发布。
