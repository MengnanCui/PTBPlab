# 为什么有了 DFTB+ 还要做 pydftb

DFTB+ 是成熟、开源、功能完整的 DFTB 程序。pydftb 不是要取代它，而是在四件 DFTB+ 不擅长、或者在 Fortran 里改造成本很高的事情上，提供一个现代的 Python 平台。

## 1. 可学习：一本能运行的 DFTB 教科书

DFTB+ 共约 21.8 万行 Fortran，其中核心 DFTB2 路径约 2.3 万行，与 MPI、BLACS、螺旋几何等工程变体交织在一起。pydftb 的做法是：

- 每个模块对应一段物理公式，并标明 DFTB+ 里对应的源文件（见 `dftbplus_map.md`）；
- 每个开发阶段都有一份设计文档（`design/`）和一份完成报告（`reports/`），记录“为什么这样做、和 DFTB+ 差多少、踩了什么坑”；
- 每个功能都与 DFTB+ 在同一输入上对照，结果固化在 `tests/data/ref/` 中，任何人都能复现。

## 2. 面向现代硬件：一套代码，多种处理器

DFTB+ 的 GPU 支持有限：MAGMA 只能单机，跨节点只有 ELPA-GPU。pydftb 的计划是：

- 计算层通过 `backend/ops.py` 访问少数几个与硬件相关的操作，物理代码与硬件无关；
- M4 阶段接入 PyTorch，一套代码可以跑在 CPU、NVIDIA、AMD/国产 GPU 和 Apple M 系列芯片上；
- 按原子数 / 轨道数自动推荐算法和并行方式（M3 阶段的计算策略推荐器）。实测已经说明，400 原子量级“加节点”没有意义，应该换算法或换硬件。

现状（M4d）：PyTorch 后端已能在 CPU 上逐项复现 NumPy 和 DFTB+ 的结果。M4d 加上了设备选项：NVIDIA 和 AMD（ROCm）的 GPU 全部在设备上算，Apple 的 MPS 和 Intel 的 XPU 按设备能力把 float64 的部分和本征分解留在 CPU；PTBP 可以用 `--pydftb_backend torch --device cuda`。GPU 上的正确性和加速还没有实测：本机没有 GPU，设备逻辑只能在 CPU 上验证（第一次求导时会出错的约 50 处已用 meta 设备查出并改正），用户运行自检脚本 `python -m pydftb.validation.gpu_check` 后才有实测数字。也要说清楚预期：PTBP 的 Cu 数据集上，DFTB 阶段只占一个 BO 步的 37%（energygeometry，27.1 s 中的 10.0 s）和 57%（dataset，18.0 s 中的 10.3 s），GPU 即使把它降到 0，一个 BO 步也最多快 1.6 倍和 2.3 倍。GPU 的价值在更大的数据集、更大的晶胞和更多的 k 点。

## 3. 天生可微，方便接入 AI

自动求导可以直接给出“误差对参数的导数”，这样：

- PTBP 的参数化可以从贝叶斯优化的“盲试”，变成梯度优化；
- 可以接入机器学习排斥势、Δ-学习，以及与 ML 势能面的混合；
- 可以接入主动学习和 LLM 智能体的 API。

梯度的优势随参数个数增长。PTBP 的参数化坚持原计划：每个元素三个参数（r0_w、r0_d、σ_rep，σ_rep 由内层搜索确定，外层优化 r0_w、r0_d），而 SK 表由 hotcent 生成、不可微，梯度要靠“pydftb 自动求导 × hotcent 有限差分”：一次梯度约等于 2–4 次函数值，未必比 BO 快（M4c 实测并如实报告）。多个元素同时优化时（每个元素仍是这三个参数），参数个数增加，梯度法的优势才明显。

现状（M4b）：`pydftb.autodiff` 已经给出能量、电荷、本征值、力、应力对 SK 表的每个值、onsite 能量、U、排斥势系数和坐标的导数，与有限差分对照的 346 项全部通过。在 PTBP 的 Cu 数据集上，能量的梯度只比一次普通计算多花 22%，连同“力对参数”的导数（以力为损失）多花 1.4 倍；对 r0 的梯度还要乘上 hotcent 的切向（4 次 hotcent），那才是主要成本（M4c）。

现状（M4c）：PTBP 已能算损失对 r0_w、r0_d 的梯度，并可选用梯度优化器（`--optimizer gradient`、`bo_grad`）。M4c 时 r0_d 根本不改变 SKF（原因见 M4e：hotcent 2 的微扰约束默认值），所以每次梯度只多跑 2 次 hotcent；M4e 恢复自洽约束后 r0_d 起作用，每次梯度要多跑 4 次；一次“值 + 梯度”约等于 1.4 个 BO 步（energygeometry）和 2.6 个（dataset）。与 BO 的对比（Cu，4 核）：energygeometry 模式梯度法明显更好（同样时间 0.760 对 0.855），dataset 模式打平。只有两个参数也能看到好处，一个原因是 PTBP 默认的 BO（11 次）其实是种子加 10 个随机点；参数变多时梯度法的优势应更明显。

## 4. 新科学：同一元素用多套参数，且随环境平滑切换

固态电池里，Li 可能同时处在有机电解液、无机正极和界面上，一套 Li 参数很难同时描述好。文献现状（已核实）如下：

- DFTB+ 支持给同一元素起不同的物种名（如 `Li1`、`Li2`），各用一套 SKF，但每个原子的类型在整个计算中固定不变。
- Song 等（arXiv:2605.19977，2026）用环境自适应的 Li 参数纠正了 Li 嵌入能垒的错误，但只做单点计算，没有力，不能做分子动力学。
- TBMaLT（JCP 158, 034801, 2023）可以随环境调整压缩半径，但不支持周期体系。
- 常用的 3ob、matsci 参数集**根本没有 Li**；用 DFTB 研究固态电解质、正极/电解质界面的工作也是空白。

pydftb 的目标是**平滑、带力、可做分子动力学、支持周期体系**的多套参数（M5、M8 阶段）。离散多类型的机制已在 M0 打好基础（`System` 的类型标签、`write_typed_copies`），并已与 DFTB+ 对照验证。

这条路上有一个隐藏的坑：两套参数的 Hubbard U 只要相差 3e-6 到 1e-3，DFTB+ 的 γ 公式就会在数值上失效，DFTB3 下实测总能量错 0.5 eV，而且没有任何警告。pydftb 已在 M2b 改用数值稳定的积分形式（`reports/M2b-dftb3.html`）。

## 5. 与 PTBP 一体化

参数生成（hotcent）、计算（pydftb）和拟合（PTBP）可以在同一个进程里完成，不再反复写文件、启动外部程序，为自动参数化铺路。

## 什么时候仍然应该用 DFTB+

- 需要 pydftb 还没实现的功能（见 `ROADMAP.md`），例如响应性质（极化率、Born 电荷，M6g）、长程校正（M6h）、输运、实时 TD（M6 正在按顺序补齐；非共线自旋与自旋轨道耦合（M6a）、DFTB+U 与 onsite 修正（M6b）、外电场、点电荷与隐式溶剂（M6c）、激发态 Casida（M6d）、激发态的力与 XL-BOMD（M6e）已完成，只有 NumPy 引擎）。
- 需要经过长期生产检验的稳定性。
- 性能因场景而异。按 PTBP 的真实设置（按壳层分辨 SCC 等）处理铜数据集时，pydftb 的 DFTB 阶段比经 ASE 调用的 DFTB+ 快 1.8 倍（M1 报告）；在别的体系上要另行测量。
