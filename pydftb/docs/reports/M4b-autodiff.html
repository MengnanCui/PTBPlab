关键信息

新包 pydftb.autodiff（需要 torch）给出 pydftb 结果对参数和几何的导数：SK 表的每个值、onsite 能量、Hubbard U、Hubbard 导数、自旋常数、排斥势系数，以及原子坐标和晶胞。SCC 仍由引擎（NumPy 或 M4a 的 torch）按 DFTB+ 的规则收敛，evaluate() 返回的数值就是引擎自己的数，只是带上了导数。

  • 两种模式：mode="hf"（默认）利用 Mermin 自由能的变分性，把收敛的密度当作常数，得到 dF/dθ、力和应力，不对本征分解求导；mode="implicit" 在 torch 里重算一次 SCC，用隐函数定理接上不动点，能量、电荷、本征值、费米能级、力、应力都有完整的导数，包括“力对参数”的导数（以力为损失）。
  • 与有限差分对照（validation/gradcheck.py --check，11 个算例覆盖分子、T ≈ 0 与有展宽的金属、k 点、自旋、DFTB3、轨道分辨 SCC、H–X 阻尼、f 轨道、色散，随机方向，Richardson 外推）：346 项全部通过。导数大于 1e-4 的 259 项中，hf 的 39 项最大相对差 7.6e-7、中位数 2e-9；implicit 的 220 项最大 2.8e-6、中位数 2e-9。更小的导数受差分的舍入限制。
  • 互相对照：两种模式的 dF/dθ 逐项一致（≤ 8.7e-10，T ≈ 0 的 Cu₈ 金属 6e-12，说明费米能级上 f′ 的抵消成立）；implicit 与“整条 SCC 展开求导”一致到 1e-14–4e-12；伴随方程残差 ≤ 6e-15；密度矩阵的反向通过 11 组 gradcheck（实/复、简并、k 组、自旋组、Gaussian 与 MP、带隙中点规则、T ≈ 0）。
  • 以力为损失：PTBP 用 DFTB+ 的 0.01 Bohr 差分算力；implicit 模式的力用同样的差分核，与引擎的力差 ≤ 1e-11，它们对参数的导数与差分一致到 1e-8。这是 M4c 的力 VJP 需要的量。
  • 发现的问题（第六节）：DFTB+ 的两条约定使引擎的 F 不是“电子数固定的 Mermin 自由能”——MP 展宽配 DFTB+ 的 TS，以及电子数为整数时的带隙中点费米能级（电子数可漂移 1e-7）；异核 SK 文件对 ss、pp、dd、ff 积分各存一份；简并本征值单个没有导数。都已处理或写明。
  • NumPy 路径不变：golden 两个环境逐字节相同；新选项 Smearing(fermi_level=...) 的默认值保持原行为。
  • 346与差分对照的项，全部通过
  • ≤ 8.7e-10hf 与 implicit 的 dF/dθ 逐项之差
  • 0NumPy 路径改变的位（golden 237 次计算、41,519 个量）

二、怎么用

from pydftb import DFTB, ParamSet
from pydftb.autodiff import Params, evaluate

calc = DFTB(ParamSet(skdir).skset(labels), kpts=..., temperature=300.0)
params = Params.from_skset(calc.sk, calc.repulsive, requires_grad=("tables", "hubbard"))

res = evaluate(calc, labels, positions, cell, pbc, params)          # mode="hf"
res.free_energy.backward()            # params.tables[("Cu", "O")].grad, params.hubbard["Cu"].grad

res = evaluate(calc, labels, positions, cell, pbc, params, mode="implicit")
loss = ((res.forces - f_ref) ** 2).sum() + (res.energy - e_ref) ** 2
loss.backward()                       # 力和能量对参数的导数
  • 坐标、晶胞可以传带 requires_grad 的 torch 张量，它们也会收到导数。
  • hf 模式下只有 F 带导数（T ≈ 0 时 E 也带）；有展宽时要 E 的导数，hf 会抛 GradientUnavailable，用 implicit。
  • SCC 没收敛时 evaluate 抛 GradientUnavailable。
  • 参数的方向：异核文件 A-B、B-A 都存的 l₁ = l₂ 积分，以及相等的 Hubbard U，只有“一起变”的方向有导数（第六节）；hotcent 给出的切向就是这样的。

三、结果是否与原来相同

  • pydftb 的 NumPy 路径：golden 工具与 M4 之前的提交 65115d1 比较，conda 环境 237 次计算、41,519 个量，最小环境 198 次、36,176 个量，全部逐字节相同（新增的内部字段 PairBlocks.groups、Coulomb.gint）。golden 包括 PTBP 设置下的 Cu 运行，PTBP 的代码没有改动。
  • 与 DFTB+：refgen --check 两个后端 74 个参考全部通过；dynamics --check 两个后端 11 个参考全部通过。
  • import pydftb 仍不导入 torch；pydftb.autodiff 只在显式导入时需要 torch。

2. hf 模式

  • 替代能量对坐标和应变的导数 = 引擎的解析力和应力：12 个算例最大差 3.6e-15 Ha/Bohr、6.7e-15 Ha/Bohr³。
  • 晶胞的导数（固定笛卡尔坐标）：与引擎 F 对晶胞分量的差分一致到 ~1e-9；与位置梯度一起重建的维里 gᵀR + CᵀH 与应力一致到 1e-14。

3. 与引擎的有限差分（gradcheck --check）

每个算例、每类参数取一个随机方向（按参数的大小缩放），SCC 收敛到 1e-13，中心差分在 2h、h、h/2（h = 2e-5）三个步长上做 Richardson 外推，两次外推之差作为差分的误差棒；另加舍入的噪声下限（30 ε|X|/h，对非变分的量再加 SCC 容差造成的 1e-13 × 项数 / h）。hf 的参照用 fermi_level="exact"、ts_convention="variational"，容差 1e-7；implicit 的参照用引擎默认的 DFTB+ 约定，容差 1e-6。

4. 互相对照

  • hf 与 implicit：11 个算例 dF/dθ 逐项（每个张量的最大差 / 最大值）≤ 8.7e-10（GdO），其余 ≤ 3e-11；T ≈ 0 的金属 Cu₈ 6.2e-12。
  • implicit 与展开：线性混合把 SCC 收敛到机器精度、整条循环求导，与隐式结果比较：水 1.2e-14，甲醇（DFTB3）4.0e-12，Cu₄CO（金属团簇，混合 0.05、1500 步）6.0e-13。
  • 伴随方程：稠密解的残差 ≤ 6e-15；强制走 GMRES 与稠密解一致到 1e-9 以内，残差 ≤ 1e-10。
  • 密度矩阵的反向：torch.autograd.gradcheck 对整个前向（含主机上的费米能级搜索）11 组全部通过，随机方向的最大相对差 1.5e-8。
  • 两种引擎后端：NumPy 引擎与 torch 引擎给出的梯度一致到 1.3e-14（水）、2.9e-11（CuO 自旋链，两边 SCC 各自收敛到 1e-12）。

五、代价

PTBP 的 Cu 数据集（66 个结构，1–2 个原子，PTBP 的 k 点规则；已发表的 Cu 点上 PTBP 生成的表；PTBP 的 pydftb 设置：T ≈ 0、SCC 1e-5、0.01 Bohr 差分、轨道分辨 SCC、多项式排斥势），一个进程、一个线程：

做什么66 个结构合计相对引擎
引擎：能量和力（一个 BO 步里每个结构做的事）29.0 s1
hf：引擎 + 能量对表、onsite、U、排斥势系数的导数35.5 s1.22
implicit：引擎 + torch 里的 SCC 步 + 能量与“力之和”的导数（以力为损失的 VJP）68.4 s2.36
  • hf 的导数只多花 22%：替代能量对参数的梯度只需重算一次原子对块和 γ。最大的结构（2 个原子、1,688 个 k 点）引擎 1.97 s，hf 1.90 s（计时的波动大于差别）。
  • implicit 多出两次全部 k 点的本征分解（Φ 和下游各一次）、伴随方程的雅可比矩阵（每个电荷一次反向传播，轨道分辨的 Cu₂ 有 6 个）、以及对力的二阶反向；最大的结构 4.75 s。
  • 对 M4c 的含义：一个 BO 步里 DFTB 阶段在 4 核上约 10 s（M3b），加 hf 梯度约 +2 s，加以力为损失的梯度约 +14 s；hotcent 的切向（4 次 hotcent，每次 4.6 s，可并行）仍是梯度的主要成本。

六、发现的问题

  • MP 展宽配 DFTB+ 的 TS 时，F 不是变分的（M4 之前就如此，DFTB+ 相同）。DFTB+ 的熵项把 MP 各阶的 Hermite 项都加上，只有最高阶那一项才与占据函数配套。实测 Cu₈、MP2、2000 K：引擎的解析力与 −dF/dx 差 1–9%，与 −dE/dx 也不同。test_smearing.py 早已记录这一点；现在 hf 模式遇到这种设置拒绝给 dF 的梯度（提示用 ts_convention="variational"），implicit 模式则直接对引擎的 F 求导（gradcheck 的 MP 算例用的就是 DFTB+ 约定）。
  • 带隙中点的费米能级让电子数漂移。电子数为整数时，DFTB+ 先试带隙中点，只要那里的电子数与目标差 ≤ 1e-7 就采用。有展宽、带隙小的体系（Cu₄CO 300 K：差 4e-8；CuO 链的上自旋：3e-9）因此不是“电子数固定”的 Mermin 自由能，F 的导数多出 μ dN/dθ：hf 模式与引擎 F 的差分差 1.7e-5（相对），引擎自己的解析力与 −dF/dx 差 1e-7 Ha/Bohr（DFTB+ 对照表的坑 7 早已记下力与能量导数的这一差别）。新增 Smearing(fermi_level="exact")：总是二分到准确的电子数（默认仍是 DFTB+ 的规则，结果逐位不变）。implicit 模式按引擎实际用的规则对 μ 求导（中点规则下 dμ = ½(dεH + dεL)）。另外，两条规则在 1e-7 的阈值处切换，F 在那里不连续（构造的测试里 1e-6 的扰动就让规则翻转）。
  • 异核 SK 文件的冗余积分。A-B 和 B-A 两个文件都存 l₁ = l₂ 的积分（ss、pp、dd、ff）。引擎的矩阵上、下三角各用一份，本征求解只读一个三角、Mulliken 求和两个都读（DFTB+ 只填下三角，用哪一份取决于原子编号的顺序），所以只改其中一份时，S 不再对称，引擎的响应取决于这些实现细节（实测：水的表方向 dF 差 5%，甲醇的连符号都不对）。只有两份一起变的方向有意义——hotcent 生成的两份数值相同，它的切向就是这样。梯度在两份之间平分（hf 的替代能量天然如此；implicit 模式在折叠后取 H0、S 的厄米部分，使两种模式逐项一致）。gradcheck 的随机方向按此绑定。同理，相等的 Hubbard U（DFTB+ 对 |ΔU| < 3.125e-6 走另一个分支）只有一起变的方向有导数。
  • 简并本征值。单个简并本征值没有线性的导数（扰动劈裂的方式随方向变）；本征值的梯度在每个简并能级内取平均，对能级的任何对称函数是精确的。ρ、W、能量、电荷、力不受影响（差商对简并有定义）。
  • D3（三体项、周期）的维里与能量不完全配套：库给的维里与它的能量在应变下的差分差 3e-4（相对），且差分随步长不收敛（实空间截断造成的不连续）。pydftb 的应力用的就是库的维里（与 DFTB+ 一致）；晶胞的导数由梯度和维里推出（C = H⁻ᵀ(W − gᵀR)ᵀ），因此同样以库的维里为准。
  • 差分作为参照的局限：GdO 的表方向上 f 态响应很强，单个中心差分在 h = 1e-4 时误差 3e-3；DFTB+ 的 SK 尾部公式（二阶差分，步长 1e-5）把表值的舍入放大 1e10，使本征值之和的差分带 ~4e-10 的噪声；E（有展宽时）、电荷、本征值、力不是变分的，带一阶的 SCC 误差，所以参照要收敛到 1e-13。gradcheck 因此用三步 Richardson 和误差棒。
  • 对 PTBP 的含义（留给 M4c）：在 PTBP 的设置下（SCC 1e-5、T ≈ 0），hf 与 implicit 的 dE/dθ 只一致到 7e-7–2.4e-5（Cu 数据集 4 个结构），非变分量（力、电荷）的导数也只有 SCC 容差量级的精度；求梯度时宜收紧 SCC。T ≈ 0 的金属里，费米能级上简并的能级被参数劈裂时，占据数在 kT = 1e-8 Ha 内翻转，力对参数的导数会很大：只用 Γ 点的 2 原子 Cu 晶胞，|F|² 对表的导数最大 7.3e3，用 k 网格的结构 ≤ 3e-2。数值是对的（kT = 1e-8 Ha 下的导数），但作为优化的方向没有意义；以力为损失求梯度时宜加展宽。

七、单元测试

新增 60 项：test_autodiff.py 29 项（核函数对照 7、hf 的力和应力 10 个算例、参数导数 vs 差分 7 个算例、坐标与晶胞的叶张量、拒绝的情形、Params 的往返、带隙中点规则的影响、选项检查）、test_autodiff_implicit.py 30 项（密度矩阵 gradcheck 11 组、简并能级、implicit vs 差分 6 个算例、hf 与 implicit 4 个算例、展开 3 个算例、伴随方程两种解法、0.01 与 1.22e-4 两种差分步长下的力、返回值即引擎的值、两种引擎后端）、test_smearing.py 1 项。conda 环境 pydftb 测试 429 个全部通过（约 2 分钟）；最小环境（无 torch）257 个通过、93 个跳过；最小环境加 torch 398 个通过、31 个跳过（没有 dftd3/dftd4）。PTBP 的 179 个测试：171 个通过、1 个跳过，失败的仍是已知的 7 个界面冒烟测试（与之前相同）。

八、与计划的偏差

  • 没有加 DFTB.calculate(keep_state=True)：内部的 _run() 返回 setup 和 SCC 状态，公开接口不变。
  • Params 不把相等的 U 或冗余的 SK 积分“绑”成一个张量（那样会改变参数的形状）；改为写明只有一起变的方向有意义，gradcheck 按此取方向，梯度在各份之间平分。
  • MP 的 Σ w f′ 接近 0 时没有报错：Σ w f′ = 0 时不耦合 μ，其余情况照常（MP 的测试通过）。
  • 没有另做 value_and_grad、vjp、jvp_tangent：evaluate() 返回 torch 张量，VJP 就是 torch.autograd.grad，沿切向 t 的导数是 grad·t（gradcheck 就这样用）。M4c 若需要把 hotcent 的切向打包成函数，再在那里加。
  • 差分对照的步长与容差：计划写 SCC 1e-12、相对差 1e-7；实际用 SCC 1e-13、三步 Richardson、误差棒，implicit 的容差按计划取 1e-6（见第四节第 3 小节）。
  • 新增了计划外的 Smearing(fermi_level=...)，用于把引擎的 F 变成电子数固定的 Mermin 自由能（第六节）。
