关键信息

pydftb 现在有 DFTB+ 的 Solver 块的对应：solver="ntpoly" 用矩阵乘法的纯化求密度矩阵，不做本征分解。它是 NTPoly 2.7 四种纯化（PM、TRS2、TRS4、HPCP）的逐步移植，包括截断、收敛判据与化学势。三种 LAPACK 驱动（QR、DivideAndConquer、RelativelyRobust）与 ELPA 也有了。13 个 DFTB+ 参考算例全部对上，NTPoly 的参考来自 DFTB+ 24.1 + ELSI。DFTB+ 的 NTPoly 拒绝或算错的地方，pydftb 照样给出正确结果：自旋通道、两分量、k 点、杂化泛函、块势、XL-BOMD，以及 torch 设备与混合精度。只有本征分解的旧计算逐位不变。

  • 对 DFTB+ 的 NTPoly（9 个算例，四种方法，默认与收紧的设置）：
    • SCC 轮数全部相同，包括 TRS2 在默认容差下多出的 2 轮；
    • 能量 ≤ 9.4e-11 Ha，力 ≤ 8.4e-11 Ha/Bohr，电荷 ≤ 1.4e-10 e；
    • 化学势 ≤ 6.8e-12 Ha，DFTB+ 把它当费米能级。
    LAPACK 驱动与 ELPA 的 4 个算例 ≤ 2.7e-11 Ha。
  • 越过 DFTB+：收紧的 TRS2（容差 1e-10，截断 1e-15）等于本征分解。12 种哈密顿量下能量 ≤ 1.1e-10 Ha，电荷 ≤ 1.6e-10 e，力 ≤ 7.2e-11 Ha/Bohr，SCC 轮数相同。这 12 种是：共线自旋、SOC、k 点、分子与 k 点的杂化、+U、onsite、H5、外场、点电荷与溶剂。XL-BOMD 的 20 步轨迹与本征分解差 < 1e-8 eV。
  • DFTB+ 的问题：
    • B28：NTPoly 用稠密输入且有块势时结果错，最多差 3.6e-2 Ha。
    • B29：没有自旋而电子数为奇数时，电子数被悄悄进位，H2O+ 按中性水算。pydftb 改为报错，并提示改用自旋。
    • OMM 在 16 次默认设置的运行里 9 次 SCC 不收敛，pydftb 不实现它。
  • 速度：在本机 CPU 上，稠密纯化比本征分解慢 4–6 倍，3072 个轨道时是 16–19 s 对 3.2 s。它的价值在 GPU 上和之后的稀疏版本（M7c）。
  • 13 / 13DFTB+ 参考算例通过（SCC 轮数全同）
  • ≤ 9.4e-11能量对 DFTB+ 24.1 NTPoly（Ha）
  • 12DFTB+ 的 NTPoly 不支持而 pydftb 支持的哈密顿量
  • 0旧计算路径改变的位

开发细节一、做了什么
位置内容
purification.py（新）
  • NTPoly 2.7 的稠密算法，NumPy 与 torch 共用（数组的类型决定后端，标量的控制流用 Python 浮点数）：
    • inverse_sqrt：耦合 Newton–Schulz，Taylor 五阶；
    • 四种方法：类 _PM、_TRS2、_TRS4、_HPCP，各有起点、一步与这一步的标量多项式；
    • purify：NTPoly 的循环、收敛判据与截断；
    • 化学势：在组合多项式上二分，只用 “退出步数 − 1” 步。
  • 求解器类 NTPoly（eigenpairs = False）：
    • prepare(S)：每个几何、每个 k 算一次 Z；自旋通道重复的一半不重算。
    • density(h, kw, n_occ, g, need_w)：每个矩阵纯化一次，得到 P = g Z†XZ 与 W = PHP/g；化学势按 k 点权重平均；占据数不是整数时报错。
    • solve：与本征求解器相同的闭壳层接口。
    • precision="mixed"：单精度的步骤在前，见第五节。
backend/ops.pyeigh_driver(a, b, driver)："gv"、"gvd" 经 SciPy；"gvr" 是 DFTB+ 的 hegvr：potrf，hegst/sygst，heevr/syevr（全部本征值，abstol 取安全最小值），再做三角回代。
solvers.py
  • EighSolver(driver=None)：driver 为 None 时照旧调用 ops.eigh（逐位相同）。
  • SOLVERS 新加 "qr"、"divideandconquer"、"relativelyrobust"、"elpa"（= "eigh"）与 "ntpoly"；UNSUPPORTED_SOLVERS 给 "omm"、"pexsi" 的说明。
  • SP2Solver 标上 eigenpairs = False。
calculator.py
  • 构造时检查求解器名（未知名与 OMM、PEXSI 报错）。
  • _check_purification：只用 Fermi 填充（DFTB+ 的原话）；T > 0 时警告；不能和 relax_total_spin 一起用；混合精度配 scc_tol < 1e-5 时警告；需要本征矢的分析报错。
  • 原来对 "sp2" 的检查（固定费米能级、每个 k 单独填充、Casida）改成 “求解器是否给本征对”，报错的话写出求解器名。
  • _solve_density：没有本征对的求解器按无自旋、自旋通道（每个通道一个化学势）、两分量调用 density。结果没有本征值与占据数，TS = 0。
  • torch 后端用同一个 NTPoly 类，计算在设备上进行。
ase_calc.py、dftbplus_io.py求解器没有占据数时，get_occupation_numbers 给出说明（本征值已有同样的说明）；write_band_out 遇到没有本征值的结果时报错，并指向 bands.eigenstates。
validation
  • cases.py：新字段 solver，13 个算例；dftbplus = "elsi" 指 $DFTBPLUS_ELSI，即 24.1 MPICH 版的单进程包装。
  • dftbplus.solver_block 写 Solver = ...，NTPoly 只写与默认不同的键。
  • refgen：
    • 用算例的求解器；
    • 冻结 NTPoly 的化学势与每轮误差；
    • 参考里没有 Mermin 自由能时用总能量；
    • 没有本征值时不比较本征值；
    • 求解器算例比较 SCC 轮数（必须相同）、每轮误差（相对 1e-4）与化学势。
测试新文件 tests/test_purification.py：46 项（见第七节）。

二、怎么用

DFTB(sk, solver="ntpoly")                     # = DFTB+ Solver = NTPoly {}：TRS4，1e-5，1e-10
from pydftb.purification import NTPoly
DFTB(sk, solver=NTPoly("trs2", tolerance=1e-10, truncation=1e-15))   # 等于本征分解
DFTB(sk, solver=NTPoly(precision="mixed"), backend="torch", device="cuda", scc_tol=1e-5)
DFTB(sk, solver="relativelyrobust")           # 或 "qr"、"divideandconquer"、"elpa"
PyDFTB(skdir, solver="ntpoly")                # ASE 同样可用
  • 结果：eigenvalues 与 occupations 为 None，TS = 0；fermi 是 NTPoly 的化学势（DFTB+ 相同；它是纯化多项式的 0.5 等值点，不是带隙中点）。共线自旋时 fermi_spin 给每个通道的化学势。solver.last_iterations 记录当前几何的 SCC 里每次纯化的步数（每次调用一个列表，换几何时清空），solver.isr_iterations 记录 S−1/2 的步数。
  • 能用的：
    • 只需要密度矩阵与能量加权密度矩阵的功能：力、应力、结构优化、MD 与 XL-BOMD，以及 SCC 的各项（DFTB3、+U、onsite、外场、点电荷、溶剂、色散、H5、卤素修正、偶极修正）。
    • 按原子的能量、净布居、CM5、键分析。
    • 能带与 DOS：后处理本来就在 SCC 的电荷上做一次对角化，同 DFTB+ 的能带运行，所以照样可用。只有 SCC 自己的 band.out 写不出（没有能级）。
  • 报错的：
    • 要本征矢的分析（eigenvec.out、Pipek–Mezey、响应与坐标导数）、Casida、固定费米能级、每个 k 单独填充；
    • MP 与 Gaussian 展宽（DFTB+ 的原话）、relax_total_spin；
    • 每个自旋通道的占据数不是整数（例如没有自旋的奇数电子）。
  • 适用范围：纯化给出 T = 0 的投影，体系要有带隙。k 点的每个点按相同的占据数纯化，所以金属会悄悄给出错误的占据，这与 DFTB+ 的组并行相同。有限温度与金属放在 M7b。
  • 选哪种方法：DFTB+ 的默认 TRS4 有 1e-8 量级的误差，提前退出（|tr G| < 1e-14）后收紧容差也不变。TRS2 在默认容差下有 1e-4 e 量级的误差。要与本征分解一致，用收紧的 TRS2（容差 1e-10，截断 1e-15），步数约 20。

混合精度（precision="mixed"，pydftb 自己的选项，NTPoly 没有）：

  • 规则：先用单精度纯化。tr(X − X²) 到达单精度的噪声（10·n·ε32）后转到双精度；tr(X − X²) 已小于 1e-2·√n 而两步内不再下降，也转到双精度。双精度最多再走 4 步，或者 NTPoly 的判据先满足。X 回到双精度。
  • 单精度引入的子空间误差（占据与空轨道的混合），之后的双精度步骤修不掉，所以电荷的误差在 1e-6 量级。scc_tol < 1e-5 时警告：试过 1e-10，Broyden 跑满 500 轮也不收敛，能量差到 48 Ha。
  • 实测（scc_tol 1e-5，对双精度的 TRS4；能量 Ha，电荷 e）：H2O 4.5e-9、1.0e-7；CH3OH 9.3e-7、1.5e-6；水盒子（DIIS）3.4e-8、4.6e-6，SCC 23 轮（双精度 17 轮）。

六、DFTB+ 的情况

DFTB+pydftb 的做法
conda-forge 的 25.1 MPI 版把 ELSI 列为依赖却没有链接，选 ELSI 的求解器时报 “Not compiled with ELSI supported solvers”参考用 24.1 的 MPICH 版（链接 ELSI 2.9.1）
B28：NTPoly 的稠密输入（Sparse = No）配块势：对稀疏输入差 5.3e-6（+U）、2.2e-2（+U 加 onsite）、4.3e-3–3.6e-2 Ha（onsite）。DFTB+ 的 unpackHSRealBlacs 把原子自身的块照原样写入，只对不同原子的块补转置。LAPACK 与 ELPA 只读一个三角，NTPoly 读整个矩阵。不受影响（矩阵本身对称）；参考用 DFTB+ 默认的稀疏输入
B29：没有自旋而电子数为奇数时，NTPoly 按 2·nint(N/2) 个电子算，不报错。OH 的净电荷成了 −1；H2O+ 的能量与中性水逐位相同。报错：每个自旋通道的占据数必须是整数，提示改用自旋
NTPoly 拒绝自旋（共线与非共线）：“Solver does not currently support spin polarisation”支持，每个通道或旋量矩阵各纯化一次
“This electronic solver can only be used for Fermi function distributed electrons”；温度不起作用MP 与 Gaussian 用 DFTB+ 的原话报错；T > 0 时警告
每个 (k, 自旋) 要一个 MPI 组：“This solver requires as many parallel processor groups as there are independent spin and k-point combinations”k 点逐个纯化，不需要进程组
MPI 构建拒绝杂化（“Range separated calculations do not work with MPI yet”）与 Casida杂化可以用纯化；Casida 需要本征矢，报错
OMM：自旋要共用费米能级，不写费米能级；P99 里 16 次默认设置的运行 9 次 SCC 不收敛，其余要 3–30 倍的轮数，nIterationsELPA = 0 时一次收敛到差 75 Ha 的态不实现，solver="omm" 报错并说明原因
PEXSI：conda-forge 的 ELSI 没有编译不实现；有限温度放在 M7b

B28、B29 与其余发现记入 dftbplus_map 的坑 175–180；向 DFTB+ 报告需要你同意。

八、与设计的偏差

  • 混合精度的切换：设计用能量判据，即单精度的能量变化不再减小时转到双精度，再迭代到 NTPoly 的判据。实测有两个问题：TRS2 早期能量变化会回升，这个判据让它过早停下，X 差 0.44；HPCP 在双精度下走满 100 步。所以改成幂等性 tr(X − X²) 的判据，加上 Kruchinin 式的 “足够小之后两步内不降” 保护，双精度最多 4 步。另加了 scc_tol < 1e-5 的警告。
  • 能带与 DOS：设计把它们列为 “需要本征值、拒绝”。实际上 bands.eigenstates 在 SCC 电荷上自己对角化（求解器没有本征矢时用分批的本征分解），所以照样可用，第四节验证了。SCC 结果里不带本征值，所以 write_band_out 改为明确报错。
  • 门槛重跑了两次：第一次启动后，补查发现 ASE 的 get_occupation_numbers 与 write_band_out 遇到没有占据数的结果时抛出看不懂的 TypeError；另外 last_iterations 在长的 MD 里会一直增长。修好并补了测试（外场、点电荷、溶剂、应力、能带、XL-BOMD、ASE 的接口）之后，门槛从头重跑。第七节是最后一次的结果。
  • HSD：设计说 ELSI 的算例去掉 UseOmpThreads。24.1 的 MPI 版在单进程时接受它，所以 HSD 与其他算例相同。
  • ELSI 版本：参考 JSON 记下 DFTB+ 的版本（24.1）；ELSI 2.9.1、NTPoly 2.7.1 写在 cases.py 的注释与本报告里，JSON 不另记。
  • 验证：设计里 “力对能量的差分” 没有单独做。收紧的 TRS2 的力与本征分解差 ≤ 1e-10，而本征分解的力已经对过差分与 DFTB+。
  • 拒绝原文：需要本征矢的分析统一成 “the analysis (…) needs an eigensolver (not the NTPoly solver)”。
  • 其余按设计。
