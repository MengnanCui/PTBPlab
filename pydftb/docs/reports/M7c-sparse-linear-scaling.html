关键信息

pydftb 的 NTPoly 纯化现在可以整条在稀疏矩阵上走：NTPoly(sparse=True)，对应 DFTB+ 的 Solver = NTPoly { Sparse = Yes }。H0 与 S 按邻居块的图样组装，不再有 N × N 的矩阵。S−1/2、H̃、纯化、P 与 W 是带 NTPoly 逐元素截断的 SciPy CSR 乘法。Mulliken 布居、能带能量、力与应力只用图样上的密度矩阵元。算法与稠密路径是同一份代码，只在数组函数里按类型分派；默认的 sparse=False 仍是 M7a 的稠密路径，逐位不变。

  • 对稠密的 NTPoly：16 种哈密顿量，包括分子、Γ 点、k 点、两种共线自旋、DFTB3、色散、外场、点电荷、溶剂、卤素修正与电荷文件，都在相同设置下比较。NTPoly 的稠密分支与全部 CSR 乘法两种情形下：能量差 ≤ 2.8e-14 Ha，电荷 ≤ 2.8e-14 e，力 ≤ 6.8e-15 Ha/Bohr，应力 ≤ 8.2e-18，SCC 轮数全部相同。
  • 对 DFTB+：M7a 的 7 个 NTPoly 参考（DFTB+ 24.1 + ELSI 2.9.1，四种方法，没有块势）走稀疏路径，偏差与稠密路径完全相同：能量 ≤ 6.2e-11 Ha，SCC 轮数与 DFTB+ 相同。块势的 2 个参考按设计跳过。
  • 速度（本机 4 核，水盒子，Γ 点，SCC 加力，截断 1e-6）：
    • 求解部分每轮 SCC 的耗时随 N 线性增长：1000 与 1728 个水分子都是每个分子每轮 9.8 ms。
    • 512 个水分子时与本征分解持平（总计 77 s 对 79 s）；1000 个时求解快 2.2 倍（156 s 对 336 s），总计 1.8 倍（219 s 对 404 s），内存也更少。
    • 1728 个水分子（10368 个轨道）共 411 s，其中求解 271 s。本征分解只计时了一次对角化（101 s），按 16 轮估计全程约 1800 s：稀疏的求解快约 6 倍。
  • 截断的精度：截断 1e-6 时 X 每行约 273–281 个非零元，不随大小变。216 个水分子对本征分解：能量 3.4e-7 Ha，电荷 4.7e-7 e，力 3.2e-7 Ha/Bohr（P111）；大体系见第三节。
  • 内存：SCC 中图样上的矩阵与截断的 CSR 很小。峰值出现在建立 γ（Ewald）的阶段，与稠密路径共用：1728 个水分子时 9.3 GiB，SCC 中 4.3 GiB。
  • ≤ 2.8e-1416 种哈密顿量对稠密 NTPoly 的能量差（Ha）
  • 7 / 7适用的 DFTB+ NTPoly 参考通过（两种乘法分支）
  • 9.8 ms每个水分子每轮 SCC 的求解耗时（1000 与 1728 个）
  • 0旧计算路径改变的位

开发细节一、做了什么
位置内容
csr.py（新）
  • matmul(A, B, τ)：两个因子的填充都 > 0.1 时转成稠密做 GEMM（NTPoly 的规则）；否则 A 按行分成 4·t 块，在线程池里各乘 B，每块在线程里截断（|c| < τ 置零）、去掉零、排好下标，再按行拼起来。SciPy 的 CSR 乘法释放 GIL，分块的结果与串行逐位相同。
  • options(threads, dense_fill)：用 contextvars 把线程数与稠密阈值传给乘法。
  • drop、eye、ct、trace、dot（Re tr(AHB)）、abs_column_sums、gershgorin、equal。
  • Pattern：邻居对的矩阵元与对角元的 CSR 结构，周期体系的像折叠到同一个 (μ, ν)；每个邻居对元素的位置 elem 与转置位置 elem_t，对角位置 diag。fold（Γ 点实数，k 点乘相位）、matrix（共用下标的 CSR）、sample（乘积在图样上的值）、row_sums（布居）、at_pairs（力用的实空间值）。
purification.py数组函数加 CSR 分支，与 torch 分支并列；NTPoly(sparse=False, threads=None, dense_fill=0.1)；prepare 与 density 接受 CSR 的列表；last_fill：最后一次密度里 X 每行的平均非零元数；sparse=True 配 precision="mixed" 报错。稠密路径的运算不变。
calculator.py
  • _Sparse：图样与 H0、S 的值（每个 k 一行），hamiltonian(h0, v, vs) 在图样上组装 H 与两个自旋通道。
  • _setup：稀疏时建图样，st.h0 与 st.smat 为 None。
  • _scc：CSR 的 S 交给 prepare，每轮在图样上组装 H；_with_net 把净位点电势加在图样的对角上。
  • _solve_sparse：每个自旋通道调用求解器，把 P、W 取值到图样。
  • _mulliken、_trace、_net_populations、_pair_densities：稀疏分支。
  • _check_sparse：拒绝 torch、两分量、块势、杂化、Casida、分析输出、XL-BOMD 的力。
validationrefgen --check --solver sparse 与 sparse-csr（每次乘法都走 CSR）：NTPoly 参考算例改用 sparse=True，其余算例打印原因跳过（sparse_skip）。
测试新文件 tests/test_sparse.py：42 项（见第六节）。

二、怎么用

from pydftb.purification import NTPoly
DFTB(sk, solver=NTPoly(sparse=True))                     # DFTB+ 的 Sparse = Yes：TRS4，1e-5，1e-10
DFTB(sk, solver=NTPoly(sparse=True, truncation=1e-6))    # 大的有带隙体系
DFTB(sk, solver=NTPoly("trs2", sparse=True, threads=2))  # 稀疏乘法用 2 个线程
PyDFTB(skdir, solver=NTPoly(sparse=True, truncation=1e-6))  # ASE：求解器对象在各步之间共用
  • 截断：DFTB+ 的默认 1e-10 在一千个水分子以内几乎不稀疏，适合与 DFTB+ 逐项对照。线性标度要放宽到 1e-6–1e-8，误差见第三节。
  • 能用的：分子、Γ 点、k 点；无自旋与共线自旋；DFTB3、H 阻尼、H5、色散、外场、点电荷、位点电势、溶剂、卤素与偶极修正、自定义 Hubbard 与参考占据、混合器、初始电荷与电荷文件、类型切换；力、应力、优化、MD。
  • 报错的：两分量（DFTB+ 同样拒绝）、+U 与 onsite、杂化、Casida、分析输出、XL-BOMD 的力、torch、precision="mixed"。这些用稠密的 NTPoly() 或本征分解。
  • 小体系：X 的填充超过 10% 时乘法本来就走稠密分支，再加上格式转换，比稠密路径慢（216 个水分子约 2 倍）。稀疏路径从几百个水分子起才有意义。

  • 线性：稀疏求解每轮 SCC 的耗时，截断 1e-6 时 3.7、9.8、16.9 s（512、1000、1728 个水分子），每个分子 7.2、9.8、9.8 ms；1e-7 时 11.6、23.6、45.0 s，每个分子 22.6、23.6、26.0 ms（X 每行 501–518 个元素）。
  • 1728 个水分子的本征分解：全程要半小时以上，只计时了一次对角化（含密度矩阵）：101 s，比 1000 个水分子时每轮的 21 s 多 4.8 倍（N³ 是 5.2 倍）。按 16 轮估计求解约 1620 s，加上建立、布居与力，全程约 1800 s。稀疏的求解快约 6 倍（1e-6）与 2.3 倍（1e-7），全程快约 4.4 倍与 2.1 倍。
  • 优化：第一版把截断放在拼接之后的主线程里。剖析（512 个水分子，3 轮）显示截断、排序与拼接的时间和乘法本身一样多：未截断的乘积比结果宽好几倍。改到线程里之后，512 个水分子的求解从 106 s 降到 56 s。
  • 求解器之外：邻居对（k-d 树，含 27 个像）与 Ewald 的 γ（O(Nat1.5–2)）在 1728 个水分子时共 101 s，力 31 s；建立 γ 的阶段（Ewald 的实空间对表）临时多占约 5 GiB：峰值 9.3 GiB 出现在这一段，SCC 中是 4.3 GiB。这些与稠密路径共用，是下一步更大体系的瓶颈。
  • 小体系：216 个水分子时 X 的填充 21%，乘法走稠密分支，格式转换使它比稠密路径慢约 2 倍。截断 1e-7 时每行多一倍元素，乘法相应变慢。

七、与设计的偏差

  • 模块名：设计写的是 sparse.py，但 M0 的原型已用这个名字（bench/sparse_bench.py 还在用），新模块叫 csr.py，原型不动。
  • 截断放在线程里：设计只说 “分块后拼接”。剖析后改为每块在线程里截断、排序再拼接（第五节）。
  • 类型切换：设计没有列出。它只用邻居对的值（H0、S 与它们的导数），在图样上照样成立，测试与稠密路径一致，所以放开。
  • refgen 的选项：设计写 --sparse 与 --sparse-branch，实现用 --solver sparse 与 sparse-csr，与 M7b 的 --solver foe 一致。
  • DFTB+ 的计时：设计打算在第五节并列 DFTB+ 的 NTPoly。只有 P110 的数（设计文档）：一个进程、一个线程、非 SCC，而第五节的 pydftb 用 4 个线程，不能直接比较，所以没有并列。两边的交叉点相近：截断 1e-6、1000 个水分子时，DFTB+ 的 NTPoly 比 RelativelyRobust 快 2.1 倍（36.2 s 对 76.3 s），pydftb 的稀疏求解比本征分解快 2.2 倍。
  • 1728 个水分子的本征分解：全程要半小时以上，只计时了一次对角化，全程是估计（第五节）；截断的误差在这个大小上对 1e-7 计算（第三节）。
  • 其余按设计：k 点、共线自旋、力与应力都在稀疏路径上；FOE 的稀疏版、块势、两分量与杂化不做。

八、下一步

  • 更大的体系：Ewald 的实空间对表与 γ 矩阵（Nat²）、邻居表的常数，是几千个水分子以上的瓶颈：分块的 Ewald 或不建矩阵的电势。
  • 块势的稀疏路径：+U 与 onsite 不改变 H 的图样，块布居要 ρS 的原子对角块。
  • 之后是 M7d 分治与多机，M7e GPU 自检与跨结构批量。
  • 向 DFTB+ 报告 B28、B29（以及 B1、B2、B3、B6、B13、B18–B26）：需要你同意再提交 issue。
