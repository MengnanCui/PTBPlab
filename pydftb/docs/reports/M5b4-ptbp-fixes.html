关键信息

用户在 M5b-3 之后决定的三项修改（M5b-3 报告第八、九节），都在 PTBP 一侧，pydftb 未改动。① energygeometry 损失的 Boltzmann 因子改为在每种组成内分别计算（组成 = EOS 组结构的约化化学式，B2N2 → BN）：每种组成得到它单独作为数据集时的因子，不同组成的每原子总能量不再互相比较。② --shared-parameters 与列出数据集全部元素的 --multi_element 一起使用时在开始时报错。③ σrep 搜索中 L-BFGS-B 的结果与 σ* 处的损失配对：SciPy 可能把 σ* 与另一次求值的损失一起返回，现在用记录下的 μ(σ*)；两条路径（一个参数集、按类型）都改。M5b-2 定下的失败值规则不变。

  • Boltzmann 因子：原来所有 EOS 组在同一个 Boltzmann 分布里比较 DFT 每原子总能量（3000 K，kBT = 0.26 eV），组成不同时相差几百到几万 eV，只有能量最低的组成有权重：dft/nitrides.xyz 的 18 种组成只有 I4N16 为 1，其余为 0；现在 18 种都是 1（每种组成一个 EOS 组）。只有一种组成的数据集（所有单元素数据集）逐位不变；--multi_element 的相同权重不变。所有使用者——DFTB 阶段的 k 点、一个参数集与按类型两条损失路径、utils/loss_grad.py、计划（plan.json、ptbp plan）、ptbp parity、打印——都经过同一个 utils.data.get_bolt_factor；多组成运行的检查点元数据多记 "boltzmann": "per composition"，不续跑 M5b-4 之前写的这类检查点（第二节）。
  • 演示（energygeometry、pydftb、11 次 BO，dft/nitrides.xyz 的 B2N2 + N3Na，按元素与 --shared-parameters，基础对本分支）：因子 [0.0, 1.0] → [1.0, 1.0]，B2N2 的 11 个结构由只算 Γ 点改为完整的 k 点网格并进入损失。两次计算同样的 11 个点：按元素时每个点的损失都变了（排序也变），最低仍是种子点，0.0926528370 → 0.0745784425，σB 原来对损失没有作用、现在由 B2N2 决定；共用参数时每个损失大了 3.8–6.2 倍（一组参数描述 B2N2 很差，原来权重为 0 看不出），最低点不变，0.1903568534 → 0.7298165280。DFTB 阶段每步多约 0.7 s（hotcent 约 30 s）（第二节）。
  • 拒绝的组合：没有元素留在 PTBP 的参数上时类型模型判为旧布局，旧代码按 --multi_element 的旧含义只给第一个列出的元素设半径。基础提交上 B2N2 + N3Na 加 --shared-parameters --multi-element B N Na 的 11 个点全部失败（没有结构得到 DFTB 结果，每点 1000），最后停在 BO 结束时的作图错误；现在开始时报错并说明三种可行的做法，不写 par.out、plan.json、results/；ptbp plan 同样拒绝（第三节）。
  • L-BFGS-B 的配对：线搜索失败时 SciPy（1.17.1）把 x 退回上一个迭代点，返回的 fun 却是最后一个试探点的损失。用 M5b-3 第八节那类合成数据（盒子里的 CO、OH 分子，DFTB 极小在扫描范围外，EOS 拟合随 σ 跳动）重现：基础返回 σ* = 0.5941628418 与 1.8950513240，μ(σ*) = 1.8950513447；合成的跳动损失上基础返回 74.90，μ(σ*) = 1.80。现在都返回 μ(σ*)，并打印一行说明；不出现不配对时返回 SciPy 的结果本身（第四节）。
  • 逐位不变：G1 损失 0.9198547924，1 核与自动核数逐位相同，34 个文件与基础提交 77a0e38 逐字节相同；共用参数的 reaction 示例（B2N2 + N3Na，11 次 BO，DFTB+，同一输出路径）296 个文件中 261 个逐字节相同，其余只有已知的每次运行不同的内容（可用内存、耗时、孤立原子 DFTB+ 输出的随机种子与计时表），11 个损失逐位相同（最佳 368.3471325）。
  • 改变的旧结果：组成不止一种的 energygeometry 运行（没有 --multi_element；两条路径、所有优化器）；--shared-parameters 加全部元素的 --multi_element（原来每个点都失败，现在拒绝）；L-BFGS-B 不配对的那一步（门槛的运行与磁盘上留着的 206 个旧 BO 步中都没有出现）（第五节）。
  • 18dft/nitrides.xyz 中有权重的组成（原来 1 种）
  • 286PTBP 测试通过（新增 16 项；7 个已知的界面冒烟失败）
  • 0只有一种组成的运行改变的字节（G1 的 34 个文件；共用参数的 reaction 示例）

二、按组成的 Boltzmann 因子

原来

cli/run.py 对 energygeometry（没有 --multi_element）调用 data.get_bolt_factor(dft_center, 'boltzmann', 3000)：每个 EOS 组取中心结构的 DFT 每原子总能量 eg，wg = exp(−(eg − emin)/kBT) / Σh exp(−(eh − emin)/kBT)，emin 与求和取所有组。全电子总能量的每原子值主要由元素决定：B2N2 −1084.63、N3Na −2223.75、I4N16 −40510.75 eV/原子，而 kBT = 0.2585 eV，所以组成不同时只有能量最低的组成有权重（M5b-3 报告第九节）：

数据原来的因子现在
dft/nitrides.xyz（18 种组成，各一个组）I4N16 为 1，其余 17 种为 018 种都是 1
B2N2 + N3Na（examples/04 的 22 个结构）[0.0, 1.0][1.0, 1.0]
B2N2 + C3N4 + N3Na[0.0, 0.0, 1.0][1.0, 1.0, 1.0]
Cu 的六个相（dft/dft.xyz，一种组成）[0.0000446, 0.00174, 0.00796, 0.1266, 0.3998, 0.4639]逐位相同（两个数组的字节相同）
Cu 的六个相 + B2N2 + N3Na（顺序交错）—Cu 的六个与 Cu 单独时逐位相同，BN、N3Na 为 1

权重 < 0.1 的组既不进入损失（μE、μV 只对权重 ≥ 0.1 的组求和），DFTB 阶段也只算 Γ 点（utils.dftb_stage.kpoint_grid）。所以原来多组成的 energygeometry 运行实际上只拟合一种组成（每原子能量比最低者高出约 kBT ln 10 ≈ 0.6 eV 以上的组成，权重就低于 0.1），其余组成的结构照样计算（只算 Γ 点），对损失没有贡献；按元素拟合时，只出现在这些组成里的元素（演示中的 B）除了罚项之外没有任何数据约束。

现在

  • 组成：EOS 组中心结构的约化化学式（data.composition，ASE 的 get_chemical_formula(mode='hill', empirical=True)）：B2N2 → BN，K2N6 → KN3，I4N16 → IN4，Cu4 → Cu；N3Na、C3N4 不变。B2N2 与 B4N4 是同一种组成。取中心结构，因为因子本来就用它的能量；一个 EOS 组的结构组成相同（dft/nitrides.xyz 的 18 个组逐一核对过）。
  • 因子：每种组成 c 内 wg = exp(−(eg − emin,c)/kBT) / Σh∈c exp(−(eh − emin,c)/kBT)，就是这种组成单独作为数据集时的因子。实现上 get_bolt_factor 对每种组成的中心结构调用原来的公式（同样的运算、同样的顺序），再放回原来的位置；bolt_f11 仍是每组 11 份。只有一种组成时直接走原来的代码，所以单元素数据集（以及组成都相同的多元素数据集）的因子逐位不变。
  • “每种组成最稳定的相得 1”：一种组成只有一个 EOS 组时它得 1（dft/nitrides.xyz 的每种组成都是这样）；有几个组（几个相）时它们的和为 1，最稳定的相权重最大，与原来单元素时相同（Cu：fcc 0.4639）。要求单元素逐位不变，只能这样归一（第九节）。
  • 损失的公式不变：μV 是权重 ≥ 0.1 的组的 v0 误差按权重的加权平均，μE 是这些组各自的组内相对能量平均误差之和除以它们的权重之和。组成不止一种时现在每种组成都进入，分母约为组成数。'identical'（--multi_element，dataset/reaction）与 'uniform' 不变。

检查点

  • 多组成 energygeometry 运行的损失变了，原来写的检查点里的损失属于旧因子，与新损失混在一起会破坏 BO 的模型。Bayesian_optimization 写 checkpoint.pkl.meta.json 时，energygeometry、没有 --multi_element、组成不止一种的运行多写 "boltzmann": "per composition"（两种布局都写；按类型时加在 TypeModel.meta 之后）。
  • 续跑时 _check_checkpoint_meta 在原来的核对（损失版本、罚项半径或类型）之后核对这一项：本次运行应有而元数据没有（M5b-4 之前写的），或者元数据有而本次没有（例如改加了 --multi_element），都报错并说明“删除它或换一个 --checkpoint”。旧检查点不能换算：损失要重新计算。tools/rescale_checkpoint.py 换算出的检查点没有这一项，多组成时同样被拒绝。
  • 只有一种组成、--multi_element、dataset/reaction 的运行不写这一项，元数据与原来逐字节相同，原来的检查点照常续跑。

三、共用参数加全部元素的 --multi_element

原因

TypeModel.from_dataset 把 --multi_element 列出的元素作为拟合的元素，其余元素固定在 PTBP 的参数上。列出全部元素时没有固定的元素，--shared-parameters 又只有一个参数集，类型模型判为旧布局（legacy），运行走 M5b 之前的代码；那里 --multi_element 还是旧含义（“二元体系”：只优化第一个列出的元素）：

  • Loss.set_parameters 只给第一个列出的元素设 (r0,w, r0,d)，没有列出的元素（这里没有）取 PTBP 的半径，其余列出的元素没有半径（B、N、Na 时 Confinement_r0: {'B': […]}）；hotcent 写不出含 N、Na 的表。
  • 罚项半径、BO 边界取第一个列出的元素（B，1.587 Bohr，r0,w 上界 11.11 Bohr）；Boltzmann 因子用 'identical'；计划的代价模型因 KeyError 退回简单规则（第八节）。

基础提交上实测（B2N2 + N3Na，energygeometry，pydftb）：11 个点全部是失败点，每点都是 “no structure has DFTB results at these parameters (B2N2 x11, N3Na x11)”，损失 1000（还没有成功点时的固定值），元数据记下 failed_evaluations 0–10，最后停在 BO 结束时的作图错误；ptbp plan 照样给出 11 个点、约 14.9 min 的计划。

修正

  • TypeModel.from_dataset：shared 加上一个列出数据集全部元素的 multi_element（数据集有两个以上元素；顺序、重复不论）时 ValueError。cli/run.py 读入数据集后立即建类型模型（_type_model），把它变成 SystemExit("types: …")：在写 par.out、log.out 的表头、算因子、定计划和第一次 hotcent 之前（dataset/reaction 没有 --E0s 且没有缓存时，之前只有 E0 的最小二乘拟合）。实测（同一数据）：几秒内以退出码 1 停止，运行文件夹里只有 dft 链接与 ptbp_run.yaml（ptbp optimize 结束时总会写的设置记录）。ptbp plan 用同一个函数，打印 ptbp plan: … 并以 2 退出。
  • 消息（原文）：--shared-parameters cannot be combined with a --multi-element that lists every element of the dataset (B, N, Na): nothing would keep PTBP's parameters, and the code of one parameter set would give the radii to B only. Use --shared-parameters alone (one set for all elements), --multi-element alone (one set per listed element), or list only the elements to fit (with --shared-parameters they share one set, the others keep PTBP's published parameters)
  • --shared-parameters 的帮助（ptbp optimize 与旧的平铺命令行）和 YAML 的 shared_parameters 说明加了同样的一句。

不受影响的组合

  • --shared-parameters 加列出部分元素的 --multi_element：按类型的路径，列出的元素共用一组，其余固定在 PTBP 的参数上（M5b 起就能运行）。
  • 只有 --multi_element（列出全部元素也可以）：每个列出的元素一组；只有 --shared-parameters：所有元素一组。
  • 单元素数据集加 --shared-parameters --multi_element Cu：只有一个元素，第一个列出的就是全部，旧代码能正常运行（与只加 --multi_element Cu 相同），所以不拒绝（第九节）。

四、L-BFGS-B 结果的配对

原因

σrep 搜索先在 11 个格点上搜索并用 Nelder–Mead 打磨（brute），再从那里做 L-BFGS-B（ftol 1e-3，最多 20 次求值），返回 (res.x[0], res.fun)。SciPy 1.17.1 的 L-BFGS-B 驱动（scipy/optimize/_lbfgsb_py.py）中 x 是就地修改的数组，f 则是每次求值后重新绑定的 Python 数。线搜索失败（ABNORMAL：超过 20 个试探步，或线搜索报告舍入误差）时，setulb 把 x 退回上一个迭代点后结束，Python 一侧的 f 仍是最后一个试探点的损失，于是 res.x 与 res.fun 来自不同的求值。损失跳动时很容易发生：EOS 拟合在 σ 改变约 10−9 时换到另一个解，σ* 处的有限差分导数就有 109 量级，第一次线搜索的步长缩到 10−10 仍得不到足够的下降，于是失败，x 退回起点 σ*。

修正

  • 目标函数按 σ 的精确值（一个参数集：float(σ)；按类型：σ 向量的 tuple）记下每次求值的损失；minimize 之后，如果记录中 res.x 处的损失与 res.fun 不同，就用记录的损失，并打印一行（Search time 2: L-BFGS-B returned sigma_rep = […] with mu = …, the loss of another evaluation (scipy: ABNORMAL: …); the loss at this sigma_rep, …, is used）。相同（或 res.x 不在记录中）时返回 res.fun 本身：不出现不配对的运行逐位不变。
  • 一个参数集（Loss.Repulsion_optimization：energygeometry 的 parallel_repulsion、dataset/reaction 的 unparallel_repulsion）：把目标函数包一层，参数与选项不变；返回的 μ 进入 par.out、BO 与检查点。
  • 按类型（Loss.Repulsion_optimization_types）：n = 1 时同上；n > 1 时每一轮的联合 L-BFGS-B 只在损失低于当前点时被采纳，原来拿 res.fun 比较——试探点的损失可能略低于退回的点，于是当前点的损失被记成试探点的值，之后各轮的比较也受影响；现在用 μ(res.x) 比较与记录。
  • 没有改的：搜索过程中写的文件。一个参数集的路径每次求值都写 SKF、dftb_full.xyz 和（energygeometry）EOS 文件，EnergyGeometry 之后用 σ* 重写 SKF 与 dftb_full.xyz，EOS 文件（eos_*.traj、dft.json、dftb.json、几个 csv）却留着最后一次求值的（第八节）。梯度优化器的 refine_sigma 本来就在结果处重新计算损失，不受影响。

  • 多组成的 energygeometry 数据集每种组成都进入损失（按元素与 --shared-parameters 都是）：每种组成的因子与它单独拟合时相同，原来只有每原子总能量最低的组成有权重。这样的运行更贵：原来只算 Γ 点的组现在算完整的 k 点网格（演示：DFTB 阶段每步 1.2–1.3 s → 1.9 s，与约 30 s 的 hotcent 相比很小；整套 dft/nitrides.xyz 按 ptbp plan 估计每步 32.9 → 39.1 min）。用 --shared-parameters 拟合几种组成时，损失现在会显示一组参数对其他组成描述得多差（演示中损失大了约 4 倍）。标准输出按组成列出因子。
  • 这类运行在 M5b-4 之前写的检查点不能续跑（损失变了），报错说明删除它或换一个 --checkpoint；新写的元数据多一项 "boltzmann": "per composition"。只有一种组成的运行、--multi_element 与 dataset/reaction 的检查点照常续跑。
  • --shared-parameters 加列出全部元素的 --multi_element（命令行、YAML、界面都一样）在开始时报错，消息给出三种做法；原来这样的运行每个点都失败。ptbp plan 同样报错。
  • 每一步报告的损失是写进 SKF 的 σ* 处的损失：SciPy 的 L-BFGS-B 把 σ* 与另一次求值的损失一起返回时，打印一行说明并改用 μ(σ*)。在平滑的损失上看不到任何变化。
  • 只有一种组成的运行（所有单元素数据集）、dataset/reaction 的运行逐字节不变；命令行、YAML 的键、文件格式都没有变（多组成运行的检查点元数据多一项）。

八、发现的问题与偏差

  • --params sigma_rep 的路径在 dataset/reaction 模式下也用 Boltzmann 因子（原有，未改）：cli/run.py（本分支第 463 行）只按 --multi_element 选 'boltzmann' 或 'identical'，不看模式；主路径（r0 + σ）在 dataset/reaction 模式下用相同权重。那里因子只决定 k 点网格，现在按组成计算（第五节）。
  • 旧路径的 --multi_element 让计划的代价模型失败（原有，未改，只影响计划）：cli/run.py 把 opt_elem 换成原子序数后传给 _parallel_plan，utils.recommender.hotcent_tables 却按元素符号使用它，于是 [plan] cost model unavailable (KeyError: 29); simple rule（单元素 Cu 加 --multi_element Cu；B、N、Na 时 KeyError: 5），计划退回简单规则。
  • 一个参数集的路径中步的 EOS 文件属于最后一次 σ 求值（原有，未改）：parallel_repulsion 每次求值都写 EOS 文件（eos_*.traj、dft.json、dftb.json、volume.csv、B.csv、Bp.csv、delta.csv），EnergyGeometry 之后只用 σ* 重写 SKF 与 dftb_full.xyz。平滑时最后一次求值离 σ* 约 10−8，看不出差别；不配对时可能是另一个 EOS 解。按类型的路径（_write_typed_step）在 σ* 处写，没有这个问题。
  • SciPy 1.18 将去掉 L-BFGS-B 的 disp 选项：一个参数集的搜索传 'disp': True，现在每次得到 DeprecationWarning。
  • M5b-3 记下的那一次不能原样重现：那次的数据没有留下；第四节用同一类数据（盒子里的 CO、OH）重现了同样的机制，数值不同（不配对的差 2·10−8，那次是 73），合成的跳动损失重现了 74.9 那一种情形。
  • 不在本次范围、照旧的已知问题：单元素作图在多于 6 个 EOS 组时让运行停止；tools/skf_generator.py（不能运行的旧脚本）；physrep 的 raiseExceptions；bandstructure 的失败值 20；BO 结束时的作图错误（eval[0][0]，门槛与演示的所有 --optimizer bo 运行照旧停在那里）。
  • 与指示的偏差：
    • 工作树建在 main（2eb6bd6，第一个提交）上，开始时把本分支 git reset --hard 77a0e38（工作树是干净的，只动本分支）。
    • 按组成的计算放在 get_bolt_factor 的 "boltzmann" 选项里，而不是在 cli/run.py 另写一个：这样 ptbp plan、ptbp parity、tools/grad_check.py 与运行用同一组因子（副作用见上面第一条）。
    • 检查点元数据加了一项并在续跑时核对（指示要求“检查点”与新因子一致；旧损失不能换算）。
    • --shared-parameters 的帮助与 YAML 说明各加一句；拒绝只针对两个以上元素的数据集（第九节）。
    • 第三项的测试除了真实的 DFTB 数据，还加了不依赖 DFTB 的合成损失（覆盖两条路径、两种模式，以及按类型两个参数集时的比较）；真实数据的那一项在别的机器上没有触发时跳过，而不是失败。真实数据用 0.5、0.5 的权重：这组数据按组成的因子（1、1）不触发。
    • 测试分在三个文件（按主题），而不是一个新文件。

九、需要用户决定的事

  • 组成内的归一：现在每种组成的因子之和为 1（它单独作为数据集时的因子），所以“最稳定的相得 1”只在组成只有一个 EOS 组时成立；有几个相时（Cu）与原来一样归一。若要每种组成最稳定的相都是 1（不归一），单元素的结果也会变（Cu 的 fcc 由 0.4639 变 1，μE 的分母随之变化），与“单元素逐位不变”冲突，所以没有这样做。
  • 单元素数据集加 --shared-parameters --multi_element Cu：能正常运行（与只加 --multi_element Cu 相同），没有拒绝。要不要为了规则简单也拒绝？
  • 多组成 energygeometry 的旧检查点：现在拒绝续跑（不能换算）。也可以只警告后继续，但旧点的损失会混进 BO 的模型。
  • --params sigma_rep 的 dataset/reaction 模式（第八节）：要不要与主路径一致改用相同权重？会改变这条路径在多结构数据上的 k 点。
  • L-BFGS-B 的试探点可能更低：第四节第一行的线搜索试探点损失 1.8950513240 低于 μ(σ*) = 1.8950513447。按决定返回 σ* 与 μ(σ*)；改为返回所有求值中最低的一点也可以，但会改变没有不配对的运行（例如有限差分点更低时），所以没有做。
  • 一个参数集的路径中步的 EOS 文件属于最后一次求值（第八节），要不要在 σ* 处重写。
