关键信息

仓库现在是两个可安装的包：pydftb（运行只依赖 numpy、scipy、ase、threadpoolctl）和 ptbp（依赖 pydftb）。装好后有两个命令：pydftb advisor|refgen|dynamics|golden|gpu-check|gradcheck 与 ptbp parity。没有移动任何文件，旧的 python -m … 与脚本写法照旧可用，数值逐位不变。

  • 真实构建（第三节）：
    • pydftb 的轮子有 443 个文件（设计预期的 439 个，加上本阶段新增的 cli.py、__main__.py 与两个测试文件）和 licenses/LICENSE，没有 docs/、bench/；sdist 再构建出的轮子与直接构建的逐字节相同；
    • ptbp 0.3.0 的轮子有 65 个文件，其中没有 pydftb/。
  • 只装 pydftb 的干净环境（Python 3.11 与 3.13，PyPI 上的最新 numpy、scipy、ase）：PTBP 的模块导入不了；pydftb refgen --check 203 个算例通过，14 个（需要未安装的 D3/D4）跳过；在仓库外 pytest --pyargs pydftb.tests 674 个通过、256 个跳过。
  • 两个包、可编辑安装：同一个环境中 pip check 无问题，两个命令都可用；pip install -e ./pydftb -e . 后导入都指向仓库，git status 不变。
  • 门槛（第四节）：golden 对 5b90f55 逐位相同（conda 679 次计算，最小环境 637 次）；refgen --check 217 个单点、dynamics --check 24 个优化/MD 全部通过；pydftb 测试 conda 908 个、最小环境 675 个、最小环境 + torch 873 个通过（各比基线多出新测试）；PTBP 测试 227 个通过（7 个已知的界面冒烟测试失败，与之前相同）；G1 两种写法（python tools/engine_parity.py 与 ptbp parity）的损失都是 0.9198547924，1 核与自动核数逐位相同。
  • 443pydftb 轮子的文件（不含元数据）；ptbp 轮子 65 个
  • 674在只装 pydftb 的环境中通过的测试（3.11 与 3.13）
  • 6 + 1新命令：pydftb 的 6 个子命令与 ptbp parity
  • 0改变的位（golden 两个环境）

开发细节一、做了什么
位置内容
pydftb/pyproject.toml（新）项目 pydftb：package-dir = {"pydftb" = "."}，显式的 6 个包，include-package-data = false，测试数据 "pydftb.tests" = ["data/**/*"]；版本取 pydftb.__version__；依赖 numpy、scipy>=1.15、ase>=3.23、threadpoolctl；可选 torch、dispersion、test；命令 pydftb = "pydftb.cli:main"。没有 pytest 配置。
pydftb/LICENSE（新）根目录 LICENSE 的副本（license-files 写 .. 已弃用）。
pydftb/cli.py、pydftb/__main__.py（新）
  • 子命令 advisor、refgen、dynamics、golden、gpu-check（别名 gpu_check）、gradcheck：用到时才导入，参数原样交给 main(argv, prog="pydftb 子命令")，返回 int(rc or 0)；
  • 工具的 SystemExit 照常穿过；缺 torch 时一句话、退出码 2；
  • --help（无参数、help 同）列出子命令，pydftb help 子命令 等于 子命令 --help；--version；未知的子命令或选项由 argparse 报错（退出码 2）；
  • python -m pydftb 是同一个命令。
pydftb/validation/、pydftb/advisor/
  • refgen、dynamics、golden、gpu_check、gradcheck、advisor/__main__ 的 main 加关键字参数 prog=None（不传时与以前相同）；
  • golden.checkout_problem()：包的上一级目录必须是跟踪着 pydftb/__init__.py 的 git 检出的顶层，否则在 main 里打印原因，退出码 2；
  • 文档字符串改用新命令；refgen、dynamics、make_f_set、make_poly_set、advisor_cases 写明重新生成会写进包里的 tests/data，只在检出中做。
根目录 pyproject.tomlptbp 0.3.0；include = ["cli*", "utils*", "tools*"]，exclude 加 "pydftb*"；依赖加 pydftb>=0.1.0.dev0；torch = ["pydftb[torch]"]、dispersion = ["pydftb[dispersion]"]。其余不变。
cli/main.py、parameterize.pydispatch 一开始把 ptbp parity … 交给 tools.engine_parity.main(argv[1:], prog="ptbp parity")；只用于帮助的占位子命令让它出现在 ptbp --help 中；SUBCOMMANDS 与 NEW_SUBCOMMANDS 加 parity。
tools/engine_parity.pymain(argv=None, prog=None)；文档字符串改用 ptbp parity；sys.path.insert(0, 仓库) 只在作为脚本运行时执行（第五节）。
界面中的提示utils/recommender.py（两处）、cli/cmd_optimize.py、cli/tui/screens/optimize_step6_advanced.py 改为 pydftb gpu-check；tests/test_recommender.py 随之改。
测试
  • pydftb/tests/test_cli.py（新，13 个测试函数，参数化后 26 项）：帮助、版本、用法错误、每个工具的 main(argv, prog)、每个子命令的 --help 用法行、参数原样传递、None 的返回值、SystemExit、缺 torch、通过命令运行真实的 advisor、python -m pydftb；
  • pydftb/tests/test_packaging.py（新，2 项）：pyproject.toml 的包清单与目录树一致（安装的副本中跳过）；在新解释器中导入 pydftb 的每个模块（98 个，含测试），导入系统拒绝 utils、cli、tools、parameterize，不能有任何一次尝试；
  • pydftb/tests/test_api.py：_tmp_maxl 改用 tmp_path（以前写在包目录里）；
  • tests/test_cli_subcommands.py（3 项）：ptbp parity 原样传参、--help 是工具自己的、parameterize.main 的分派。
CI.github/workflows/pydftb-tests.yml：两个作业不变（torch 作业的 pip 缓存改看 pydftb/pyproject.toml）；新作业 wheel：python -m build pydftb，检查轮子（没有 docs/、bench/，测试数据与 git 跟踪的文件一一对应），装进干净的 venv，在临时目录运行 pydftb --help 与 pytest --pyargs pydftb.tests。
文档两个 README 的安装部分；现行文档（index.html、glossary.md、ROADMAP.md、WHY.md、dftbplus_map.md、RESEARCH.md）中的命令；带日期的设计与报告不改。

二、怎么用

pip install ./pydftb .                  # 在仓库根目录：两个包（可选依赖："./pydftb[torch,dispersion]"）
pip install -e ./pydftb -e .            # 开发：两个都可编辑
pip install ./pydftb                    # 只要引擎

pydftb --help                           # 子命令列表；pydftb 子命令 --help 是工具自己的选项
pydftb refgen --check                   # = python -m pydftb.validation.refgen --check
pydftb advisor RUN_DIR                  # = python -m pydftb.advisor RUN_DIR
pydftb gpu-check --device cpu --quick   # 需要 torch；没有 torch 时一句话提示，退出码 2
pydftb golden --base COMMIT             # 只在 git 检出中；安装的副本给出原因，退出码 2
python -m pytest --pyargs pydftb.tests  # 安装后在任意目录跑 pydftb 的测试

ptbp parity dft/dft.xyz --mode energygeometry --points 2.749,12.036 \
     --engines pydftb --compare-serial --workdir /tmp/parity   # = python tools/engine_parity.py …
  • 不安装也照旧：仓库根目录 PYTHONPATH=.，命令写成 python -m pydftb 子命令。
  • 只装 ptbp（不给 ./pydftb）时 pip 报 “No matching distribution found for pydftb>=0.1.0.dev0”：PyPI 上没有这个名字。
  • 重新生成参考（--regenerate、make_f_set、make_poly_set、advisor_cases）写进包里的 tests/data，只在检出中做。

三、构建与安装检查

构建都在 git ls-files -co --exclude-standard 导出的副本中做。venv 都是新建的，不用 --system-site-packages，依赖从 PyPI 安装；检查在仓库外的空目录中运行。

五、与设计的偏差

  • 轮子的文件数：443 而不是 439，多出的是本阶段新增的 cli.py、__main__.py、tests/test_cli.py、tests/test_packaging.py。
  • CI 的数据检查：不写死 344，而是比较轮子里的 pydftb/tests/data/ 与 git ls-files pydftb/tests/data（现在正好 344 个），以后增加参考数据不必改 CI。
  • engine_parity 的 sys.path：它在导入时把仓库根目录插到 sys.path 最前面；被 ptbp parity 导入时，在安装的副本中插进去的是 site-packages，会压过 PYTHONPATH。现在只在作为脚本运行时插入（python tools/engine_parity.py 照旧）；被导入时 tools 所在的目录本来就在 sys.path 上。tools/grad_check.py、bo_vs_grad.py 有自己的插入，不受影响。
  • G1 的 ptbp parity 写法在哪里跑：在 conda 环境中用它的 ptbp 命令加 PYTHONPATH=工作树（parameterize、cli、tools、pydftb 都来自工作树）。新建的 venv 里没有 hotcent 与 pylibxc（只在 conda-forge 上），跑不了 G1。
  • golden 的检查：除了 git rev-parse --show-toplevel 等于包的上一级目录，还要求 git 跟踪着 pydftb/__init__.py。
  • 门槛的计算次数：golden 是 679 与 637 次（不是 M6f-3 报告中的 639 与 600）：那次的基准是 89b24d4，M6f-3 的新计算不参与比较；这次的基准 5b90f55 已包含它们。
  • 多出的小功能：pydftb（不带参数）与 pydftb help 显示帮助，pydftb help 子命令 显示子命令的帮助，与 ptbp 的习惯一致。
