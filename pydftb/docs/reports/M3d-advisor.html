python -m pydftb.advisor 运行目录 读 DFTB+ 的输入、DFTB+ 实际用的输入（dftb_pin.hsd）、屏幕输出和 SKF，按 18 条规则列出问题，附上证据所在的文件和行号，并给出建议。PTBP 用 DFTB+ 时，每次运行自动检查第一个 DFTB+ 运行和每个失败的运行，结论打印出来并写进 advisor.json。顾问只读、只报告，运行结果与原来逐字节相同。

  • PTBP 自己的 DFTB+ 输入被查出 5 条：
    • ParserVersion = 1 让 DFTB+ 自动打开壳层分辨 SCC，并把 H、S 的差分步长定为 0.01 Bohr。这个步长下水、甲醇的力差 4–7e-3 eV/Å，默认步长只差 2e-7。
    • Fermi、MethfesselPaxton 两块写在 Filling 外面，被悄悄忽略，实际是 T = 0。
    • 栈只有 8 MB；周期体系用的是默认的 Ewald 容差。
    前两项标为“预期”：已发表的参数正是在这些设置下拟合的。
  • 18 条规则，每条都有出处（对照中踩过的坑、阶段报告或 DFTB+ 源码）。11 次冻结的 DFTB+ 25.1 运行（每条依赖屏幕输出的规则至少一个正例，外加一个干净的输入），每一次得出的结论都与预期完全一致；DFTB+ 报错退出的运行都被报告为错误。

三、PTBP 的历史输入

PTBP 经 ASE 写 DFTB+ 输入（utils/calculator.py），--smearing none（默认）时就是 PTBP 一直用的输入。ptbp optimize --engine dftbplus 第一个 BO 步里顾问打印：

[advisor] DFTB+ advisor: input …/dftb_tasks/s0033/dftb_in.hsd; ParserVersion 1; pin yes; screen output Cu2.out; …; 2 atoms (Cu), periodic
[advisor] [P01] warning old ParserVersion: DFTB+ rewrites the input  (dftb_in.hsd:46)
[advisor]     ParserVersion = 1: on the way to version 14, ShellResolvedSCC = Yes is added …;
[advisor]     Differentiation = FiniteDiff { Delta = 0.01 } is added …
[advisor]     expected here: PTBP's published parameters were fitted with this DFTB+ input …
[advisor] [P03] warning input ignored by the parser  (dftb_in.hsd:10-12)
[advisor]     Hamiltonian/DFTB/Fermi is not inside Filling and is ignored …; DFTB+ used Filling = Fermi with T = 0 Ha
[advisor] [P03] warning input ignored by the parser  (dftb_in.hsd:24-26)   (MethfesselPaxton)
[advisor] [E01] info    default Ewald tolerance
[advisor] [T04] info    stack size limit  (Cu2.out)
[advisor] 0 error(s), 3 warning(s), 2 info
发现意味着什么处理
壳层分辨 SCC（P01）每个壳层有自己的电荷和 U；Cu 的 4p（U = 0.08 Ha）让库仑求和到 96 Bohr（M3c）预期：pydftb 也按壳层分辨计算（M1 起）
0.01 Bohr 的差分步长（P01）H、S 的导数用 0.01 Bohr 中心差分：水、甲醇的力差 4–7e-3 eV/Å，强压缩的 Cu₂ 差 0.11 eV/Å（0.2%）；默认步长 1.22e-4 时 2e-7–9e-6 eV/Å预期：pydftb 默认复现这个步长（--pydftb-forces dftbplus），exact 时用精确导数
展宽被忽略，T = 0（P03）写的 2000 K 和 MP 二阶都没有生效预期；--smearing fermi 等写出正确的 Filling（M1）
默认 Ewald 容差（E01）周期能量约 1e-7 Ha 的精度，远小于拟合误差不用处理
栈 8 MB（T04）大体系可能随机崩溃，PTBP 的 1–2 原子晶胞没有问题不用处理

PTBP 的方案给每个 DFTB+ 运行 1 个 OpenMP 线程，所以 T01、T03 不会出现；Parallel { Groups = 1 } 在非 MPI 版本中被忽略也无害（T02 只在 Groups > 1 时报告）。

H01：DFTB+ 的 γ 闭式公式

用与 DFTB+ 相同的闭式公式，和 pydftb 的 Hermite–Genocchi 积分形式（误差 ≤ 4e-12）比较，r = 2–6 Bohr、U = 0.3 和 0.5 Ha 时一个原子对的 γ 误差：

|Ua − Ub|（Ha）5e-61e-53e-51e-43e-41e-3
γ 的误差（Ha）2–3e-31e-43–4e-62–5e-81–3e-90.3–2.4e-10

低于 3.125e-6 Ha 时 DFTB+ 当作相等，用精确的同 U 公式，没有问题。规则把 < 3e-5（误差 > 1e-6 Ha）定为 error，3e-5 到 3e-4 定为 warning；DFTB3 时 ∂γ/∂U 的误差大得多（M2b：1e-5 时相对误差 24），到 1e-3 都是 error。

五、PTBP 中的自动检查

  • cli/run.py 在 DFTB+ 引擎时调用 advisor_hook.configure；DFTB 阶段并行时保留第一个发出的任务目录，阶段结束后检查并删除；串行时（运行在 BO 步目录里）检查第一个结构的文件。每次运行只检查一次。
  • DFTB+ 运行失败（缺 SKF 以外的错误）时，检查它保留的目录，把报告附在异常上（add_note）。例：两个原子重合的结构，报告中 X01 给出 DFTB+ 的 “Atoms 2 and 1 too close together”。
  • 结论追加到运行目录的 advisor.json（每次检查一项，含“第一个 DFTB+ 运行”或“失败的 DFTB+ 运行”）。
  • 顾问开和关时，DFTB 阶段写出的 dft_final.xyz、dftb_band.xyz、search_index.txt 逐字节相同（1 核和 4 核，有测试）。读不了的 pin、乱码的屏幕输出、读不了的输入都不会让 PTBP 出错。

七、发现的问题与学到的东西

  • 一行写两个赋值，DFTB+ 报 “Superfluous data found”。MethfesselPaxton { Order = 2 Temperature [K] = 1000 } 中，HSD 把 Order 之后整行都当作它的值。块里的每个赋值要另起一行（或用 ;）。生成冻结样例时踩到，顾问的解析器照同样的规则读。
  • 不分壳层的 SCC 用 s 壳层的 U。parser.F90:readSKFiles 在 ShellResolvedSCC = No 时把所有壳层的 U 设为第一个（s）壳层的值。M3c 的成本模型原来按最小的 U 算截断，已改为与 DFTB+ 相同（PTBP 总是按壳层分辨，不受影响）。
  • DFTB+ 的 D4 中 s9 必须写（没有默认值），ChargeScale 默认 3、电荷模型默认 EEQ，所以周期体系不特意关掉时 D02、D03 都会出现。
  • 旧的 Driver = LBFGS 有步长上限（不开线搜索时 setMaxStep 默认开），新的 GeometryOptimisation 驱动里的 LBFGS 没有（M2f），G02 只查后者。
  • 屏幕输出的格式。转换时自动添加的节点在警告里没有行号；被忽略的节点按 “(n) / Path / Line” 列出；DFTB+ 报错退出时，ERROR! 之后还有 “ERROR STOP” 和浮点异常的提示。解析器按这些格式读，消息正文只取 “->” 开头和缩进的续行。
  • 线程数要从屏幕输出读。DFTB+ 在打印 “OpenMP threads” 之前报错退出时，线程数未知；顾问只在还没有屏幕输出（运行之前检查输入）时才按当前环境推断，否则不报告 T01、T03。

八、与计划的偏差

  • 规则从设计的 17 条变为 18 条：加了 X01，把 DFTB+ 的错误信息和它指出的输入行直接报告出来。PTBP 的失败报告主要靠它。
  • 设计中的 v2 候选（坑 10、13、14、15、31 和 TimingVerbosity 的提示）没有做。
  • 冻结样例的 SKF 只保留顾问读的几行（格式行、在位行、Spline 段），表格去掉，整个样例目录约 0.5 MB。
  • 加了 PTBP_ADVISOR=0 关闭自动检查。
  • 并行的 DFTB 阶段要多保留一个任务目录直到阶段结束；目录在检查后删除，结果文件不变。
