关键信息

PTBP 现在又是每个元素三个有效参数：r0_w、r0_d、σ_rep。hotcent 的原子计算默认改用自洽约束（hotcent 1.x 的做法，PTBP 最初就是按它写的），r0_d 重新进入 SKF。--confinement perturbative 保留旧行为，用来复现 M3、M4 的运行：G1 门槛下它与 M4 之前的提交逐字节相同。

  • 原因：hotcent 在 2023-02-05 把“微扰约束”改成了默认（2024-03-18 随 2.0.0 发布）。微扰约束下，只要每个价层都有波函数约束（PTBP 正是这样），密度就只由 r0_w 决定。PTBP 的 hotpy.py 最初按 hotcent 1.x 的接口写（hotcent.slako.SlaterKosterTable，2021-11 以前的接口），那时默认是自洽约束；同项目的 get_sto_coefficients.py 也显式写了 perturbative_confinement=False。后来改用 2.x 时只改了接口，没有处理这个默认值的变化。
  • r0_d 起作用了：Cu 的 r0_d 从 12.036 改到 13.0 Bohr，SK 表最大变化 0.011（微扰约束下为 0），energygeometry 损失从 0.920 变为 0.986。
  • 发表的 Cu 参数下更接近论文：energygeometry 损失从 1.899 降到 0.920（论文 0.288）。其中 μ_V 从 0.120 降到 0.0129，与论文的 0.0182 同一量级；μ_E 从 0.510 降到 0.293，仍比论文的 0.0775 大 3.8 倍。剩下的差距最可能来自 hotcent 在 2021-10-25 修正的二中心积分 GGA 错误（PTBP 最初用的版本还带着这个错误），这一部分不应恢复。
  • 两个引擎仍一致：新的 SKF 下，pydftb 与 DFTB+ 每个结构的能量差 ≤ 1.8e-9 eV。dataset 模式的损失相对差 7e-10；energygeometry 模式为 3e-6，来自 PTBP 内层 σ_rep 搜索的宽松收敛，不是引擎差异。
  • 默认结果改变（有意）：同一组参数的 SKF 变了，损失、BO 路径随之改变。dataset 模式在发表参数下的损失从 446.2 变为 837.8：发表参数不是用这个模式拟合的，这个数不与论文比较。
  • 代价：hotcent 多做几次原子自洽计算，一次 Cu 的 SKF 生成 47 → 50 s（单进程）。dataset 模式有一个 2 原子结构在 T = 0 下 SCC 从 7 轮变为 629 轮，DFTB 阶段（4 核）从约 10 s 变为约 30 s。
  • 3每个元素的有效参数
  • 1.899 → 0.920发表参数下的 energygeometry 损失（论文 0.288）
  • 0.120 → 0.0129其中的 μ_V（论文 0.0182）
  • 0--confinement perturbative 时与 M4 之前改变的字节

二、怎么用

ptbp optimize dft/dft.xyz --mode energygeometry                      # 默认：自洽约束，r0_d 起作用
ptbp optimize dft/dft.xyz --mode energygeometry --confinement perturbative   # M3、M4 时的行为
python tools/engine_parity.py dft/dft.xyz --mode energygeometry --points 2.749,12.036 \
    --engines pydftb dftbplus --confinement perturbative                     # 复现 M4 的数字

YAML 写 confinement: perturbative。运行开头打印 [hotcent] confinement selfconsistent，plan.json 里记下约束方式和 hotcent 版本。旧运行的检查点（skopt）是在微扰约束下得到的，续跑时要加 --confinement perturbative，否则同一参数点的损失不同。

三、原因：hotcent 的时间线

日期hotcent（/opt/hotcent 的 git 历史）与 PTBP 的关系
2019-12-261.0 发布；perturbative_confinement 默认 False（自洽约束）PTBP 的 hotpy.py 最初用 1.x 的接口 hotcent.slako.SlaterKosterTable
2021-10-25修正二中心积分中 GGA 交换关联梯度修正的错误（65c5f82）用旧接口时的 hotcent 还带着这个错误
2021-11-02SlaterKosterTable 改名为 offsite_twocenter.Offsite2cTablehotpy.py 后来改用新名字，旧 import 留在注释里
2023-02-05微扰约束成为默认（fe79493，开发版）hotpy.py 没有指定这个选项，从此 r0_d 不起作用
2024-02—PTBP 参数发布在 Zenodo
2024-03-182.0.0 发布（变更说明里写明了上面两项）—

同一项目的 utils/get_sto_coefficients.py 显式写了 perturbative_confinement=False，说明作者用的是自洽约束。发表的参数究竟是用哪个版本的 hotcent 生成的，从仓库里无法确定；但损失的对比（第四节）支持“自洽约束、且带着 2021 年以前的 GGA 错误”这一判断。

五、两个引擎的一致性

模式pydftbDFTB+相对差
energygeometry0.91985479240.91985205973.0e-6
dataset837.8367392837.83673866.9e-10

energygeometry 模式的 3e-6 不是引擎差异：66 个结构的能量差都 ≤ 1.8e-9 eV。差异来自 PTBP 内层的 σ_rep 搜索（L-BFGS-B，ftol 1e-3，M3b、M4c 已记录）：两个引擎选出的 σ_rep 分别为 0.40322096 和 0.40322213，μ 随之差 3e-6。微扰约束下损失面在这里更平，两个引擎碰巧一致到 1e-7。

六、代价与梯度

  • hotcent：自洽约束要为每个价层、再为密度各做一次完整的原子自洽计算。Cu 的一次 SKF 生成（参考实现，单进程）47 → 50 s（+6%）；一个 BO 步（4 核）中 hotcent 阶段 从约 5.0–5.1 s 变为 6.0–6.4 s：原子计算在主进程里串行，SK 表的行才分给各进程。
  • DFTB 阶段（dataset 模式）：第 15 个结构（2 原子，T = 0）的 SCC 从 7 轮变为 629 轮（20.7 s），另有两个结构变为 105 和 88 轮；其余结构不变（6–8 轮），没有不收敛的。4 核上 DFTB 阶段从约 10 s 变为约 30 s，成为一个 BO 步里最长的部分。成本模型（M3c）按轮数正常的情况估计，这时会低估；从第二步起任务按实测时间排序，影响有限。energygeometry 模式不受影响。
  • 梯度（M4c 的梯度优化器）：r0_d 现在改变 SKF，r0_d 的切向不再是零，要多做两次 hotcent（r0_d ± 0.2 Bohr）。一次“值 + 梯度”（4 核）：energygeometry 54 s（M4c 为 38 s），dataset 106 s（M4c 为 41 s，另有 SCC 轮数变多的影响）；其中切向部分 25–29 s。

梯度

M4c 的梯度原样可用：r0_d 的导数现在除了罚函数，还有能量和力的部分。tools/grad_check.py 在发表点比较梯度与差分（L3：σ_rep 固定在 σ*；L4：PTBP 的损失，σ_rep 重新搜索）：

datasetdμ*/dr0_d（h = 0.2）45.03845.0482.3e-4
energygeometrydμ*/dr0_w（h = 0.01）−1.45054−1.450437.8e-5

  • σ_rep 固定在 σ* 时（L3），dataset 模式一致到 4.9e-4（r0_w）和 1.2e-4（r0_d）；energygeometry 模式的中心差分一致到 4.5e-3 和 1.0e-3，但左右两侧的差分相差很大（例如 r0_w：−1.73 和 −0.92）。这是折点：σ* 恰好让一个结构的误差为零，固定 σ* 改变 r0 时这一项的绝对值在发表点有折角，梯度给出两侧斜率的平均。
  • energygeometry 模式沿 r0_w 用 h = 0.04 时，两侧差分也不一致（−1.87 和 −1.34），中心差分 −1.60 与 h = 0.04 的梯度 −1.55 差 3%：损失在这个尺度上弯曲很大（M4c 在微扰约束下也是这样）。h = 0.01 时一致到 8e-5。

八、与设计的偏差

  • utils/get_sto_coefficients.py 不用改：它本来就显式写了 perturbative_confinement=False（这也是第三节的证据之一）。
  • par.out、log.out 的格式不变，设置只记在运行开头的打印和 plan.json 里：下游脚本按列读取这两个文件。
  • 没有重新标定成本模型：自洽约束只让 hotcent 多 6%；dataset 模式变慢来自 SCC 轮数，成本模型本来就不预测轮数。
  • 三个工具（engine_parity、grad_check、bo_vs_grad）也加了 --confinement，用来复现之前的结果。
