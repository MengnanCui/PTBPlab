关键信息

M8b 精简版训练集（142 个结构）在电光云 dg83 上全部算完、全部收敛，实际扣费 7.98 元（预算 33 元）。拿这份数据拟合 M8a 的自适应模型：只拟合能量的最好，训练集 39.6 meV/atom，测试集的团簇 65、理想相 43 meV/atom，力的误差 0.3–0.4 eV/Å（团簇、体相），二聚体与重构的 Cu13 仍有 2–3 eV/Å。把力加进拟合（权重 0.01）反而更差：30 次评估里只走了 13 步，停在 228 meV/atom。M8a 在 6 个理想相上的 1.4 meV/atom 在这份更难的数据上变成了几十 meV/atom，说明这套模型（ptbp_hcocu 的 Cu–Cu 表加 CN 的修正）对短程与低配位描述不够。只拟合能量的模型在 Cu13 的 600 K MD 中 2 ps 全程稳定（总能量漂移 0.10 meV/ps，团簇完整），是 M8 里第一个 MD 稳定的自适应模型。

  • 只拟合能量（自适应，34 个参数，23 次评估）：训练 39.6 meV/atom；测试：团簇 65、理想相 43、应变 12、二聚体 57、MD 帧 168 meV/atom。
  • 能量加力（力权重 0.01，13 个原子以内的结构带力）：训练 228 meV/atom，力 2.5 eV/Å；没有收敛。

一、电光云上的计算

用户批准在电光云上算精简版（不含扰动晶胞和表面），预算上限 33 元。设置与 M8b 设计相同：PBE PAW，ENCUT 450 eV，300 K 的 Fermi 展宽（自由能），周期体系 KSPACING 0.2，团簇与二聚体只用 Γ 点并自旋极化。

  • 预算控制：校准后按实测重估为约 14 元（加每个作业 60 s 的开销约 20 元），分阶段提交。每一阶段都设了墙钟上限，保证即使全部跑满时间，累计也低于 33 元；每阶段结束后用 sacct 统计实际核时。
  • 估计偏差：粗估按原子数的 2.2 次方放大，周期体系高估 30–40 倍（β-Sn 4.6 → 0.11 核时，空位 58.7 → 1.9 核时）；Cu13 低估约 3 倍（自旋极化、SCF 步数多）。
  • dg50：没有用。按实际费率（GPU 4.5 元/卡时，CPU 不收费），一张卡加 76 核跑 CPU 版 VASP 每小时 4.5 元，比 dg83 的 76 核（5.7 元）便宜约 20%；19 核的小作业仍然是 dg83 便宜（1.4 元）。这批作业里只有 8 个 76 核的和 Cu13 能省，最多省约 1–1.5 元。以后大体系的 CPU 作业可以放到 dg50。
  • 免费的替代：Materials Project 的 MPtrj 与 Meta 的 OMat24（CC-BY 4.0）有 Cu 的 PBE 数据，但设置不同（如 ENCUT 520），要对齐能量零点；国家超算中心有试用机时。这次没有用。

三、拟合

python -m pydftb.bench.cu_dft_fit cu_m8b.extxyz。每组每 5 个结构留 1 个做测试：116 个训练，26 个测试。一个公共能量偏移。

  • 裸表：ptbp_hcocu 的 Cu–Cu 表在第一壳层以内没有排斥。在 1.7–1.9 Å 的二聚体和重构的 Cu13 上，DFTB 比 DFT 低 4–6 eV/atom，其他组差 0.1–0.4 eV/atom。

五、主动学习：第二轮候选

python -m pydftb.bench.active_cu fit_energy.json md_adaptive.extxyz --data cu_m8b.extxyz --members 3 --member-evaluations 15 --perturb 0.02 --group round2 --write …：委员会围绕只拟合能量的模型，在它的训练集（116 个结构）上重抽样，只拟合能量；筛的是能量加力模型那段 1.5 ps 的轨迹（149 帧，最短键到 1.6 Å，最后一个原子飞出），正好是这类模型会走到的地方。

  • 锚点：排斥势的多项式系数（高次项的 Jacobian 列模到 2.7e4）即使扰动 0.0025 也让短二聚体的 SCC 不收敛，所以加了 perturb_skip=("pair",)。其余系数扰动 0.02（on-site 0.54 eV）仍有团簇不收敛，成员 0 减半到 0.01 才成功。
  • 成员：训练误差 140、17.9、26.5 meV/atom（基础模型 39.6）。成员 0 从扰动的锚点出发，15 次评估没有回到基础模型附近；成员 1、2 比基础模型还低，说明基础拟合也没有完全收敛。
  • 筛选：149 帧中 72 帧至少一个成员 SCC 不收敛（已加了更慢的混合重试），训练集上也有不收敛的，所以训练集的 σ 是 nan。收敛的帧上 σ 随重构上升：0 fs 是 10.9 meV/atom、0.91 eV/Å，200 fs 是 16.8、1.56，500 fs 是 101、10.2。
  • 挑出的帧：不收敛的帧分数是无穷大，10 帧都是这类帧，按指纹去重后落在 100–560 fs（最短键 1.68–2.20 Å）。写在 /Users/mncui/Documents/PProjects/pydftb/cu_dft_m8b_active/round2，按 Cu13 的实测约 20 核时、约 1.5 元，没有提交。（已被第五节续第 5 小节的新候选替换，旧的移到 round2_prev_fit_energy。）
  • 结论：这一轮委员会没有标定好：成员在训练集上都不全收敛，σ 只能当“出界”的信号，不能排序。要先解决 SCC 在扰动参数下的稳定性（按通道设锚点尺度、更强的混合），再做下一轮。

2. 从二聚体曲线拟合有第一壳层排斥的 Cu 排斥势

python -m pydftb.bench.cu_dimer_repulsive cu_m8b.extxyz OUT：Vrep(r) = EDFT(r) − Eel(r) − C，Eel 是表的电子自由能（不含排斥势），截断 3.5 Å，写成 ptbp_hcocu 副本里 Cu–Cu.skf 的 Spline。表在 /Users/mncui/Documents/PProjects/pydftb/cu_dft_m8b_lite_results/fits/skf_dimerrep。

  • 原来的表在短程塌缩：ptbp_hcocu 有排斥势样条，但只到 2.63 Å 且太弱；Cu2 在 1.7 Å 比 3.5 Å 低 34 eV，在 1.4 Å 低 55 eV（DFT：高 1.2 eV）。需要的排斥在 0.4 Å 内升了 35 eV（1.7 Å：35.7 eV，1.9 Å：10.2，2.1 Å：0.49），比单个指数还陡，6 项多项式的对排斥势拟合二聚体时在 2.0 Å 出现假的鼓包、1.5 Å 以下又塌缩。
  • 新表的二聚体与 DFT 一致（1.7 Å：+1.20 eV，1.9 Å：−0.86 eV，相对 3.5 Å），1.4 Å 以下强排斥。裸表的误差：二聚体 5640 → 671、MD 帧 4102 → 2349 meV/atom，但应变 256 → 760、理想相 427 → 568：只从二聚体来的排斥势在 2.5 Å 附近约 0.26 eV，fcc 每个原子 6 个键，体相约高 1.5 eV/atom。这是二聚体排斥势已知的毛病。
  • 在它上面只拟合能量（100 次评估）：训练 22.8 meV/atom（原来 39.6），二聚体的力 2.53 → 0.80、团簇 0.43 → 0.31 eV/Å；但测试集里压得最紧的 bcc（bcc_00）低了 879 meV/atom；其余 12 个理想相里 7 个比原来好，均方根 31.4（原来 38.5）meV/atom。CN 相关的排斥势标度在高 CN 时把排斥压低来抵消体相的多算，外推到最高 CN、最短键时就过度结合。MD 中一个原子飞出。
  • 结论：只从二聚体来的排斥势不能直接当底。要么把体相（与团簇）一起拿来拟合排斥势，要么限制 CN 标度的外推（例如在数据的 CN 范围外取常数）。

  • 训练集好很多，测试集多数更差：训练误差从 44.9 降到 17.2 meV/atom，团簇测试 61 → 28；但二聚体、MD 帧、理想相的测试都变差。bcc_00 从 −879 收到 −229 meV/atom（截断 CN 起了作用，但没消掉），bcc_10 仍是 +87。这是过拟合：没有力的约束，34 个参数加上 B 样条的排斥势在训练点之间可以随意弯。
  • MD 失败的原因是假的短程势阱：拟合后的 Cu2 曲线在 1.8 Å 有 −1.31 eV 的极小，比 2.2 Å 的真极小（−0.98 eV）还深（原表的模型：1.8 Å 处 +0.23 eV）。排斥势样条本身也不单调（2.3–3.3 Å 之间有 0.05–0.25 eV 的起伏，1.6 Å 处 69 eV）。团簇打开、有原子 CN 降到 1–2 以后，原子对掉进这个阱，再撞上 1.6 Å 附近极陡的墙。力与有限差分一致到 2.6e-7 eV/Å；步长 0.5 fs 时同样在 1.78 ps 后失守（范围 932 meV），所以不是积分步长的问题，是势本身。
  • 结论：在这份数据上，联合排斥势加截断 CN 没有超过“原表 + 力权重 0.001”。能用的模型仍是 fit_f001。要让联合排斥势可用，至少需要：把力（对 V′ 也是线性的）放进排斥势的线性拟合；限制样条单调（非负的一阶差分约束）；短程只用二聚体定值；之后再做力权重 0.001 的精修。

5. 围绕 jfm 模型重做第二轮筛选

同一段 149 帧的轨迹（能量加力模型的 1.5 ps），委员会围绕上一小节最好的模型。先按第五节的设置（锚点扰动 0.02，3 个成员 × 15 次评估）跑：在 jfm 模型上这个扰动把成员 0 的起点推到 5053 meV/atom，二聚体、Cu55、空位的 SCC 反复不收敛，3 小时只到第 5 次评估（机器上还有别的拟合，负载约 21），停掉。改成纯 bootstrap 委员会：active_cu fit_jfm_f001.json md_adaptive.extxyz --data cu_m8b.extxyz --members 3 --member-evaluations 8 --perturb 0 --processes 4，每个成员从 jfm 的极小出发，在重抽样的训练集上只拟合能量。34 分钟。顺带修了 active_cu：原来总用 ptbp_hcocu 的表，现在用拟合 JSON 里的 skf。

  • SCC 不收敛的问题没有了：149 帧全部收敛（原来 72 帧失败），训练集上也全部收敛，训练集的 σE 是 11.7 meV/atom（原来 nan）。成员训练误差 11.6、18.3、14.6 meV/atom（72–78 个不同结构）。

  • 挑出的 10 帧全部不同：1130、1230、1260、1310、1320、1350、1360、1390、1400、1410 fs（原来 100–560 fs）。原来的帧是因为 SCC 不收敛分数无穷大才被挑中；现在按 σ 排序，挑的是最压缩、最出界的帧，正是 fit_energy 加力模型 MD 失败的那段。新输入替换了 cu_dft_m8b_active/round2，旧的在 round2_prev_fit_energy。

六、工程问题

  • 电光云：
    • 每个用户最多 10 个排队作业，数组的每个任务都算一个，115 个的数组被拒。改成 run_chunk.sh：一个作业顺序算一段结构。
    • mpirun 读走了循环的标准输入，每个作业只算了一个结构；加 < /dev/null。
    • 一个扰动的 Cu13 自旋极化 SCF 来回振荡，到 NELM = 200 也没收敛。加 AMIX 0.2、BMIX 1e-4、AMIX_MAG 0.8、BMIX_MAG 1e-4 与 NCORE 4 后 18 步收敛；Cu38、Cu55 同样设置，20–34 步收敛。collect.py 现在拒绝没算完或到 NELM 的结果。
  • 拟合（pydftb.adaptive_fit）：
    • 试探步上某个 SCC 不收敛时，不再中断整个拟合：这一步记为代价极大，信赖域缩小。先只算能量判断收敛，再算力的 Jacobian，失败的试探步便宜约 2nx 倍。
    • 初始信赖域很大：x_scale="jac" 下 Jacobian 的列模从 1.8（d 跃迁）到 2.7e4（排斥势的高次项），开始要被拒 6–8 次。之后可以给定 x_scale。
    • macOS 上 fork 出来的子进程在 Accelerate 的 LAPACK（dsygvd → dispatch_apply）里段错误：父进程用过多线程的 Accelerate（线性起点的 lstsq）以后，GCD 在子进程里不能用。multiprocessing.Pool 遇到死掉的工作进程会永远等下去，看起来像死锁。改用 ProcessPoolExecutor（工作进程死掉时报错），并用 VECLIB_MAXIMUM_THREADS=1 运行。
  • SCC 的混合：扰动的与重构的 Cu13 上，Broyden 在默认混合下 300 步不收敛，混合 0.05、1000 步就收敛（结果与混合方式无关）。evaluate_sample 现在在不收敛时用这个设置重试一次；显式给了 mixing 时不重试。拟合里被拒的试探步、委员会的锚点失败，有不少是这个原因。
  • 测试：新增“SCC 失败的试探步被拒绝，起点失败仍报错”与“不收敛时用更慢的混合重试，显式 mixing 时不重试”；另有 RBF.clamp 的测试；test_adaptive.py 与 test_active.py 共 27 个全部通过。pydftb.calculator 没有改动，golden 不受影响。
