关键信息

两边都有的功能现在都能用 pydftb 或 DFTB+ 计算，只换一个参数：Python 里是 make_calculator(skdir, engine="pydftb"|"dftbplus", **options)，命令行是 pydftb run --engine pydftb|dftbplus。选项就是 PyDFTB 的名字、单位与默认值。新的 ASE 计算器 DFTBPlus 用写出全部冻结参考的那套块写 DFTB+ 的输入，运行 DFTB+，把结果换成与 PyDFTB 相同的字段。新命令 pydftb dual 用 517 个冻结单点与 34 个动力学参考逐个核对了输入、实跑的输出、两个引擎之间的差，以及 ASE 驱动的优化与 MD，全部在算例的容差内。PTBP 自己的 --engine 没有动，旧的 pydftb 路径逐位不变。

  • 一个开关：两个引擎用同一组选项。只有一个引擎有的选项放在 pydftb={...} 或 dftbplus={...} 里（选项文件里是同名的两节），所以换引擎时选项不用改。放错地方的选项报 EngineOptionError，说明原因和该放的那一节。DFTB+ 引擎拒绝只有 pydftb 才有的功能：类型切换、torch 后端与 float32、FOE 与子体系求解器、溶剂化的模型对象、CM5 的自定义参数、repulsive="none"；XL-BOMD 只在 DFTB+ 自己的 MD 驱动里。k_threads 只影响 pydftb 的速度，DFTB+ 引擎接受并忽略。
  • 输入（V1，不需要 dftb+）：588 个冻结输入，DFTB+ 读到的内容与新引擎写出的全部相同。其中 517 个单点（511 个逐字节相同，6 个只差末位，是固定费米能级与归一化 k 点权重的一次换算），13 个能带运行，24 个二阶导数运行，34 个 DFTB+ 自己驱动的优化与 MD。几何文件逐字节相同。这项核对也是一个 pytest 测试。
  • DFTB+ 引擎实跑（V3）：517 个算例全部跑通，502 个解析出的输出与冻结参考逐位相同。其余 15 个分两类：上面那 6 个输入差末位的算例，差 ≤ 4.0e-11（cu4co_pol_fixef 每轮 SCC 误差的记录；电荷 ≤ 1.9e-13）；9 个 ELSI 版 NTPoly 的算例，电荷差到 4.4e-13，这是 DFTB+ 自己每次运行就不同（坑 209）。
  • 两个引擎互相比较（V4）：同一个算例、同一组选项，PyDFTB 对 DFTBPlus，517 个全部在算例的容差内。
    • 能量差的中位数是 7.5e-15 Ha，504 个 < 1e-9 Ha。最大是 2.2e-7 Ha（water_box_dftb3，那个冻结算例用 DFTB+ 自己的 Ewald 容差 1e-9），占容差的 22%。
    • 离容差最近的两项都是 69%：一是力（h2o_nonscc），因为 DFTB+ 用差分求 H0、S 的导数；二是非共线 CAM 的磁矩。
  • pydftb 经统一选项（V2）：make_calculator(engine="pydftb") 对 refgen 直接调 DFTB 的路径，517 个里 501 个逐位相同。其余 16 个差 ≤ 1.1e-12，来自单位换算的末位；能量差 ≤ 3.6e-14 Ha。
  • 优化与 MD（V5）：34 个动力学参考全部在容差内。
    • 26 个用 ASE 的 BFGS 与速度 Verlet 驱动 DFTB+ 引擎，每步沿用上一步的 charges.bin：优化 ΔE ≤ 5.0e-11 Ha、Δr ≤ 2.1e-6 Å；MD ΔE ≤ 5.7e-8 Ha、Δr ≤ 6.8e-8 Å。
    • 7 个 XL-BOMD 与 1 个非共线的杂化泛函用 DFTB+ 自己的驱动，结果与冻结参考逐位相同。
  • 核对中找到并修好的：
    • DFTB+ 会改写它读进来的 charges.bin。第一版沿用电荷时因此每隔一步丢掉电荷（坑 207），自旋 LC 的 CH3 的 MD 走到了另一个自旋态。
    • SelectedShells 时，自定义的参考占据要按 DFTB+ 的壳名对上，否则 5 个算例的中性布居差 1 e。
    • 第一轮门槛发现一处回归：溶剂化收了规格字典之后，不完整的字典从模型的构造函数里抛出 TypeError，2 个原有测试要的是带说明的 ValueError。现在缺参数、模型名不对、有未知的键时，两个引擎都给出同样的 ValueError。
    • 溶剂化规格里 DFTB+ 的输入写不出的部分（SASA 的半径、DFTB+ 之外的 CM5），原来 DFTB+ 引擎会悄悄忽略，两个引擎于是算的不是同一个模型。现在 DFTB+ 引擎拒绝它们，并说明怎样写才两边相同（坑 50：DFTB+ 的 CM5 每对原子算两次）。
    • 另记下 DFTB+ 输出的三处坑（坑 204–206）。
  • 时间（P136）：
    • 每次调用 DFTB+ 有约 20 ms 的固定开销。
    • 508 个算例，每个算例的中位数：DFTB+ 引擎 78 ms，pydftb 42 ms。
    • 水的 MD：经 ASE 调用 41 次 DFTB+ 共 2.0 s，DFTB+ 自己的驱动 0.3 s。
  • 588 / 588DFTB+ 输入与冻结的相同（V1）
  • 517 / 517两个引擎之差在算例的容差内（V4）
  • 34 / 34优化与 MD 在动力学的容差内（V5）
  • ≈ 20 ms每次调用 DFTB+ 的固定开销（P136）

开发细节一、做了什么
位置内容
dftbplus_calc.py（新）
  • DFTBPlus：ASE 计算器，implemented_properties 与 PyDFTB 相同，engine = "dftbplus"。选项的默认值从 PyDFTB.__init__ 的签名取（OPTION_DEFAULTS），引擎自己的选项见 DFTBPLUS_DEFAULTS：binary、ewald_tolerance（1e-12；None 用 DFTB+ 的 1e-9）、convergent_scc_only、regions、workdir、keep_files、extra_hamiltonian、extra_analysis、extra_options、extra_top。
  • 输入：write_input(atoms, skdir, options, properties) 给出 Input，内含 HSD、geo.gen、要写进目录的文件与 k 点。HSD 由 validation/dftbplus.py 的块拼成；单位用 pydftb 自己的换算（_fermi_au、_hybrid_au、_truncation_au 等）；k 点由 kpoints_of 给出，与 PyDFTB 用的相同（周期的杂化泛函写 SupercellFolding）。.skf.gz 解压到缓存目录一次，写临时文件再 os.replace。
  • 运行与取值：run_input 按 threads 设 OMP_NUM_THREADS 运行 DFTB+，用 parse_run 读输出，每次都把 DFTB+ 改写过的 charges.bin 读回来（坑 207）。非零退出时抛出 CalculationFailed，带 DFTB+ 的错误信息。result_of 把输出换成 DFTBResult，energies 只在 results.tag 的值与 detailed.out 在 1e-9 内一致时取全精度值（坑 204、205）。布居 = 中性原子的布居 − DFTB+ 的电荷：neutral_populations 用 ParamSet 的占据，自定义的参考占据按 DFTB+ 的壳名对上（skf.shell_names）。
  • 第二次运行：band_input、states(kpts, regions, atoms) 与 band_structure 读 SCC 的 charges.bin，MaxSCCIterations = 1，不打印力；hessian_input 与 second_derivatives 用 SecondDerivatives 驱动，Born 电荷取 reshape(-1, 3, 3).transpose(0, 2, 1)。
  • DFTB+ 自己的驱动：relax（GeometryOptimisation，可带晶胞与各向同性）与 md（VelocityVerlet，可带 Xlbomd 与 ForceEvaluation），一次运行走完整条轨迹。
  • 其他：write_charges；masses(labels, atoms) 取 SK 文件的质量，与 PyDFTB 相同；get_eigenvalues、get_fermi_level(s)、get_ibz_k_points 等 ASE 的取值方法。
engines.py（新）make_calculator(skdir, engine, pydftb=None, dftbplus=None, **options)；OPTIONS 列出每个选项在两个引擎上的支持与说明，由两张默认值表生成；check_options 对未知的名字抛 TypeError，对放错节的抛 EngineOptionError，并指出该放哪一节；engine_name（dftb+、dftb 是 dftbplus 的别名）。common_results(calc, atoms, properties) 给出两个引擎都有的结果，ASE 单位，平铺成能写进 JSON 的字典，并先算最费的属性，所以只算一次；compare_results 给出两份结果之间的最大差。
run.py（新）与 cli.pypydftb run：6 个任务（第二节），选项文件与 --set，--json 的字段两个引擎相同。cli.py 加了 run 与 dual 两个命令。
validation/dual.py（新）case_options 把冻结算例翻译成引擎中立的选项；hsd_diff 按 DFTB+ 的读法比较两份 HSD：块内的子节点不论次序（同名的按次序），数字相对差 ≤ 1e-12，SK 文件按文件名比较。V1–V5 的四个开关：--inputs、--pydftb、--live、--drivers；另有 --workers、--json。
validation/dftbplus.pyparse_run() 从 run() 里拆出来，代码不变，另记 total_tag；strip_initial_spins() 由 run_restart 与引擎共用；说明里加了一段。
ase_calc.py
  • kpoints_of()：k 点规格 → 点与权重，由 PyDFTB._kpoints 与 DFTB+ 引擎共用，多了 {"klines": ...}。
  • 新写法：electric_field 收 {"strength", "direction"}；solver 收 NTPoly 的字典；solvation 收规格字典。
  • 方法：states(..., regions=None) 给出 PDOS 区域的权重；新的 second_derivatives(atoms, delta, derivative_atoms, moved_atoms, dipole, polarisability)；masses(labels, atoms)；engine = "pydftb"。
  • 旧写法的结果逐位不变（测试与 golden）。
bands.py、solvation.py、solvers.py、validation/cases.pyStates.region_weights（新的公有字段）；solvation_from_spec（从 cases.solvation_model 搬来，原处改为调用它；模型名不对、缺参数、有未知的键时给出 ValueError）；solver_from_spec。DFTB+ 引擎的 _solvation 先做同样的检查，参数文件写成绝对路径，再拒绝 DFTB+ 的输入写不出的半径与 CM5 参数。
测试tests/test_dual_engine.py（新，63 项，其中 6 项要 dftb+），tests/test_response.py 多了一项（完整的溶剂化规格走到响应的拒绝）；存下的 4 组 DFTB+ 输出 tests/data/dftbplus_outputs/（84 KB，路径换成 <SKDIR>/）。见第五节。

二、怎么用

from pydftb.engines import make_calculator, common_results
for engine in ("pydftb", "dftbplus"):
    calc = make_calculator("skf/", engine, kpts=(4, 4, 4), smearing=("fermi", 300.0),
                           dftbplus={"binary": "/opt/dftb+/bin/dftb+"})
    print(engine, common_results(calc, atoms)["energy"])       # eV，两个引擎的字段相同
pydftb run cu.cif --skdir skf/ --engine dftbplus --kpts 6 6 6 --temperature 1000 --json cu.json
pydftb run h2o.xyz --skdir skf/ --task relax --fmax 0.01 --output h2o_opt.xyz
pydftb run h2o.xyz --skdir skf/ --engine dftbplus --task md --steps 200 --native
pydftb run cu.cif --skdir skf/ --task bands --path GXWLGK --options opts.json
pydftb run cu.cif --skdir skf/ --kpts 6 6 6 --task dos --regions regions.json
pydftb run h2o.xyz --skdir skf/ --task hessian --project
pydftb dual --inputs                     # 588 个冻结输入，不需要 dftb+
  • 选项：PyDFTB 的名字与单位（长度 Å，能量 eV，电场 V/Å，温度 K；模型参数用原子单位）。pydftb.engines.OPTIONS 列出每个选项在哪个引擎上可用。
    • --options 是 JSON 文件：共同的选项在顶层，一个引擎自己的放在 "pydftb" 或 "dftbplus" 一节，例如 {"scc_tol": 1e-8, "pydftb": {"k_threads": 4}, "dftbplus": {"binary": "..."}}。
    • --set KEY=VALUE 加一个选项，值按 JSON 读，读不成的当字符串；pydftb.KEY、dftbplus.KEY 放进对应的一节。
    • 常用的有自己的参数：--kpts、--temperature（电子温度，Fermi）、--scc-tol、--charge、--threads、--binary。
  • 任务：
    • energy：能量、力，周期体系还有应力（--no-stress 不算），以及电荷、偶极、磁矩、本征值等。
    • relax：ASE 的 BFGS、FIRE 或 LBFGS（--optimizer）；--cell 连晶胞一起优化（FrechetCellFilter），--isotropic 只均匀缩放；--output 写出最终结构。
    • md：速度 Verlet，初速度按 --md-temperature（默认 300 K）与 --seed 取 Maxwell-Boltzmann 分布，再去掉平动（分子还去掉转动）；--output 写出轨迹，结果里有总能量的漂移。
    • bands：沿 --path 的能带，默认取 ASE 给这个晶胞的路径。
    • dos：态密度，展宽 --width（eV）；--regions 是 PDOS 区域的 JSON 文件，写法与 DFTB+ 的 ProjectStates 相同（label、从 0 起的 atoms、shell_resolved、orbital_resolved）。
    • hessian：二阶导数（步长 --delta，Bohr）与简正模式，--project 去掉平动与转动。没给 SCC 容差时用 1e-10：力的差分会把 SCC 的误差放大约 104 倍。
  • 沿用电荷：两个引擎上的 relax 与 md 都沿用上一步的电荷。DFTB+ 引擎写回上一次的 charges.bin，加 ReadInitialCharges，与 DFTB+ 自己的驱动一样，每步的 SCC 轮数也相同（V5）。
  • --native（只有 DFTB+ 引擎）：用 DFTB+ 自己的 GeometryOptimisation 或 VelocityVerlet，一次运行走完。XL-BOMD 与非共线的杂化泛函总是这样跑：前者是 DFTB+ MD 驱动的选项，后者 DFTB+ 不写电荷文件（坑 208）。
  • 输出：屏幕上是摘要；--json 写出引擎、任务、用到的选项、pydftb 的版本、DFTB+ 的版本与运行次数、耗时和结果，两个引擎的字段相同。选项放错时以 2 退出，并打印 EngineOptionError 的说明。
  • 两个引擎不同的地方：
    • DFTB+ 用差分求 H0、S 的导数，步长 2−13 Bohr；pydftb 默认用解析导数，fd_delta=2**-13 时也照 DFTB+ 差分。在 SK 网格节点附近，两者的力差到 1e-6 Ha/Bohr，有限差分的 Hessian 差得更多（坑 210）。
    • SCC 不收敛时 DFTB+ 停下，抛出 CalculationFailed（dftbplus={"convergent_scc_only": False} 时照常算下去）；pydftb 只给警告。
    • DFTB+ 拒绝的组合（例如 k 点上的杂化泛函不给力）原样作为 CalculationFailed 抛出；杂化泛函时 DFTB+ 引擎不给应力（PropertyNotImplementedError）。
    • 溶剂化：两个引擎都收规格字典，pydftb 另收模型对象。DFTB+ 的 GB 里的 CM5 把每对原子算两次（坑 50），所以要两边相同就写 "cm5": {"double_count": True}；别的 CM5 参数与 SASA 的半径，DFTB+ 引擎拒绝。

三、核对（V1–V5）

每个冻结算例由 case_options 翻译成引擎中立的选项，再交给 make_calculator。DFTB+ 用的版本与冻结参考相同：大多数是 conda 的 25.1（自称 development version (commit: a23bfb2)），18 个用开发版（041e723），10 个用带 ELSI 的 24.1。下面的数是门槛里的那一次（--workers 2）。

V3 pydftb dual --live：DFTB+ 引擎实跑每个算例，输出用冻结参考的同一个解析器读，逐项比较。517 个全部跑通，502 个逐位相同，SCC 轮数 517 个都相同。

  • 没有输出的分析：DFTB+ 拒绝的坐标导数，冻结的运行里本来就是空的，算作相同。

  • 磁矩：非共线 CAM 的 O2（两个自旋从 90° 开始，最后平行）差 6.9e-3。没有自旋轨道耦合时任何方向都是解，最后的方向取决于 SCC 走的路径，而两个代码的路径不同：DFTB+ 混合后的布居只取每对原子自旋块的左下块。所以这个算例的冻结参考对 pydftb 的容差本来就是 1e-2。

V5 pydftb dual --drivers：34 个动力学参考，与冻结的 DFTB+ 自己驱动的结果比较，容差用动力学的（优化：能量 1e-9 Ha、坐标 1e-4 Å；MD 见各算例）。

六、与设计的偏差

  • V2 没有改 refgen：设计写“refgen 的 compare 接受外部给的运行，再对冻结参考比较”。实现改为与 refgen 自己的 run_pydftb 逐位比较：后者已由 refgen --check 对照冻结参考，逐位相同就足够，validation/refgen.py 没有改。
  • --cross 并进了 --live：两个引擎在同一个工作进程里先后算同一个算例，DFTB+ 只跑一遍。
  • V5 只驱动 DFTB+ 引擎：设计写“ASE 驱动两个引擎”。pydftb 经 ASE 的优化与 MD 已由 pydftb dynamics --check 对同一批冻结参考核对（门槛之一），所以 --drivers 只跑 DFTB+ 引擎。除 XL-BOMD 外，非共线的杂化泛函也用 DFTB+ 自己的驱动（坑 208）。
  • 选项名：设计的 directory 改叫 workdir，因为 ASE 的 Calculator 已有 directory。
  • pydftb run 的参数：
    • --temperature 只是电子温度；MD 的初始温度另用 --md-temperature。
    • 多了 --optimizer、--isotropic、--no-stress、--npoints、--width、--regions、--delta、--project、--output。
    • --steps 的默认值：优化 1000，MD 100。
    • hessian 任务没给 SCC 容差时用 1e-10（HESSIAN_SCC_TOL）。
  • 新参数 polarisability：两个引擎的 second_derivatives 都有。DFTB+ 只在这时把分析换成 Polarisability，冻结的 24 个 SecondDerivatives 输入里也有这种情形。
  • 能带运行写 PrintForces = No：冻结的能带运行打印了用不到的力，V1 对这一项放行。
  • 分析里 CM5 的自定义参数（analysis={"cm5": {...}}）：没有对照 DFTB+ 验证过，DFTB+ 引擎只收 cm5=True。
  • golden 加 --allow-new region_weights：bands.States 多了一个公有字段，旧字段逐位相同。
  • 核对中改的两处：每次运行后都读回 charges.bin（坑 207），以及按 DFTB+ 的壳名对上自定义的参考占据。都在实现阶段由 V3、V5 发现，修好之后才跑门槛。
  • 第一轮门槛之后改的：三个环境的 pytest 各有同样 2 个原有测试失败（test_response.py::test_refused 的溶剂化一项、test_solvation.py::test_ase_and_errors）：不完整的溶剂化字典从构造函数里抛出 TypeError，测试要的是 ValueError。solvation_from_spec 加了检查；DFTB+ 引擎用同一个检查，并拒绝它写不出的部分（坑 50 的 CM5 与 SASA 的半径），相对的参数文件改写成绝对路径（DFTB+ 在自己的目录里运行）。新测试 test_solvation_spec_errors，test_refused 多一项完整的规格。之后全部门槛重跑一遍，第五节的数是第二轮的（PTBP 测试是其后单独重跑的那一次，见第五节）；第一轮其余各项的结果与第二轮相同。
  • 其余按设计：统一的选项与新增的写法、DFTB+ 引擎的输入与第二次运行、取值规则、common_results、pydftb run 的六个任务、V1、V3 的比较规则。
