关键信息

pydftb 现在能做两分量计算：非共线自旋（每个原子的磁矩是一个三维向量），以及自旋轨道耦合（SOC），DFTB+ 的 onsite 和 dual 两种模型都有。它们可以与 DFTB3、壳层分辨 SCC、k 点、力、应力、能带与 DOS 一起用。16 个新的 DFTB+ 参考算例全部通过，SCC 轮数逐个与 DFTB+ 相同。新功能只在 NumPy 引擎中；旧的计算路径逐位不变。

  • 与 DFTB+ 一致：
    • 能量差 ≤ 4.9e-11 Ha，Espin、ELS 等各项同样；
    • 力差 ≤ 1.7e-8 Ha/Bohr，这是 DFTB+ 自己用数值差分求导的误差，与旧算例相同；
    • 应力差 ≤ 2.0e-10 Ha/Bohr³；
    • 磁矩向量、每个壳层的自旋和轨道角动量差 ≤ 7.6e-9，在 DFTB+ 输出的 8 位小数之内；
    • 能带本征值差 4.3e-14 Ha；
    • SCC 轮数全部相同，最长的 GdO 加 f 壳层 SOC 为 166 轮。
  • 自洽检查：
    • dual 模型通过重叠矩阵作用到相邻原子，力中多出一项（ξ = 0.05 Ha 时 OH 上为 9e-4 Ha/Bohr）。加上这一项后，力与能量的差分一致到 4–6e-9，应力到 2e-11。
    • 没有 SOC 时，把磁矩整体转一个角度，能量、力、应力都不变。这在周期体系上也检查了，而 DFTB+ 在同一体系上自己的 SCC 不收敛。
  • DFTB+ 的三点行为（第五节）：
    • SCC 可能发散：磁矩的方向是 SCC 的“软”方向。周期体系里磁矩不沿坐标轴时，或 SOC 太弱（ξ 小）时，DFTB+ 的 Broyden 混合会发散。pydftb 用同一个混合器，表现相同；改用 Pulay 混合器（mixer="pulay"）这些情形都收敛了。
    • 约化的 k 点网格：有 SOC 时直接给 DFTB+ 约化过的 k 点网格，它照算不误。能量、力、应力碰巧仍然正确，磁矩却错了（应为 0，算出的长度达 0.023）。pydftb 遇到这种网格直接报错。
    • 投影文件格式：两分量计算的投影态文件每行 5 列（q、mx、my、mz），而不是 2 列。对照工具已相应修改。
  • 代价：两分量的矩阵边长加倍且为复数，大矩阵的本征分解约贵 37 倍。108 个 Cu 原子单线程时，pydftb 要 209 s，DFTB+ 要 142 s。参考算例这样的小体系上，pydftb 用时为单线程 DFTB+ 的 0.2–1.2 倍（第六节）。
  • 16新的 DFTB+ 参考算例，全部通过
  • 166 / 166最长的 SCC：GdO + f 壳层 SOC（pydftb / DFTB+）
  • ≤ 4.9e-11与 DFTB+ 的能量差（Ha）
  • 0旧计算路径改变的位

二、怎么用

import pydftb
mf = pydftb.SCC(system, params, temperature=300,
                spin="noncolinear",                       # 非共线自旋
                initial_spins=[[0, 0, 1], [0, 0, 0]],     # 每个原子一个初始磁矩向量
                spin_constants={"O": -0.028, "H": -0.072},
                spin_orbit={"O": [0.0, 0.0004]},          # 每个壳层一个 ξ（Hartree），s 壳层为 0
                mixer="pulay")                            # SOC 很弱时用 Pulay 混合（第五节）
mf.kernel()
mf.result.magmoms          # (N, 3) 磁矩向量
mf.result.e_ls             # 自旋轨道能
mf.result.orbital_moments  # 每个壳层的 <L>，(n_shell, 3)
  • 只要 SOC、不要自旋极化：只给 spin_orbit。重元素体系的能带最常这样算。
  • onsite 模型：spin_orbit_dual=False。默认是 dual，与 DFTB+ 相同。
  • k 点：
    • 有 SOC 时 k 点集合必须对 k → −k 封闭，否则报错。
    • pydftb.SCC(..., kpts=(n1, n2, n3)) 和 PyDFTB 对两分量计算自动用完整网格。
  • ASE：PyDFTB(..., spin="noncolinear") 没有给 initial_spins 时，读取 atoms.set_initial_magnetic_moments 设置的 (N, 3) 向量；给的是 (N,) 时当作沿 z。
  • 能带与 DOS：mf.states(kpts=路径)，每个 k 点 2N 个能级，每个能级最多 1 个电子。
  • 不支持：backend="torch"、pydftb.autodiff、solver="sp2"，遇到时报错。

五、DFTB+ 的行为

1. 磁矩的方向是 SCC 的软方向

  • 没有 SOC 时，把所有磁矩一起转动不改变能量。SCC 的残差在这个方向上的导数为零，Broyden 混合器在这个方向上的步长趋于无穷，数值噪声就被放大。
  • 周期体系：CuO 链（k 点 4×2×2）的磁矩只要不沿坐标轴，在 500、1000、2000 K 以及混合参数 0.05 下都发散或停滞。磁矩沿 z 时，x、y 分量严格为零，这个方向不会被激发，26 轮收敛。
  • SOC 太弱：SOC 让能量依赖磁矩方向，但很弱时仍压不住。OH 自由基（300 K，磁矩沿 z 开始）中，ξO,p = 0.0004 Ha 时 DFTB+ 与 pydftb 都发散；0.002 和 0.01 时收敛（22、17 轮），两者能量一致。
  • 分子（O₂、OH、GdO）中倾斜的磁矩可以收敛，参考算例就用这些。
  • 办法：pydftb 的 Pulay 混合器（mixer="pulay"）在 ξ = 0.0004 时 36 轮收敛（混合参数 0.05 时 173 轮）。pydftb 的默认混合器仍与 DFTB+ 相同，保证 SCC 轮数一致；README 和本报告建议在磁矩方向自由、各向异性弱时改用 Pulay。

2. SOC 与约化的 k 点网格

有 SOC 时 H(−k) ≠ H(k)*，k 和 −k 不能合并。DFTB+ 的 SupercellFolding 会自动用完整网格，但直接写在 KPointsAndWeights 里的约化网格照用不误。CuO 链只加 SOC 时，约化网格算出的能量、力、应力与完整网格完全相同：时间反演对称下，密度的实部恰好仍然正确。磁矩却算错了：每个原子的磁矩长度在 0.008–0.023 之间，应为 0。pydftb 遇到不含 −k 的集合直接报错。

3. 输出格式

  • 两分量的投影态文件每行 5 列：能量、q、mx、my、mz。旧的读取代码取最后两列，会把 mz 当作权重，已改为取 q 列。Kramers 简并对的 m 分量互为相反数，具体数值取决于简并子空间里任意选取的基，不能逐个能级对照。
  • 角动量只出现在 detailed.out 中，保留 8 位小数，打印的是磁矩：轨道部分为 −⟨L⟩，自旋部分为 −(g/4) m。

六、速度

pydftb 在 conda 环境（MKL）中运行。DFTB+ 25.1 用单线程，时间包含进程启动和读写文件。

体系k 点pydftbDFTB+
OH + SOC（oh_noncolinear_soc，20 轮）Γ0.018 s0.046 s
Cu₄CO + SOC（cu4co_soc，16 轮）Γ0.10 s0.23 s
GdO + f 壳层 SOC（gdo_noncolinear_soc，166 轮）Γ0.39 s0.33 s
CuO 链 + SOC（cuo_chain_soc_k422，17 轮）160.24 s0.49 s
108 个 Cu 原子（N = 972），1000 K，无 SOC，单线程Γ4.9 s（14 轮）5.5 s（14 轮）
同上，加 SOC（2N = 1944），单线程Γ209 s（19 轮）142 s（19 轮）
  • 小体系：参考算例这样的小体系上，pydftb 用时为 DFTB+ 的 0.2–1.2 倍，主要省在进程启动和文件读写上。
  • 大体系：两分量计算的时间几乎全在本征分解上。108 个 Cu 原子单线程时，每轮本征分解从 0.29 s 增加到 10.7 s（37 倍）；理论上，边长加倍的复数矩阵是实数矩阵的 32 倍。这时 pydftb 比 DFTB+ 慢 1.5 倍。
  • solver="batched" 在这里反而更慢（262 s）：它先把问题化为标准形式，每轮多两次 2N 的复数矩阵乘法。
  • 两分量计算还不能用 GPU（只有 NumPy 引擎）。

八、与设计的偏差

  • 至少两轮的规则只用于两分量计算。DFTB+ 对共线自旋同样要求至少两轮。pydftb 的共线路径过去没有这条规则，但第一轮的输入是猜测的电荷，从来不会收敛，所以结果不受影响；为保持旧路径逐位不变，没有改它。
  • 投影的读取：设计中没有预料到 DFTB+ 两分量投影文件的格式，parse_levels 改为按列数取 q 列。旧的区域文件只有 2 列，结果不变。
  • golden 的新计算：基准提交没有新算例，golden 原来会把“只在工作树中的计算”算作差异。现在只计数、不比较；只在基准中出现的计算仍算作差异。
  • 新增建议：设计时没有想到 SOC 太弱也会让 SCC 发散（第五节第 1 条），README 中加了用 Pulay 混合器的建议。

九、下一步

  • M6b：DFTB+U 与 onsite 修正。复用 M6a 的块布居（spinorbit.block_populations）；混合向量要加入块布居（DFTB+ 的 reduceCharges）；DFTB+U 与 SOC 同用时要求 dual 模型。
  • （可选）大体系两分量计算的速度：时间几乎全在 2N 复数矩阵的本征分解上，pydftb 比 DFTB+ 慢 1.5 倍（第六节）。可以试其他 LAPACK 驱动，或用 torch 后端放到 GPU 上（需要先把两分量路径移植到 torch）。
