关键信息

M7a 的 NTPoly 纯化用稠密矩阵：内存 O(N²)，每次乘法 O(N³)。M7c 让这条路径在稀疏矩阵上走完。H0 与 S 直接按邻居表组装成 CSR 矩阵。S−1/2、H̃、纯化、P 与 W 都是带 NTPoly 逐元素截断的稀疏乘法。Mulliken 布居、能量、力与应力只用 H/S 图样上的密度矩阵元。这对应 DFTB+ 的 Solver = NTPoly { Sparse = Yes }，也是 DFTB+ 的默认。有带隙的体系在截断 1e-6 时，正交基里的密度矩阵 X 每行约 250 个非零元，不随体系增大，所以每次乘法的耗时与 N 成正比。

  • 格式（P108）：
    • 选 SciPy 的 CSR 加逐元素截断，与 NTPoly 的语义相同。
    • X·X 一次乘法，截断 1e-6：1000 个水分子时，单线程 CSR 已比 4 线程稠密快（0.85 s 对 1.94 s）；1728 个时 1.44 s 对 9.90 s。CSR 的耗时与 N 成正比。
    • 自写的空间单元块（块内稠密）在 Python 里不比 CSR 快。
    • SciPy 的 CSR 乘法会释放 GIL，按行分块用线程：3 个线程快 2.6 倍（P108c）。
    • 两个因子的填充都超过 10% 时改用稠密 GEMM，这是 NTPoly 的 sparsity_threshold。
  • 局域性（P107）：
    • 水在截断 1e-6 时，X 每行约 153 个原子块，从 216 到 1000 个分子不变。
    • Cu 金属（1000 K、3000 K）在 18 Å 的超胞里 X 完全不稀疏。
    • 所以线性标度只对有带隙的体系有效。有限温度的 FOE 不做稀疏版：P109 的估计是每次递归的乘法约为 TRS4 的 11 倍，而需要 T > 0 的金属本来就不稀疏。
  • 精度（P111）：216 个水分子的 SCC 加力，对本征分解：
    • 截断 1e-6：能量 3.4e-7 Ha（每个原子 5e-10），电荷 4.7e-7 e，力 3.2e-7 Ha/Bohr；
    • 1e-7：5e-9 Ha、1.2e-8 e、1.3e-8 Ha/Bohr；
    • 1e-8：1e-10 Ha、6.6e-9 e、3.2e-9 Ha/Bohr；
    • SCC 轮数与本征分解相同；截断 1e-5 时 SCC 不收敛。
  • 与稠密版一致（P109）：
    • 同一份算法代码，数组函数按类型分派；截断 1e-6 时稀疏与稠密的 P 差 2e-12。
    • 差别只在 TRS4 的最后一步。σ = (n/2 − tr F)/tr G 中的 tr G 到了舍入噪声时，σ 没有意义，求和次序不同就会走另一个分支（216 个水、截断 1e-10：σ 为 15.4 对 −0.75）。
    • 这时两者在 NTPoly 的容差带里不同（Tolerance 1e-5 时能量差 4e-6 Ha）。DFTB+ 自己也是这样：非 SCC 的能量与 RelativelyRobust 差 3e-10–4.8e-6 Ha（P110）。
  • DFTB+ 对照（P110，DFTB+ 24.1 + NTPoly 2.7.1，单进程）：
    • 默认截断 1e-10：216、512 个水分子比 RelativelyRobust 慢 5.7 倍与 6.6 倍。
    • 截断 1e-6：512 个时 13.5 s，RR 10.0 s；1000 个时 36.2 s，RR 76.3 s，快 2.1 倍。
  • ≈ 250水的 X 每行非零元（截断 1e-6），不随 N 变
  • 6.9×1728 个水分子：单线程 CSR 对 4 线程稠密的乘法
  • 3.2e-7截断 1e-6 时力的误差（Ha/Bohr）
  • ≈ 44一次密度的稀疏乘法次数（S−1/2、H̃、TRS4、P）

一、范围

  • 做：
    • NTPoly(sparse=True)：整个 SCC 在稀疏矩阵上，四种纯化（PM、TRS2、TRS4、HPCP）与 M7a 相同；
    • 分子、周期体系的 Γ 点（实数），k 点（复数 CSR，DFTB+ 同样有 getDensityCmplxSparse）；
    • 无自旋与共线自旋（每个通道单独纯化，同 M7a；DFTB+ 的 NTPoly 拒绝自旋）；
    • 力与应力；
    • 只改变电势或能量项的功能：DFTB3（含 H 阻尼、H5）、色散、外场、点电荷、位点电势、溶剂（分子）、卤素与偶极修正、自定义 Hubbard 与参考占据、混合器、初始电荷与电荷文件；
    • ASE 的计算器与 MD。
  • 不做（报错并说明原因，稠密的 NTPoly() 照样可用）：
    • 两分量（非共线、SOC）：DFTB+ 同样拒绝稀疏输入（原话 “Sparse solver not currently avaible for two component complex hamiltonians”）。
    • 块势（+U、onsite）：DFTB+ 可以。pydftb 的稀疏路径暂不做。块布居要 ρS 的原子对角块，力要块势的 dS 系数，都要改写成图样上的运算。块势不改变 H 的图样，以后能加。
    • 杂化泛函、Casida、响应、要本征矢的分析：同 M7a。其余的分析输出（原子能量、CM5、ESP 等）在稀疏路径上也暂不做。
    • XL-BOMD 的力（force_evaluation）与 xl 步：它们要稠密的 ρ 与 H。
    • 有限温度的 FOE 稀疏版（P109，见关键信息）。
    • torch 后端：稀疏只用 NumPy 与 SciPy。
    • precision="mixed"：float32 的 CSR 乘法不更快（P108c：0.41 s 对 0.43 s），稀疏乘法受的是索引而非浮点运算的限制。
  • 照旧：Coulomb 的 γ 矩阵（原子数 × 原子数）仍是稠密的。DFTB+ 的 invRMat 同样是 nAtom × nAtom。周期体系的 Ewald 在建立时是 O(Nat² NG)，P111 量出它的份额（第二节）。

三、数据结构与截断

  • 矩阵：scipy.sparse.csr_matrix，实数（分子、Γ 点）或复数（k 点）。下标排好序。
  • 截断：NTPoly 的 PruneList 在乘积里保留 |a| > τ；pydftb 稠密路径的 _drop 把 |a| < τ 置零。两者只在恰好相等的元素上不同。稀疏路径用 _drop 的规则，所以与稠密路径一致。截断只在 NTPoly 截断的地方做：每次乘法之后，加法不截断。
  • 乘法 _mm(A, B, τ)：
    • min(A 的填充, B 的填充) > 0.1 时转成稠密数组做 GEMM（多线程 BLAS），再截断，转回 CSR。这是 NTPoly GemmMatrix 的规则，小体系因此不比 M7a 慢。
    • 否则用 SciPy 的 CSR 乘法：A 按行分成 4·t 块，t 是线程数，在线程池里各乘 B，再 vstack；最后截断，去掉显式的零。
  • 其余的运算：
    • 加减与数乘：CSR 的运算。
    • 迹：对角元之和。
    • tr(AHB)：A.conj().multiply(B).sum() 的实部。
    • Gershgorin 界、列绝对值和、单位阵、共轭转置：在 CSR 上实现。
  • 图样：
    • 由邻居表的原子块（含 onsite 块）构成，周期体系的像在 Γ 点折叠到同一个 (μ, ν) 上。DFTB+ 的 elsicsc 也是这样把它的压缩格式变成 CSC。
    • 记下：每个邻居对的矩阵元在图样里的位置 elem，它的转置位置 elem_t，对角元的位置，每个图样元素的行号与列号。
    • H0、S、H 与输出的 ρ、W 都是图样上的数值数组（每个 k 或自旋通道一行）。这就是 DFTB+ 的压缩格式。

四、算法

  • 不变：M7a 的 S−1/2（耦合 Newton–Schulz，Taylor 五阶）、四种纯化、化学势的二分、P = g Z†XZ、W = PHP/g，都是同一份代码。purification.py 的数组函数（_mm、_drop、_eye、_ct、_trace、_dot、_abs_column_sums、gershgorin、_equal）加一个 CSR 分支，与已有的 torch 分支并列。
  • P 与 W 在图样上：先算出完整的乘积（同 NTPoly），再在图样位置上取值（m[rows, cols]，SciPy 的 csr_sample_values）。ELSI 也是把 NTPoly 的矩阵映回输入的 CSC 图样。ρ 与 W 的其余元素用不到。
  • TRS4 最后一步的分支：
    • σ = (ne/2 − tr F)/tr G，G = X²(1 − X)²。X 接近幂等时，tr G 很小，分子却是两个约 ne/2 大小的数相减，舍入约为 neε 乘上点积的长度。
    • tr G 落到这个噪声以下时，σ 的符号与大小都由舍入决定：σ > 6 走 2X − X²，σ < 0 走 X²。NTPoly 只在 |tr G| < 1e-14 时退出，这个界不随 n 变。
    • 走错分支的一步会把一半本征值离 0 或 1 的距离放大一倍，然后能量判据（|ΔE| ≤ Tolerance）就停了。结果在容差带里变动。
    • 稀疏与稠密的点积求和次序不同，所以在这一步可能分开。DFTB+ 自己的结果也一样含有这个噪声（P110）。这是 NTPoly 的算法性质，不改，以保持与 DFTB+ 相同的步数；文档与测试按此处理（第八节）。
  • k 点：每个 k 一个复数的 CSR 矩阵，图样相同，数值是 ΣT M(T) e2πik·T。迹与 tr(AHB) 取实部，转置换成共轭转置（同 M7a）。

五、计算器的稀疏路径

步骤稠密（现在）稀疏（M7c）
建立fold 把邻居对的元素累加成 N × N 的 H0、S（每个 k 一个）图样与 elem；每个 k 的 H0、S 数值用 bincount 累加到图样上，k 点乘相位。不建稠密矩阵。
SCC 的 HH = H0 + ½ S ∘ (vμ + vν)，净位点电势加在对角上同一个公式作用在图样的数值上：v 按图样的行号与列号取值。
求解稠密的 ρ、WCSR 进，CSR 出，在图样上取值，得到 (通道数, nnz) 的数组。
MullikenΣk wk Re(ρkSk)μμ，einsumqμ = Σk wk Re Σν ρk,μν conj(Sk,μν)，按行 bincount（S 是厄米的）。
能量Tr(ρH0)Σk wk Re Σ ρ conj(H0)，在图样上求和。
净布居ρ 的对角元图样里对角元的位置。
力与应力在邻居对元素上收集 ρνμ 与 Wνμ（k 点先按平移 T 求实空间矩阵）pe = Re Σk wk ρk[elem_t] e2πik·T，W 相同；之后的 dH、dS 系数与位力不变。
Coulomb、排斥、色散不变（γ 是原子数 × 原子数，与 DFTB+ 相同）。

内存：H0、S、H、ρ、W 都是 O(nnz)；求解器里的 Z、H̃、X 与乘积是截断后的 CSR；γ 是 Nat²。1728 个水分子（5184 个原子）时 γ 为 215 MB，截断 1e-7 的 X 约 60 MB，而一个稠密的 N × N 矩阵是 860 MB。

六、pydftb 的接口

from pydftb.purification import NTPoly
DFTB(sk, solver=NTPoly(sparse=True))                       # DFTB+ 的 Sparse = Yes：TRS4，1e-5，1e-10
DFTB(sk, solver=NTPoly(sparse=True, truncation=1e-6))      # 大体系：力的误差约 3e-7 Ha/Bohr
DFTB(sk, solver=NTPoly("trs2", sparse=True, threads=2))    # 稀疏乘法用 2 个线程
  • sparse：默认 False，也就是 M7a 的稠密路径，结果逐位不变。DFTB+ 的默认是 Sparse = Yes，但两者结果相同（在第四节的容差带之内），稀疏只对大体系更快。
  • threads：稀疏乘法的线程数，默认是本进程可用的全部核。稠密的 GEMM 用 BLAS 自己的线程。
  • 结果与 M7a 相同：没有本征值与占据数，费米能级是 NTPoly 的化学势。solver.last_iterations、solver.isr_iterations 照旧，另加 solver.last_fill：最后一次密度里 X 每行的平均非零元数。
  • PyDFTB(solver=NTPoly(sparse=True)) 同样可用；求解器对象在各步之间共用。
  • 拒绝：见第一节“不做”。原话指向稠密的 NTPoly() 或本征分解。

七、实现 开发细节

csr.py（新；M0 的原型 sparse.py 不动）
  • CSR 的运算：截断、带稠密分支与线程面板的乘法、迹、点积、Gershgorin、列绝对值和、单位阵、共轭转置；当前的线程数用 contextvars 传给乘法，不改变各函数的参数。
  • Pattern：由邻居对与轨道数建立；fold(values, phases) 给出图样上的数值，matrix(data) 给出共用下标的 CSR，sample(m) 在图样上取值，row_sum 与 pair_values 供布居与力使用。
purification.py数组函数加 CSR 分支；NTPoly(sparse=False, threads=None)；prepare 与 density 接受 CSR 的列表并返回 CSR 的列表；last_fill。稠密路径的代码不动，逐位不变。
calculator.py
  • _check_sparse：第一节的拒绝。
  • _setup：稀疏时建图样与 H0、S 的数值（st.sparse），st.h0、st.smat 为 None，误用会立刻报错。
  • _scc：在图样上组装 H；_solve_density 取值到图样。
  • _mulliken、_trace、_net_populations、_pair_densities：稀疏分支。
validationrefgen 的 --sparse：M7a 的 NTPoly 参考算例改用 sparse=True，块势的 2 个算例打印原因跳过；--sparse-branch 让所有乘法走 CSR（填充阈值设为 1），在小体系上也测到稀疏乘法。
tests/test_sparse.py（新）见第八节。

八、验证 开发细节

  • DFTB+ 参考：M7a 的 9 个 NTPoly 参考算例中的 7 个（块势的 2 个不适用）用 sparse=True 过 M7a 的容差（能量、电荷、力 1e-9，SCC 轮数相同），也在 --sparse-branch 下过。这些是小体系，TRS4 最后一步的 σ 没有落到噪声里。
  • 对稠密的 NTPoly：分子、周期 Γ 点、k 点、两种共线自旋、四种方法，加外场、点电荷、色散、DFTB3：能量、电荷、力、应力与 SCC 轮数相同，差到舍入（≤ 1e-10）。用小体系与收紧的 Tolerance，避开第四节的噪声。
  • 对本征分解：截断 0、Tolerance 1e-10 的 TRS2（M7a 的收紧设置）在稀疏路径上等于本征分解（≤ 1e-10）。
  • 大体系（报告，不进单元测试）：水 216–1728 个分子的 SCC 加力，截断 1e-6 与 1e-7，对本征分解的误差应与 P111 一致；耗时与内存随 N 的增长，对 eigh、稠密 NTPoly 与 DFTB+ 的 NTPoly。
  • 单元测试：CSR 运算对稠密（截断规则、稠密分支与线程面板逐位相同）；图样的折叠、取值、布居、能量对稠密；拒绝的原文；ASE 计算器。
  • 门槛：golden 两个环境逐位相同，refgen（NumPy、torch），dynamics，pytest 三个环境，PTBP 测试与 G1。

九、风险与之后

  • 速度：SciPy 的 CSR 乘法每个线程约 5e8 次乘加/秒，比 NTPoly 的 Fortran 慢。线程面板能补回 2–3 倍。交叉点（快过本征分解）按 P108 的数估计在几百到一千个水分子之间，实现后在报告里实测。
  • TRS4 的噪声：大体系配宽松的 Tolerance 时，最后一步的分支由舍入决定，结果在容差带里变动（第四节）。要稳定的结果，用较小的 Tolerance 或 TRS2，文档写明。
  • Coulomb：γ 的内存是 Nat²，周期体系的 Ewald 建立是 O(Nat² NG)，与 DFTB+ 相同。几万个原子时要换成不建矩阵的 Ewald（每轮 SCC 用结构因子算电势），之后再做。
  • 之后：块势的稀疏路径；M7d 分治与多机；M7e GPU 与跨结构批量。
