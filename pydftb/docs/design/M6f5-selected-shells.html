关键信息

DFTB+ 的 MaxAngularMomentum { Si = SelectedShells { "sp" "s" } } 把几个 SK 文件中的壳层拼成一个原子的基组：第一组 s、p 取自 Si 的文件，第二组 s 取自另一套文件（Si2），于是同一个 l 可以出现两次（sps* 基组）。M6f 的最后一块：pydftb 用 ParamSet(selected_shells=…) 做同样的事。只改 NumPy 引擎；不用这个选项时逐位不变。

  • DFTB+ 的做法（第一节）：
    • 每组壳层对应一个“文件物种”；每对物种列出 n1 × n2 个文件，第二个物种的组号变得快（Si-Si = "Si-Si.skf" "Si-Si2.skf" "Si2-Si.skf" "Si2-Si2.skf"）；原子内的轨道按组、组内按列出的壳层排列（"sd" "p" → s、d、p）；
    • 每个壳层的 on-site 能、占据数、U 取自它那一组的同核文件，按该壳层的 l；不分壳层的 SCC 时所有壳层都用第一个壳层的 U；质量取第一组的同核文件；排斥势只取每对物种的第一个文件；
    • 同一物种两组之间的文件（Si-Si2）按异核格式读（没有 on-site 行），只有对角的组（Si-Si、Si2-Si2）按同核格式读；同一对物种的所有文件必须网格相同，否则报错；
    • 同 l 的第二个壳层名为 “s2”，用在 CustomisedOccupations、eigenvec.out 与 detailed.out 中；自旋常数是 n壳层 × n壳层 矩阵，壳层分辨的 Hubbard 导数每个壳层一个。
  • 探针（第二节，DFTB+ 25.1）：
    • Cu4CO 与 Cu fcc（6 × 6 × 6 k 点）中把 Cu 写成 {"sd" "p"}（p 组取自 Cu 的类型副本 Cu2）时，能量、电荷、应力与普通写法完全相同（−13.004777345054 Ha）——确认了读取顺序与拼表规则；
    • 给 O 加一个 s* 壳层（取 H 的 1s，s2 = 0）的水、O2 三重态（3 × 3 自旋常数）、壳层分辨的 DFTB3、O 与 H 都分组（2 × 2 个文件）都能算；
    • DFTB+ 的问题：SelectedShells 与 Type2FileNames 同用时 DFTB+ 25.1 段错误（只有一个文件却按组数去取），不报错；
    • 水盒子中 O 的 s*（H 的 1s 放在 O 上）与近邻重叠太大，S 不正定（DFTB+ 与 pydftb 都会失败）：周期体系的验证改用 Cu 的重排。
  • pydftb 的接口（第三节）：ParamSet(skdir, selected_shells={"O": ("sp", "s")})（第 k ≥ 2 组的文件名默认是 “O2”，即 DFTB+ 手册的约定），或写明文件物种 {"O": (("O", "sp"), ("Ox", "s"))}；PyDFTB(skdir, selected_shells=…) 同样。reference_occupations 接受 “s2” 这样的壳层名。
  • 不支持：torch 后端、自动求导、自旋轨道耦合、DFTB+U 与 onsite 修正、Casida、类型切换（这些代码按 l 或按单组取数据），报错并写明原因。
  • 8计划的 DFTB+ 参考算例（25.1）
  • 0Cu 写成 {"sd" "p"} 与普通写法的能量差（DFTB+ 探针，Ha）
  • 段错误DFTB+ 25.1：SelectedShells + Type2FileNames

一、DFTB+ 的做法

源码 041e723（dftbplus/parser.F90：readMaxAngularMomentum、setupOrbitals、readSKFiles、getFullTable、checkSKCompElec；type/orbitals.F90: getShellNames），与 25.1 的行为一致（第二节）。

  1. 输入：SelectedShells { "sp" "s" } 的每个字符串是一组（1–4 个壳层字母，组内不能重复）；不同组可以有相同的 l。一个物种用了几组，SlaterKosterFiles 中每对物种就要列出 n1 × n2 个文件，第一个物种的组号在外层、第二个在内层；Type2FileNames 每对只给一个文件（见第二节的段错误）。
  2. 轨道顺序：一个原子的壳层按组、组内按列出的顺序排列（setupOrbitals），例如 "sd" "p" 是 s、d、p，而不是 s、p、d。
  3. 读文件（readSKFiles）：
    • 排斥势只从每对物种的第一个文件读（readRep = iSK1 == 1 .and. iSK2 == 1），其余文件的排斥势忽略；
    • 同核格式（第二行是 on-site 能、U、占据数）只用于同一物种的对角组（readAtomic = iSp1 == iSp2 .and. iSK1 == iSK2）；同一物种两组之间的文件按异核格式读——若它带 on-site 行，就会像坑 88 那样整体错一行；
    • 每个壳层（第 k 组、角动量 l）的 on-site 能、占据数、U = 第 k 组同核文件中 l 的值；不分壳层的 SCC 时 skHubbU(2:) = skHubbU(1)，即所有壳层用第一个壳层的 U；质量 = 第一组同核文件的质量；
    • 同一物种（同核对）只读正向的文件列表，反向的表就是它本身。
  4. 拼表（getFullTable）：对 A 的第 i 组中的壳层 l1 与 B 的第 j 组中的壳层 l2：l1 ≤ l2 时取文件 (Ai, Bj)，否则取 (Bj, Ai)，列的对应与只有一个文件时相同。所以整块等于“每个组对各算一个子块再拼起来”。
  5. 网格（checkSKCompElec）：同一对物种的所有文件必须有相同的网格间距与点数，否则报 “Incompatible SK grid separations / lengths”。拼好的表只有一个网格、一个截断。
  6. 壳层名（getShellNames）：s、p、d、f，同一个 l 的第二个起加序号（s2、p2）。CustomisedOccupations 按这些名字读（s2 = 0.0），eigenvec.out 与 detailed.out 的标签也用它们。
  7. 依赖壳层的其他输入：自旋常数是 n壳层 × n壳层 矩阵（按上面的壳层顺序），或者一个数；壳层分辨 SCC 的 HubbardDerivs 每个壳层一个值，否则一个值；SpinOrbit 每个壳层一个 ξ；+U 与 onsite 修正按壳层号。

二、DFTB+ 的实测行为

探针 P18（$S/m6f5/probe_ss.py），DFTB+ 25.1，测试参数 ptbp_hcocu（所有文件的网格都是 0.02 Bohr、719 点），类型副本由 skf.write_typed_copies 写出（同一个基础文件的异标签副本去掉 on-site 行）。

三、pydftb 的接口

from pydftb import DFTB, ParamSet
p = ParamSet(skdir, selected_shells={"O": ("sp", "s")})      # 第二组的文件：O-O2.skf、O2-O2.skf、O2-H.skf ...
p = ParamSet(skdir, selected_shells={"O": (("O", "sp"), ("Ox", "s"))})   # 写明每组的文件物种
r = DFTB(p.skset(["O", "H"]), reference_occupations={0: {"s2": 0.0}}).calculate(labels, pos)
atoms.calc = PyDFTB(skdir, selected_shells={"Cu": ("sd", "p")})
  • 文件名：第 1 组的文件物种默认是标签本身，第 k ≥ 2 组是“标签 + k”（DFTB+ 手册的例子 Si、Si2）；文件对 (Ai, Bj) 读 {A_i}-{B_j}.skf。同一物种两组之间的文件必须是异核格式（skf.write_typed_copies 生成的副本正是这样）。
  • 壳层分辨与否、hubbard（CustomisedHubbards，每个壳层一个值）、spin_constants（n壳层 × n壳层）、hubbard_derivs（每个壳层一个值）都按上面的壳层顺序；reference_occupations 的字典用 DFTB+ 的壳层名（s、p、s2）。
  • 一个组也可以只取部分壳层，例如 {"Cu": ("sd",)} 去掉 p 壳层（DFTB+ 允许）。
开发细节四、实现
  1. skf.SKSet(…, selected_shells=None)：
    • groups[label] = [(文件物种, [l, …]), …]；没有给的标签就是 [(label, 0…lmax)]，走原来的代码（onsite、hubbard、occupation 仍是 f.onsite[:lmax + 1] 等，逐位不变）；
    • 给了的标签：shells(label) 是各组 l 的拼接（可以重复），norb = Σ(2l + 1)；onsite、hubbard、occupation 是按壳层的数组（第 k 组同核文件中该 l 的值；默认标签的数组按 l 排，也就是按壳层排）；不分壳层时所有壳层取第一个壳层的 U（hubbard_from 不是 "s" 时报错）；质量取第一组；
    • files[(a, b)] 仍是第一个组对的文件（排斥势、截断等原有用法不变）；group_files[(a, b)] 是嵌套列表 [i][j]，只对含多组或非标准壳层的标签对建立；同核格式只用于 a = b 且 i = j（DFTB+ 的 readAtomic）；同一对的所有文件网格必须相同（同 DFTB+ 报错）；cutoff 取所有文件的最大值；truncated、with_hubbard 也处理这些文件与按壳层的 U。
  2. params.ParamSet(selected_shells=…)：解析两种写法（壳层字符串，或 (文件物种, 壳层字符串)），检查字母（spdf、组内不重复、1–4 个）、所需文件存在，传给 SKSet；缓存键包含它。
  3. hamiltonian：Basis 加 shell_local（壳层在原子内的序号）；onsite_energies 对选定壳层的标签按壳层累加偏移（原来的 l² 偏移只适用于 0…lmax）；build_pairs 对有 group_files 的标签对新加一个分支：blocks(v) 对每个组对用该组对的两个文件调用 sk_block（它本来就接受任意壳层列表），放进整块的对应位置；导数（复步或 DFTB+ 的差分）走同一个函数。单组的分支原样不动。
  4. calculator：按 l 取每个壳层数据的地方改为按 shell_local（默认标签两者相同，逐位不变）：_sites、_reference_shell_populations、_custom_shell_populations、_site_hubbard_derivs（原来的 .index(l) 在 l 重复时取错）；_reference_occupation_table 用 DFTB+ 的壳层名（与 analysis.orbital_labels 共用一个函数）。DFTB.__init__ 拒绝与 torch 后端、自旋轨道、+U、onsite 修正、Casida、类型切换同用，numpy_only_options 加 selected_shells；pydftb.autodiff 遇到选定壳层报错。
  5. ase_calc.PyDFTB(selected_shells=…) 传给 ParamSet。
  6. 验证工具：Case.selected_shells（{标签: [(文件物种, "sp"), …]}，与现有的 typed 一起生成文件副本）；dftbplus.make_hsd 写 SelectedShells 与逐对列出的 SlaterKosterFiles；refgen.run_pydftb 把它传给 ParamSet；reference_occupations 的壳层名写进 CustomisedOccupations。

六、不做的事与风险

  • 不支持：torch 后端与自动求导、SOC、DFTB+U、onsite 修正、Casida（按 l 取数据或按单组建模的代码）、类型切换；以后需要时逐项放开。
  • 风险：把按 l 取值改为按壳层序号取值，涉及几个已有函数——对默认标签两者相同，由 golden 守住逐位不变。
  • 额外的 s 壳层若与近邻重叠太大，S 会不正定（探针 wbox_s2），这是参数的问题，pydftb 与 DFTB+ 一样报错。
