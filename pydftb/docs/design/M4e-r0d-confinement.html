关键信息

PTBP 的原计划是每个元素优化三个参数：波函数约束半径 r0_w、密度约束半径 r0_d、排斥势参数 σ_rep。M4c 发现 r0_d 根本不改变 SKF，每个元素实际只剩两个有效参数。原因已经查明：hotcent 2.0 把原子计算的“约束方式”改了默认值，而 PTBP 是按 hotcent 1.x 写的，没有指定这个选项。M4e 让 PTBP 显式使用 hotcent 1.x 的做法，r0_d 重新起作用。

  • 原因：hotcent 在 2023-02-05 把 AtomicDFT 的 perturbative_confinement 默认值改为 True（微扰约束，随 2.0.0 于 2024-03-18 发布），之前是自洽约束。在微扰约束下，只要每个价层都有波函数约束（PTBP 正是这样），电子密度就完全由 r0_w 约束的轨道算出，r0_d 不再起作用。
    • utils/hotpy.py 是按 hotcent 1.x 写的，第 32 行注释里还留着 1.x 的 from hotcent.slako import SlaterKosterTable。它调用 AtomicDFT 时没有给这个选项。
    • 同一项目的 utils/get_sto_coefficients.py 调用 AtomicDFT 时显式写了 perturbative_confinement=False：作者用的就是自洽约束，只是 hotpy.py 漏掉了。
    • hotcent.slako 这个接口在 2021-11 就改名了，早于默认值的变化（2023-02），所以 PTBP 最初写成时用的是自洽约束。发表的参数（Zenodo，2024-02）具体用哪个版本生成，仓库里无从确定；M4e 报告用损失的对比来判断。
  • 实测（Cu，发表的参数 r0_w = 2.749 Bohr）：
    • 微扰约束：r0_d 取 12.036 和 13.0 时 Cu-Cu.skf 逐字节相同。
    • 自洽约束：r0_d 改变 SK 表，两者最大差 0.011。
    • 同一组参数下，两种约束方式的 SK 表最大相差 0.80。
  • 做法：
    • PTBP 新增 --confinement selfconsistent|perturbative，默认 selfconsistent，即 hotcent 1.x 的做法。
    • perturbative 用来复现 M3、M4 的运行结果。
    • onsite 能量和 Hubbard U 取自 PTBP 自己的参数表，不受影响；受影响的只有二中心积分（H、S 表）。
  • 代价：同一组参数生成的 SKF 改变了，默认 BO 的损失和结果都会变，这是有意的。hotcent 只多几次原子计算：Cu 的一次完整 SKF 生成从 47 s 增加到 50 s（单进程）。
  • 不能恢复的部分：hotcent 2.0 同时修正了二中心积分中 GGA 的一个错误。用 hotcent 2.1 的自洽约束，仍不等于论文当时的 SKF。M4e 报告要如实区分这两个因素对“损失 1.90 对论文 0.288”的影响。
  • 3每个元素的有效参数：r0_w、r0_d、σ_rep
  • 0 → 0.011r0_d 从 12.036 变到 13.0 时 SK 表的最大变化（微扰 → 自洽）
  • 0.80同一参数下两种约束方式的 SK 表最大差

一、两种约束方式

DFTB 的基函数是“受限原子”的轨道：在自由原子上加一个约束势 V = (r/r0)^p，把轨道压紧。PTBP 给每个元素两个半径：r0_w 约束波函数（决定基函数的形状），r0_d 约束电子密度（决定计算二中心积分时用的势）。

自洽约束（hotcent 1.x 默认）微扰约束（hotcent ≥ 2.0 默认）
波函数每个价层：加 r0_w 约束势，整个原子重新自洽计算一次，取这个价层的轨道先算一次自由原子；每个价层：在自由原子的有效势上加 r0_w 约束势，势保持不变，只解这个价层
密度加 r0_d 约束势，整个原子再自洽计算一次，用它的密度同样只在自由原子的势上加约束；有波函数约束的价层直接用波函数约束的轨道，所以 PTBP（每个价层都有波函数约束）的密度只由 r0_w 决定
r0_d 是否起作用是否（PTBP 的设置下）

出处：/opt/hotcent/hotcent/atomic_dft.py 第 296–360 行；/opt/hotcent/CHANGELOG.rst 的 2.0.0 一节：“The 'perturbative' confinement scheme is now the default for AtomicDFT calculations”。

  • r0_d = 12.036 时，两种方式的 SK 表最大相差 0.80（Hartree 或重叠，未归一）。差别来自波函数：自洽约束下，约束势作用于整个原子的自洽计算，轨道与“冻结势”下解出的不同。
  • onsite 能量和 U 不受影响：hotpy.generate_skf 写 SKF 时用的是 PTBP 参数表里的本征值和 Hubbard U（atom.info），不是 hotcent 算的。
  • hotpy.py 中还有一处适配 hotcent 2.0 的改动：把 _offsite2c.skf 改名为 .skf。这说明代码是先为 1.x 写的，后来才改用 2.x，但没有处理约束方式的默认值变化。
  • 同一项目的 utils/get_sto_coefficients.py 显式写了 perturbative_confinement=False，说明作者用的是自洽约束。

三、改动

位置改动
utils/hotpy.py进程级设置 set_confinement() / confinement()（默认 "selfconsistent"，与 utils.engines.configure 的做法相同，派生的 hotcent 进程自动继承）；hot_hamiltonian 调用 AtomicDFT(..., perturbative_confinement=...) 时显式传入。utils/hotcent_tangent.py 自己新建的 hotpy 因此也用同一设置
utils/hotcent_parallel.py原子计算在父进程里完成，分片只涉及 SK 表的行，与约束方式无关；只需确认它走的是同一个 hot_hamiltonian
utils/get_sto_coefficients.py不改：它已经显式写了 perturbative_confinement=False
cli/arg_parser.py、cli/cmd_optimize.py、cli/config.py--confinement（ptbp optimize 同名）、YAML 键 confinement；默认值不往旧的命令行里加任何东西
cli/run.py、utils/loss.py把设置交给 Loss.hp；在运行开头打印一行，并写进 plan.json 的 hotcent 字段
utils/hotcent_tangent.py代码不变（r0_d 探测发现 SKF 改变时自动用中心差分）；更新说明文字

不改 par.out、log.out 的列（下游脚本按列读取）；设置记在运行开头的打印和 plan.json 里。

四、对其他部分的影响

  • 默认结果：同一组 (r0_w, r0_d) 的 SKF、损失和 BO 的路径都会变。M3、M4 报告中的数字是微扰约束下的，作为历史记录保留，并在报告中注明。
  • M4c 的梯度：r0_d 有了非零切向，每次梯度从 2 次 hotcent 变为 4 次（r0_w、r0_d 各两次）。代码已支持，要用分层验证确认 dμ/dr0_d。
  • 成本模型（M3c）：hotcent 阶段的估计按微扰约束标定，自洽约束只多约 6%，在模型的误差范围内；实测偏差大于 10% 时再重新标定。
  • pydftb：不受影响（SKF 是输入）。
  • G1 门槛：拆成两部分：
    • --confinement perturbative 时，与 M4 之前的提交 65115d1 逐字节相同，证明其余代码没变；
    • 默认值下，1 核与 4 核逐位相同，pydftb 与 DFTB+ 的损失一致。

六、不做的事与风险

  • 不还原 hotcent 2.0 修掉的 GGA 错误，也不换回 hotcent 1.x：那会重新引入已知的错误。
  • 不重新拟合已发表的参数：M4e 只恢复参数化的方法；是否用新设置重新拟合，由用户决定。
  • 风险：多元素模式（--multi_element）本身跑不通（已知问题），不在本阶段处理。
