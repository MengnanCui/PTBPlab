关键信息

把仓库拆成两个可安装的包：pydftb（DFTB 引擎，运行只依赖 numpy、scipy、ase、threadpoolctl，可以单独安装）和 ptbp（依赖 pydftb）。两个包各有命令，用户不再需要 python xxx.py 命令：pydftb advisor|refgen|dynamics|golden|gpu-check|gradcheck，ptbp parity（原 tools/engine_parity.py）。不移动任何文件，旧的 python -m … 与脚本写法照旧可用。

  • 布局（第二节）：在包目录里放第二个项目根 pydftb/pyproject.toml，用 package-dir = {"pydftb" = "."} 把包 pydftb 映射到它所在的目录。源码原地不动，仓库根目录下 import pydftb 与以前完全一样：golden 从旧提交的 git 工作树根目录导入 pydftb，CI 和测试用 PYTHONPATH=.，文档里的路径都不变。
  • 包清单：显式列出 6 个包，include-package-data = false，测试数据用 package-data 收进来。自动发现会把 docs/、bench/、tests/data/*、build/ 当成命名空间包。预期的轮子：439 个文件（32 个顶层模块，advisor、autodiff、backend 各 6 个，validation 11 个，测试 34 个 .py 与 344 个数据文件），没有 docs/、bench/ 和 README。
  • 命令（第三节）：pydftb 子命令 参数… 用到时才导入对应工具，参数原样交给工具已有的 main(argv)；缺 torch 时给一句话的提示（退出码 2）。ptbp parity 在 argparse 之前把参数交给 tools/engine_parity.main。
  • 选型：setuptools ≥ 77（PEP 639 的许可证元数据）。读过 setuptools 84 与 pip 26 的源码：轮子、sdist、PEP 660 可编辑安装都支持这种布局。hatchling 的可编辑安装不适合；不改成 src/ 布局（那要移动文件）。
  • 2可安装的包：pydftb、ptbp
  • 6 + 1新命令：pydftb 的 6 个子命令与 ptbp parity
  • 0移动的文件
  • 439预期的 pydftb 轮子文件数（不含元数据）

一、目标与约束

  • 目标（用户决定）：
    • pydftb 单独可装，运行依赖只有 numpy、scipy、ase、threadpoolctl；torch、dftd3/dftd4 是可选的；
    • ptbp 依赖 pydftb；
    • 两个包都有命令：pydftb 的子命令调用现有工具的 main(argv)，不改工具本身；tools/engine_parity.py 变成 ptbp parity；
    • 文档改用新命令；旧的 python -m … 与脚本写法都要继续可用。
  • 约束：不移动文件。很多地方依赖 pydftb/ 是仓库根目录下可导入的包：
    • golden 逐字节回归在旧提交的 git 工作树里以 PYTHONPATH=工作树 导入 pydftb；
    • CI 与测试在仓库根目录用 PYTHONPATH=.；
    • 文档、设计与报告里的路径（pydftb/validation/…、pydftb/tests/data/…）。
  • 不变的东西：不改任何数值计算；golden 必须逐字节相同（不加 --allow-new）。

二、布局：包目录里的第二个项目根

PTBPlab/
  pyproject.toml          # ptbp：cli*、utils*、tools*、parameterize；依赖 pydftb
  parameterize.py  cli/  utils/  tools/  tests/
  pydftb/
    pyproject.toml        # pydftb：package-dir = {"pydftb" = "."}
    LICENSE               # 根目录 LICENSE 的副本（license-files 写 ".." 已弃用）
    __init__.py  cli.py  __main__.py  …  advisor/ autodiff/ backend/ validation/ tests/
    docs/  bench/         # 不进轮子
  • 映射：package-dir = {"pydftb" = "."} 让包 pydftb 就是 pydftb/pyproject.toml 所在的目录，子包 pydftb.validation 是 ./validation。目录本身仍是仓库根目录下的普通包，所以不安装时一切照旧。
  • 包清单要写死：packages = ["pydftb", "pydftb.advisor", "pydftb.autodiff", "pydftb.backend", "pydftb.tests", "pydftb.validation"]。自动发现（pyproject 配置下默认找命名空间包）会把 pydftb.docs*、pydftb.bench、pydftb.tests.data.* 以及在源码树里构建时留下的 pydftb.build.* 都当成包。新测试检查清单与目录树一致（有 __init__.py 的目录）。
  • 数据：include-package-data = false，只用 "pydftb.tests" = ["data/**/*"] 收测试数据（冻结的 DFTB+ 参考、SKF、顾问的运行）。docs/、bench/（bench/throughput.py 导入 PTBP 的 utils，留在仓库里）、README、图片都不进轮子。
  • 版本：dynamic = ["version"]，取 pydftb.__version__（现为 0.1.0.dev0），setuptools 静态读取，构建时不导入 numpy。
  • pytest 配置：pydftb/pyproject.toml 里不放 [tool.pytest*]：否则在仓库根目录跑 pytest pydftb/tests 时 rootdir 会变。
  • 可编辑安装（PEP 660，setuptools 的默认 lenient 模式）：
    • pydftb 的映射不是 {"": …}，setuptools 用 _TopLevelFinder：在 site-packages 写一个 finder，MAPPING 为 {'pydftb': '仓库/pydftb'}，追加到 sys.meta_path 末尾，所以当前目录与 PYTHONPATH 仍然优先（golden 的子进程照旧导入各自工作树里的 pydftb）；
    • ptbp 的映射是 {"": "."}，setuptools 用静态 .pth，把仓库根目录加进 sys.path（与现在相同）；
    • 不要用 editable_mode=compat：它用静态 .pth 把 pydftb/ 目录本身加进 sys.path，其中的模块（cli、tests、system 等）都成了顶层模块，与 PTBP 的 cli、tests 撞名。

三、命令

pydftb advisor RUN_DIR           # = python -m pydftb.advisor RUN_DIR
pydftb refgen --check            # = python -m pydftb.validation.refgen --check
pydftb dynamics --check          # = python -m pydftb.validation.dynamics --check
pydftb golden --base COMMIT      # 只能在 git 检出中运行
pydftb gpu-check --quick         # 别名 gpu_check；需要 torch
pydftb gradcheck --check         # 需要 torch
pydftb --help | --version        # python -m pydftb … 是同一个命令

ptbp parity dft/dft.xyz --mode energygeometry --points 2.749,12.036 \
     --engines pydftb --compare-serial --workdir /tmp/parity   # = python tools/engine_parity.py …
  • pydftb/cli.py：子命令表 COMMANDS（名字 → 模块）；用到时才 importlib.import_module，参数原样交给 main(argv, prog="pydftb 子命令")，返回 int(rc or 0)（refgen、dynamics、gradcheck 的 main 返回 None）。工具自己的 SystemExit（argparse 的错误、--check 的 sys.exit）照常穿过。缺 torch（ModuleNotFoundError，name == "torch"）时打印一句话，退出码 2。--help 列出子命令，--version 打印版本；未知子命令由 argparse 报错（退出码 2）。pydftb/__main__.py 让 python -m pydftb 可用。
  • prog=：六个工具的 main 加一个关键字参数 prog=None，用法行显示为 pydftb refgen；不传时与以前相同（advisor 默认仍是 python -m pydftb.advisor）。
  • ptbp parity：cli/main.py 的 dispatch 一开始（argparse 之前）就把 argv[1:] 交给 tools.engine_parity.main：用 argparse 的 REMAINDER 会把开头的 --help 当成 ptbp 自己的。_build_top_parser 里加一个只用于帮助的占位子命令，让它出现在 ptbp --help 中；SUBCOMMANDS（cli/main.py）与 NEW_SUBCOMMANDS（parameterize.py）加上 parity。
  • golden 在安装的副本中：golden 在包的上一级目录运行 git，从轮子安装时那是 site-packages。新增检查：上一级目录必须是一个跟踪着 pydftb/ 的 git 检出的顶层，否则给出清楚的错误（退出码 2）。
  • 重新生成参考：refgen --regenerate、dynamics --regenerate、make_f_set、make_poly_set、advisor_cases 写进包里的 tests/data，只在检出中使用；在文档字符串与 README 中写明。

开发细节六、验证计划

所有构建都在 git ls-files -co --exclude-standard 导出的副本中做，不在仓库里（源码树内构建会留下 pydftb/build/ 与 egg-info）。

  1. 构建：conda 环境（setuptools 84）pip wheel --no-build-isolation 构建两个轮子；数 pydftb 轮子的文件（预期 439 + licenses/LICENSE），ptbp 轮子里不能有 pydftb/；python -m build（隔离环境）走 sdist → 轮子。
  2. 只装 pydftb：conda 的 Python 与 /usr/bin/python3 各建一个 venv（不用 --system-site-packages：conda 环境的 ptbp .pth 会把仓库加进 sys.path），装轮子与 pytest；在仓库外检查 find_spec('utils') is None，运行 pydftb --help、pydftb refgen --check、pytest --pyargs pydftb.tests。
  3. 两个包：同一个 venv 中 pip check、ptbp --help、ptbp parity --help、import pydftb, utils, cli, tools, parameterize。
  4. 可编辑：pip install -e 仓库/pydftb -e 仓库；在 / 下导入指向仓库；git status 不变。
  5. 门槛：golden 两个环境对 5b90f55 逐字节相同（不加 --allow-new）；refgen --check 217 个单点、dynamics --check 24 个；三个环境的 pydftb 测试（基线 880/143、648/254、845/178，加上新测试）；PTBP 测试（224 个通过与 7 个已知的界面冒烟测试失败）；G1：engine_parity 与 ptbp parity 两种写法，损失 0.9198547924，1 核与自动核数逐位相同。

新测试

  • test_packaging.py：pyproject.toml 的包清单与目录树一致（安装的副本中没有该文件时跳过）；在新的解释器中导入 pydftb 的每个模块，导入系统拒绝 PTBP 的顶层名字 utils、cli、tools、parameterize，不能有任何一次尝试。
  • PTBP 一侧：ptbp parity 把参数原样交给工具，--help 是工具自己的，parameterize.main 把 parity 交给分派。

七、不做的事与风险

  • 不做：
    • 不移动文件，不改成 src/ 布局；
    • 不发布到 PyPI；advisor_cases、make_f_set、make_poly_set 这些只在检出中用的生成工具不做成子命令（仍用 python -m）；
    • 不改共享的 conda 环境：合并后由主线把它换成两个可编辑安装（命令见报告）。
  • 风险：
    • 真实构建与设计不符（例如 setuptools 不接受这种映射）：先做构建验证；不行就停下汇报，不改布局；
    • PyPI 上还没有名为 pydftb 的项目：只装 ptbp 时 pip 找不到 pydftb 并报错；将来若有人注册这个名字，单独 pip install . 会装上别人的包。安装说明一律把 ./pydftb 与 . 一起给 pip；
    • 可编辑安装的 lenient 模式：_TopLevelFinder 排在 PathFinder 之后，所以当前目录与 PYTHONPATH 上的 pydftb 优先；但若那棵树里缺少某个直接子模块，finder 会从可编辑安装的目录补上（只影响在旧树里运行新代码这类情形，golden 不会遇到）。
