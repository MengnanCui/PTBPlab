关键信息

M7c 的稀疏路径与 M7d 的分治之后，大体系卡在 Coulomb（Ewald）的建立上。pydftb 把 Ewald 实空间截断内的全部原子对存成一张表（i、j、像、矢量、距离），供 γ 与力使用：1728 个水分子时这张表 2.74 GiB，建立时峰值多出 8.2 GiB（邻居表本身 56 s），力再临时多出 3.7 GiB，都随 N1.5 增长；2744 个水分子就超过这台机器给作业的 13.36 GiB（估计约 19 GiB）。M7d2 改为按中心原子分块，每块现算自己的原子对、算完就丢，力也一样，倒空间的和按 G 分块；这与 DFTB+ 的做法相同（它的 TDynNeighList 不存对表）。小体系照原来的代码走，逐位不变。

  • 逐位相同（P122、P123）：
    • 块的近邻查询拼起来与全局对表逐位相同：五个数组都一样，216 个水分子共 1.8M 对，块为 97 个中心原子。
    • 按块累加的实空间 γ 与实空间力，与原来的逐位相同：γ 的每个元 (i, j) 与每个原子 i 的力，贡献全在同一块里，块内次序与全局切片相同。
    • 倒空间不分块时，整个 γ 与力都逐位相同（1000 与 1728 个水分子）。位力是对全部对的一次 einsum，按块求和后相对差 5e-14。
    • 倒空间按 G 分块时，γ 的相对差 ≤ 6e-16，力差 ≤ 1e-18 Ha/Bohr。
  • 内存与时间（P122，1728 个水分子，块 64 个中心原子，G 每块 1024 个）：
    • γ 从 63 s、+8.4 GiB 降到 24 s、+0.9 GiB；
    • 力从 17.5 s、+3.8 GiB 变为 23 s、+0.16 GiB。力里要重算一遍原子对，所以慢一些。
    • 每块的查询比一次全局查询快，因为没有巨大的临时数组与全局排序。
  • 更大的体系（P124，SCC 加力，Subsystems(processes=4)）：
    • 1728、2744、4096 个水分子各用 189 s、321 s、558 s。主进程峰值 2.06、3.50、5.64 GiB，整台机器（含 4 个工作进程）5.43、8.29、12.6 GiB；原来的代码在 1728 个水分子时主进程就要 9.74 GiB。
    • 1728 个水分子对原来的 Coulomb：能量差 9.1e-13 Ha，电荷 2.5e-12 e，力 2.8e-13 Ha/Bohr。
    • 4913 个水分子超出这台机器给作业的内存上限（13.36 GiB），原因已不是 Coulomb：建立之后主进程有 6.05 GiB（γ 1.62、SK 原子对 1.38、稀疏结构 0.85 GiB），再加上分治的工作进程（P125、P127，第八节）。
  • 不在这一块做的：γ 本身仍是 N × N（4913 个水分子时 1.62 GiB）；ThirdOrder 的 γ3、LJ 与 Slater–Kirkwood 色散的 N × N 参数矩阵、点电荷与 ESP 的 cos/sin 也还是 N 的平方。不建 γ 的电势（每轮用结构因子）是再往上一步。
  • 0实空间 γ 与力按块累加后变的位
  • +0.9 GiB1728 个水分子建立 γ 的峰值（原来 +8.4 GiB）
  • 24 s1728 个水分子建立 γ（原来 63 s）
  • 558 s4096 个水分子（12288 个原子）的 SCC 加力，整台机器峰值 12.6 GiB

一、范围

  • 做：
    • 周期体系的 Coulomb：估计的实空间原子对超过阈值时按块工作，γ、力与位力都不存对表；
    • 倒空间的和（γ 与力）按 G 分块，γ 原地累加，每个原子一个位点时只有一个 N × N 数组；
    • ThirdOrder 的原子对在分块时由块的查询取得；
    • perfmodel 的内存估计按分块后的数。
  • 不做：
    • 分子（截断就是短程截断，对表很小）、torch 后端与 autodiff（autodiff 遇到分块的 Coulomb 时报错，见第四节）；
    • γ 本身的 N² 与其他 N² 的数组（第八节）；
    • Ewald 的参数（α、截断、G 的范围）不变，与 DFTB+ 相同。
  • DFTB+：它只存 N × N 的 invRMat，实空间的近邻用 TDynNeighList（type/dynneighlist.F90）在需要时现算，力（addInvRPrime）也一样。分块的做法与它相同。

二、探针

草稿目录 m7d2/：p121_breakdown.py（现状的分解）、原型 chunkproto.py（ChunkedCoulomb，Coulomb 的子类）、p122_compare.py（原型对原来的 γ、力与位力）、p124_large.py（大盒子上的 SCC 加力）、p125_setup_memory.py（建立阶段的内存）、p127_states.py 与 p127b_subs_memory.py（分治存下的数组）。水盒子与 M7c、M7d 相同（ptbp_hcocu，约 1 g/cm³，每个原子一个位点）。每个规模一个进程，峰值是 VmHWM，每段之前经 /proc/self/clear_refs 归零，表中给的是比该段开始时多出的量。本机 4 核，15 GB。

三、方法

  • 块的查询：neighbors.pair_blocks(pos, cell, pbc, cutoff, step)。像的范围与 neighbor_list 相同（按全部原子取），全部像的 k-d 树建一次；每块的中心原子 [lo, hi) 建一棵小树，做稀疏距离查询，pair_vectors 求矢量，去掉零距离，按 (i, j, 像) 排序。neighbor_list 拆成同样的几步，只是搬代码，结果逐位不变。
  • γ：每块照原样做位点展开、S（含 H 阻尼与 H5）与 erfc(αd)/d，用 np.add.at 加到 γ（或原子级的实空间矩阵）上。倒空间：
    • 原路径（对数在阈值以下）不变：一次 GEMM，g + expand(real + rec − c) 的次序照旧；
    • 分块路径按 G 分块（默认每块 1024 个 G）、GEMM 按行分块，原地加进 γ；每个原子一个位点时实空间与倒空间都直接加进 γ，壳层分辨时先在原子级的矩阵里加好再按行展开到位点。
  • 力与位力：gradient 先做倒空间（分块时按 G 分块），grad = zeros; grad += … 的次序照旧，然后逐块算 dedr（短程与 Ewald 在同一个数组里）并 np.add.at(grad, i, …)。位力的对的部分从第一块起累加（不从零开始，免得对称晶胞里翻出 −0.0），再加 G 的各项。
  • 阈值：估计的实空间对数 N²·(4/3)π·rc3/V（1728 个水分子给出 40.77M，实测 40.83M），超过 PAIR_TABLE_LIMIT = 600 万对时分块：约 500 个水分子，原路径在这里建立 Coulomb 时多出约 1.2 GiB（P121：512 个水分子 6.5M 对）。块的大小按对数定：每块约 BLOCK_PAIRS = 219（约 52 万）对，1728 个水分子时每块 66 个中心原子。全部参考算例与 golden 的体系都 ≤ 24 个原子，远在阈值以下。
  • 逐位：原路径不变（golden）；分块路径对原路径到舍入（实空间部分逐位，倒空间约 1e-15，位力约 5e-14）；分块路径的“一块”与“多块”逐位相同。

四、与其他模块

  • ThirdOrder：原来从 c.nl 里挑出自己截断内的对。分块时 c.nl 是 None，改由块的查询按自己的截断取（截断取 min(rc, 表中最大的截断)，再按原来的条件过滤），与过滤整表的结果逐位相同（已在内存里核对）。不假定它的截断 ≤ 短程截断：(tau/3.2)·3.2 的往返可能差一位。
  • autodiff：autodiff.model.gamma_matrix 要整个 Ewald 范围的对表。遇到分块的 Coulomb 时抛出 NotImplementedError，说明对数超过了 coulomb.PAIR_TABLE_LIMIT；在需要时才建整表，反正也放不下。
  • 点电荷与 ESP：只用 α、截断、G 矢量与体积，自己建对，不受影响。
  • 只用 γ 的：SCC 的 energy_shift、XL 的影子能量、Casida、response.scc_kernel，不受影响。
  • 分子：response.coulomb_jacobian 等只用于分子，分子总走原路径。
  • golden 与 test_perfmodel：只看小体系，原路径的公有属性（nl、sp_*、gamma）照旧；新的状态都用下划线开头的名字，golden 不记录，不用 --allow-new。
  • perfmodel：PYDFTB_MEMORY["coulomb_pairs"]（每对约 77 B，相当于整表）在对数超过阈值时封顶在块的预算。

五、接口

  • 没有新的用户选项：分块与否按体系大小自动决定，结果到舍入相同。
  • coulomb.py 的模块常数（写法同 hybrid.IMAGE_CHUNK）：PAIR_TABLE_LIMIT（分块的阈值，6_000_000）、BLOCK_PAIRS（每块的对数，2**19）、G_CHUNK（每块的 G 数，1024）、ROW_BLOCK（倒空间 GEMM 每块的行数，1024）。测试用 monkeypatch 把阈值设为 0、把块设小来强制分块。
  • Coulomb 分块时 nl 与 sp_* 是 None（不会悄悄给出一张不完整的表）。

七、验证 开发细节

  • pair_blocks 拼起来等于 neighbor_list：斜晶胞、有原子在晶胞外，块为 1、7 个原子与全部。
  • 分块的“一块”与“多块”：γ 与力逐位相同。
  • 强制分块对原路径：γ ≤ 1e-13，能量、电荷、力（有无 other）与位力 ≤ 1e-12；冻结的周期算例覆盖 Γ 点与 k 点、DFTB3、H 阻尼与 H5、壳层分辨与点电荷（water_box_gamma、cuo_chain_k422、gdo_rocksalt_k444、water_box_dftb3、water_box_h5、water_box_pc、cu4co_shell_resolved、cu4co_dftb3_shell），SCC 轮数相同；ASE 的 MD 两步。
  • 建在分块 Coulomb 上的 ThirdOrder：数组与梯度相同。autodiff 的拒绝。内存守卫：约 200 个水分子强制分块时，γ 阶段的峰值低于 γ 加上几倍的块预算。perfmodel 的内存封顶。
  • 工作进程在主进程被杀之后自己退出（test_subsystems.py）。
  • 门槛：golden 两个环境逐位相同（对照 6b45c0b，不用 --allow-new），refgen（NumPy、torch、sparse、sparse-csr、foe、subsystems），dynamics，pytest 三个环境与 MPI 环境，PTBP 测试与 G1。

八、风险与之后

  • γ 仍是 N²：4913 个水分子 1.62 GiB，一万个水分子 6.7 GiB。再往上要不建 γ：每轮 SCC 用结构因子算倒空间的电势、按块算实空间的电势，力也一样；这改变 SCC 的每一轮，另做一块。
  • 其他 N² 的数组：ThirdOrder 的 γ3（DFTB3）与它的对表、LJ 与 Slater–Kirkwood 色散的 N × N 参数矩阵、点电荷与 ESP 的 cos/sin（N × nG）、response.scc_kernel 的 γ 副本、不用 M7c 与 M7d 求解器时的稠密 H 与 S。这一块只处理 Coulomb 本身，其余在文档里写明。
  • 力变慢：力要重算一遍原子对（1728 个水分子 23 s 对 17.5 s）；SCC 中不受影响，只在每个几何多一次。
  • 位力：按块求和改变次序（约 5e-14，相对），对称晶胞的零要小心（第三节）。
  • 分治在五千个水分子时的内存（M7d 的部分，不在这一块）：4913 个水分子、4 个工作进程超出 13.36 GiB（P124、P125、P127b）。子体系的索引（1.99 GiB，每个工作进程都留着整份）可以减半：位置用 int32，核心部分用掩码而不另存一份；再像 MPI 的进程那样由每个工作进程只建自己的那些。稀疏路径（M7c）没有这些，4913 个水分子放得下（报告第五节）。
  • SK 原子对：build_pairs 仍用整张邻居表，4913 个水分子时建立阶段临时多出 3.86 GiB，是现在最大的临时峰值；可以照 Coulomb 的办法分块。
  • 之后：M7e（GPU 自检与跨结构批量），再后是 M8。
