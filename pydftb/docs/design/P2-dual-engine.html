关键信息

用户要两套计算机制：同一组选项，在计算命令里切换 --engine pydftb|dftbplus，就能用 pydftb 或 DFTB+ 计算所有两边都有的功能。现在只有 PTBP 自己的计算能切换引擎；pydftb 的功能没有面向用户的 DFTB+ 路径，也没有 pydftb run 命令。可是验证工具里早有一套 DFTB+ 输入的写法，517 个冻结参考就是用它写出、跑出的。所以这一块把这套写法接到一个新的 ASE 计算器上，参数与单位和 PyDFTB 相同，再加一个统一的入口和命令。

  • 输入（P133）：把每个冻结参考的设置翻译成引擎中立的选项，再由新的 DFTB+ 引擎写出输入。
    • 517 个单点、34 个优化与 MD、37 个第二次运行（13 个能带、24 个二阶导数），DFTB+ 读到的内容全部与冻结的输入相同。
    • 511 个单点逐字节相同。另外 6 个只差末位：两个是固定费米能级的 eV → Ha 换算，四个是归一化后的 k 点权重。
  • DFTB+ 引擎实跑（P134）：517 个算例全部跑通，其中 502 个解析出的输出与冻结参考逐位相同。
    • 例外是上面 6 个输入差一个末位的算例（输出差 ≤ 2e-13），和 9 个 NTPoly 算例（带 ELSI 的 24.1，差 ≤ 2e-13）。后者是 DFTB+ 自己的不确定性：同一个输入连跑三次，电荷之间就差 5e-13。
    • 能量用 results.tag 的全精度值，与 detailed.out 的 10 位小数差 ≤ 5e-11 Ha。
    • 找到 DFTB+ 输出的三处坑（第五节）。
  • pydftb 引擎（P134b）：PyDFTB 用同样翻译出来的选项，与 refgen 直接调 DFTB 的结果相比，517 个算例里 501 个逐位相同，其余 16 个差 ≤ 1.1e-12。差别来自输入的单位换算：eV 的费米能级、V/Å 的电场方向、归一化的 k 点权重、Casida 求解器的名字。
  • ASE 驱动 DFTB+ 引擎（P135）：BFGS 与速度 Verlet 每步调用 DFTB+，沿用上一步的电荷，与冻结的 DFTB+ 自己的驱动对照。
    • 27 个算例里 26 个在动力学的容差内：优化到同一个极小（坐标差 ≤ 2.1e-6 Å，能量差 ≤ 5e-11 Ha），MD 轨迹差 ≤ 6.8e-8 Å、≤ 5.7e-8 Ha，与 pydftb 经 ASE 的一样，受 ASE 的单位常数限制。
    • MD 每步的 SCC 轮数绝大多数相同。
    • 不行的一个是非共线的杂化泛函：DFTB+ 不给它写电荷文件，每步从初始自旋开始，有一步 SCC 发散。它与 7 个 XL-BOMD 算例都只能用 DFTB+ 自己的驱动（--native）。
  • 时间（P136）：每次调用 DFTB+ 的固定开销约 20 ms（H2 非 SCC：引擎 22 ms，PyDFTB 3 ms）；水的 MD 经 ASE 每步比 DFTB+ 自己的驱动多 41 ms。508 个算例每个的中位数：DFTB+ 引擎 78 ms，pydftb 42 ms。
  • 不改的：PTBP 自己的 --engine 照旧，结果逐字节不变；旧的 pydftb 路径逐位不变。
  • 588 / 588DFTB+ 输入与冻结的相同（P133）
  • 517 / 517实跑 DFTB+ 与冻结参考相同（P134）
  • 501 / 517pydftb 经统一选项逐位不变（P134b）
  • ≈ 20 ms每次调用 DFTB+ 的固定开销（P136）

一、范围与现状

  • 现状：
    • PTBP：utils/engines.py 的 make_calculator(mole, dftb_args, engine) 在 ASE 的 Dftb 与 PyDFTB 之间切换（M1）。只有 PTBP 用到的功能才有两条路径（静态、能带、xTB）。
    • pydftb：每个功能都对照 DFTB+ 验证过，但用户只能用 pydftb 算。DFTB+ 的输入只在 validation/dftbplus.py 与 refgen 里写出，按“算例”组织，不是按用户的选项。
    • 冻结参考存着每个算例的输入、HSD 与结果：517 个单点，34 个优化与 MD。
  • 做（用户选的范围：“pydftb 统一入口 + 命令”）：
    • 新的 ASE 计算器 DFTBPlus：参数与单位和 PyDFTB 相同，写 DFTB+ 的输入，运行，把结果换成同样的字段。
    • pydftb.engines.make_calculator(skdir, engine=...)：同一组选项给出 PyDFTB 或 DFTBPlus；某个引擎没有的选项给出明确的错误。
    • 命令 pydftb run --engine pydftb|dftbplus：单点、优化、MD、能带、DOS 与 PDOS、二阶导数与简正模式。
    • 核对：每个冻结参考的输入与结果，两个引擎都核对（第七节）。
  • 不做：
    • PTBP 的引擎开关不动；
    • DFTB+ 有而 pydftb 没有的功能（xTB、输运、REKS、MBD 等）不进统一选项，只能用原样的 HSD 片段传给 DFTB+（extra_*）；
    • pydftb 有而 DFTB+ 没有的（类型切换、torch 后端、FOE、子体系、自动求导）在 DFTB+ 引擎上报错。

二、探针

草稿目录 p2/。原型 proto.py 把算例翻译成选项、由选项写 DFTB+ 的输入；proto_calc.py 是原型计算器。DFTB+ 是 conda 的 25.1。开发版与 ELSI 版（24.1）只给需要它们的算例用，与冻结参考相同。

探针做什么结果
P133每个冻结输入：算例 → 引擎中立的选项 → 新引擎写出的 HSD，与冻结的 HSD 按 DFTB+ 的读法比较。比较规则：块内子节点不论次序，同名节点保持次序；数字相对差 ≤ 1e-12；SK 文件按文件名比较。
  • 517 个单点、34 个优化与 MD、37 个第二次运行全部相同；几何文件逐字节相同。
  • 511 个单点逐字节相同（SK 目录替换后）。
P134新引擎在每个算例上实跑 DFTB+，输出用冻结参考的同一个解析器读，逐项与冻结参考比较；再比较换成 pydftb 字段后的结果。
  • 517 个全部跑通，502 个输出逐位相同。
  • 输入差一个末位的 6 个：电荷差 ≤ 2e-13，力差 ≤ 6e-14。
  • 9 个 NTPoly：差 ≤ 2e-13，DFTB+ 同一输入连跑之间就差 5e-13。
  • 能量与冻结的 10 位小数差 ≤ 5e-11 Ha。
P134bPyDFTB 用翻译出的选项（新增的几种写法先在草稿的子类里换算），对照 refgen 的 run_pydftb（直接调 DFTB）。
  • 517 个里 501 个所有字段逐位相同。
  • 其余 16 个差 ≤ 1.1e-12（SCC 误差），能量差 ≤ 4e-14。
  • 两条路径的总时间相同（105 s 对 103 s）。
P13534 个动力学算例：ASE 的 BFGS（带晶胞时用 FrechetCellFilter）与速度 Verlet 驱动新引擎，reuse_charges=True，对照冻结的 DFTB+ 驱动结果。XL-BOMD 的 7 个只在 DFTB+ 自己的驱动里有（P133 已核对输入）。
  • 27 个里 26 个在容差内：优化 ΔE ≤ 5e-11 Ha、Δr ≤ 2.1e-6 Å；MD ΔE ≤ 5.7e-8 Ha、Δr ≤ 6.8e-8 Å。
  • 每步 SCC 轮数：MD 大多相同；onsite 修正差到 3 轮（DFTB+ 自己的驱动每个几何步的第一轮不加 onsite，从文件读电荷时加）。
  • ch3_lc_noncolinear_md：没有电荷文件，每步从初始自旋开始，一步 SCC 发散。
P136时间：每次调用 DFTB+ 的固定开销（进程启动、写读文件），以及两个引擎在全部算例上的时间。
  • H2 非 SCC：引擎 22 ms（DFTB+ 进程 15 ms），PyDFTB 3 ms。
  • 水的 MD：ASE 驱动 41 次调用 2.0 s，DFTB+ 自己的驱动 0.3 s。
  • 508 个算例，每个的中位数：DFTB+ 78 ms，pydftb 42 ms，比值中位数 3.8。
  • 最慢的是 k 点上 NeighbourBased 的杂化泛函（Threshold 1e-100）：DFTB+ 607 s，pydftb 7 s。
  • P133 的 6 个不逐字节相同的单点：
    • 两个固定费米能级：选项用 eV，写成 [Hartree] 时经过一次除法，末位变了；
    • 四个 cu8_distorted_k355：k 点权重归一化后末位变了。PyDFTB 也做同样的归一化。
    这是原则（第三节）的结果：DFTB+ 拿到的就是 pydftb 自己换算后用的数。
  • P134 找到的 DFTB+ 输出的坑：见第五节。

三、统一的选项

  • 原则：
    • 选项的名字、单位与默认值就是 PyDFTB 的：长度 Å，能量 eV，电场 V/Å，温度 K；模型参数（U、W、色散、溶剂化、CM5 等）用原子单位。
    • DFTB+ 引擎用 pydftb 自己的换算函数（ase_calc 的 _fermi_au、_hybrid_au、_truncation_au 等）把选项换成 Bohr 与 Hartree，再以 DFTB+ 的默认单位写出。两个引擎解同一个问题，输入的数逐位相同。
    • 默认值按 pydftb 的：SCC 容差 1e-6、最多 200 轮、T = 0 的 Fermi、max_l 用 ASE/PTBP 的规则。DFTB+ 自己的默认（1e-5、100 轮）不用，写出的输入总是显式的。
  • 新增的写法（两个引擎都收，旧写法不变）：
    • electric_field 可写成 {"strength": V/Å, "direction": (3,)}（DFTB+ 的写法）；
    • point_charges 可写成 {"positions": Å, "charges": e, "blur": Å}；
    • solvation 可写成溶剂化的规格字典（与验证算例的相同：{"model": "gb"|"sasa", "solvent", "free_energy_shift", ...}，param_file 是路径）。DFTB+ 引擎只收这种写法：模型对象从参数文件读出后，不再知道原来的输入。
    • solver 可写成 {"name": "ntpoly", "method", "tolerance", "truncation"}。

    • convergent_scc_only：默认 True，SCC 不收敛时 DFTB+ 停下，计算器抛出 CalculationFailed。pydftb 只给警告。
    • regions：DFTB+ 的 ProjectStates，写在这次运行里。

    • 某个引擎不支持的选项放在共同部分时报 EngineOptionError，说明原因，并指出放到哪一节。

四、DFTB+ 引擎

  • 输入：
    • 由 validation/dftbplus.py 的块拼成：就是写出全部冻结参考的那套，一份写法，经 588 个冻结输入核对过。
    • 那个模块的说明改成“DFTB+ 引擎（P2）也用这些块”；run() 的解析部分拆成 parse_run()，引擎与 refgen 共用，代码不变。
  • 运行：
    • 每次计算在工作目录里写 geo.gen 与 dftb_in.hsd（还有要读的 charges.bin），按 threads 设 OpenMP 线程后运行。
    • DFTB+ 非零退出时抛出 CalculationFailed，带 DFTB+ 的错误信息，与 ASE 的 Dftb 相同。
  • 力与应力：照 ASE 的属性请求写 PrintForces（周期体系同时给应力），与 PyDFTB 的规则相同。
  • 沿用电荷（reuse_charges=True）：
    • 上一次计算的 charges.bin 写进下一次的目录，加 ReadInitialCharges = Yes。DFTB+ 自己的驱动在几何步之间也保留 qInput，所以每步的 SCC 起点相同（P135）。
    • 杂化泛函的 charges.bin 里带着密度矩阵，同样续上。
    • DFTB+ 不给非共线杂化写电荷文件，这时从中性原子开始。
  • 第二次运行（与冻结参考的做法相同）：
    • 能带：读 SCC 的 charges.bin，MaxSCCIterations = 1、ConvergentSCCOnly = No，Klines 或显式的 k 点；不算力。
    • 二阶导数：Driver = SecondDerivatives，要极化率导数时把分析换成 Polarisability。
  • DFTB+ 自己的驱动：relax() 写 GeometryOptimisation，md() 写 VelocityVerlet（可带 Xlbomd）。一次运行走完整条轨迹，没有每步的进程开销。
  • 版本：从标准输出读 DFTB+ 的版本，记在结果里。写出的是 ParserVersion 14，要 DFTB+ ≥ 24.1。

五、两个引擎都给的结果

  • ASE 的属性：两个引擎相同。energy、free_energy（受力一致的，固定费米能级时是 F − Σ Ns Ef,s）、forces、stress、charges、dipole、magmom(s)，有原子能量分析时还有 energies。Casida 的目标态带激发态的力时，能量是 E0 + Ω。
  • calc.raw：两个引擎都是 DFTBResult（原子单位）。DFTB+ 引擎填上它能给的字段：各能量项、费米能级、本征值与占据、k 点、布居、力、应力、SCC 轮数与每轮误差、磁矩、偶极、点电荷受力、激发能。
  • calc.output（只有 DFTB+ 引擎）：解析出的全部输出，与冻结参考用同一个解析器。
  • 取值：
    • 能量从 detailed.out 读（10 位小数）。results.tag 有同一个量的全精度值、并且在打印的位数内一致时换成全精度值；总能量由 2 E0 − F 得到。
    • 布居 = 中性原子的布居（SK 文件的占据，或自定义的参考占据）− DFTB+ 的电荷。
  • DFTB+ 输出的坑（P134）：
    • 固定费米能级时，results.tag 的 mermin_energy 其实是受力一致的能量（F − N Ef），不是 Mermin 自由能（Cu4CO 差 9.16 Ha）。所以要先与 detailed.out 对照。
    • 带 ELSI 的 24.1（NTPoly）只写 total_energy，没有 mermin_energy 与 extrapolated0_energy，也没有本征值。
    • 溶剂中缩放电场时，detailed.out 与 scaled_dipole 是乘了 3ε/(2ε+1) 的偶极，results.tag 的 dipole_moments 没乘，与 pydftb 的偶极是同一个量，所以取后者。
  • common_results(calc)：两个引擎都给的结果，ASE 单位，平铺成字典。命令输出与跨引擎比较都用它。
    • 能量、力、应力、电荷、偶极、磁矩；
    • 费米能级、按 (自旋, k, 能级) 排的本征值与占据（eV）、k 点与权重、SCC 轮数；
    • 激发能（eV）与振子强度；
    • 分析给出的原子能量与 CM5 电荷。

六、pydftb run

pydftb run STRUCTURE --skdir DIR [--engine pydftb|dftbplus] [--task energy|relax|md|bands|dos|hessian]
           [--options FILE.json] [--set KEY=VALUE ...] [--kpts N N N] [--charge Q] [--json OUT.json]
           [--fmax F] [--steps N] [--cell] [--timestep FS] [--temperature K] [--native] ...
  • 结构：ASE 能读的任何格式（xyz、gen、cif、POSCAR ……）。
  • 选项：
    • 选项文件（JSON）：共同的选项在顶层，引擎自己的放在 "pydftb"、"dftbplus" 两节；
    • --set key=value：值按 JSON 读，读不成的当字符串；
    • 常用的选项有自己的参数。
  • 任务：
    • energy：单点，common_results。
    • relax：ASE 的 BFGS，--cell 时连晶胞（FrechetCellFilter），写出最终结构。
    • md：ASE 的速度 Verlet，Maxwell-Boltzmann 初速度（--seed），写出轨迹。
    • bands：SCC 后沿路径（ASE 的特殊点或 Klines）的本征值。
    • dos：态密度，可带 PDOS 区域；展宽用 pydftb.bands.broaden，两个引擎共用。
    • hessian：二阶导数（pydftb：vibrations.second_derivatives；DFTB+：SecondDerivatives 驱动），简正模式都用 vibrations.normal_modes。
  • --native（只有 DFTB+ 引擎）：优化与 MD 用 DFTB+ 自己的驱动。带 XL-BOMD 的 MD 在 DFTB+ 引擎上自动用它，并提示。
  • 输出：屏幕上的摘要，以及 --json 给的文件。内容：结果（ASE 单位）、引擎与版本、用到的选项、时间。两个引擎的 JSON 字段相同，可以直接比较。

九、风险与之后

  • DFTB+ 的版本：参考用 25.1，用户的版本可能改变输入的读法或结果。引擎记下版本；核对只在 25.1（与开发版、ELSI 版）上做。
  • 力的差：DFTB+ 差分 H0/S，pydftb 默认用解析导数，SK 网格节点附近差到 1e-6 Ha/Bohr。fd_delta=2**-13 时 pydftb 照 DFTB+ 差分。
  • SCC 不收敛：pydftb 只警告，DFTB+ 默认停下。两个引擎的行为不同，文档里写明。
  • DFTB+ 拒绝的组合：例如 k 点上的杂化泛函不给力，也不能优化晶胞。引擎把 DFTB+ 的错误原样抛出；冻结参考里已有的拒绝情形，核对时按算例的规则处理。
  • 速度：每次调用多约 20 ms 的固定开销（P136），小分子的长 MD 用 --native 更快。
  • 非共线的杂化泛函：DFTB+ 不写电荷文件，ASE 驱动的每一步都从初始自旋开始（P135 有一步发散），所以 pydftb run 在 DFTB+ 引擎上对它用 DFTB+ 自己的驱动。
  • ELSI 版的 NTPoly：同一输入的结果每次差到 5e-13，核对时按这个看。
  • 之后：PTBP 可以改用 pydftb.engines，但要保证它的结果逐字节不变，单独评估。
